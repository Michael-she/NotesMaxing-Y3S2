DATA ANALYTICS 344 · WEEK 4

Data Clustering and Cluster Analysis

Unsupervised learning: defining similarity, building clusters with K-means, K-medoids and hierarchical methods, and judging whether the result is compact, separated, interpretable and stable.

Week 4 at a glance

Core ideas

  • Clustering is unsupervised: there is no target feature; group membership is discovered, not predicted.
  • Similarity is not absolute — it is defined by the features selected, their representation/scale, and the distance measure chosen.
  • Clustering algorithms always return clusters, even for structureless data — first check cluster tendency (visual inspection, Hopkins statistic, ordered dissimilarity image).
  • Partition-based (K-means, K-medoids) gives one flat partition; hierarchical methods build a dendrogram that can be cut at any height.
  • More clusters always reduce within-cluster error — choose k by the elbow method or silhouette analysis, never by smallest error.
  • A good solution is compact, well separated, interpretable (needs domain knowledge) and stable under resampling (Jaccard coefficients).

Key definitions

  • Cluster — a group of instances more similar to each other than to instances in other clusters.
  • Centroid — the mean of the descriptive feature values of a cluster's members (may not be a real instance).
  • Medoid — the observed instance in a cluster with the smallest total distance to all other members.
  • Linkage — rule defining distance between two clusters: single (min), complete (max), average (mean of all pairs).
  • Dendrogram — tree recording the merge order and merge heights of agglomerative clustering.
  • Silhouette — s(i) = (b−a)/max(a,b); near +1 well clustered, near 0 on a boundary, negative likely misassigned.
  • Hopkins statistic — ≈0.5 suggests uniform/no structure; close to 1 suggests clustered data.
  • Jaccard coefficient — |intersection|/|union| of two matched clusters; used to measure cluster stability.

Formulas

  • Euclidean: √∑(ai−bi)²  ·  Manhattan: ∑|ai−bi|  ·  Minkowski: (∑|ai−bi|p)1/p
  • Binary (simple matching): (f01+f10)/(f01+f10+f00+f11)  ·  Categorical: (m−j)/m
  • Silhouette: s(i) = (b(i)−a(i))/max(a(i),b(i))  ·  Jaccard: |A∩B|/|A∪B|

Exam traps

  • Hopkins ≈ 0.5 means no cluster structure (data like uniform random); close to 1 means clustered. Some software uses the complementary formula — check which definition is used.
  • A falling sum of squared error is not evidence of real clusters; k = n gives zero error.
  • K-means finds k clusters even in purely uniform data; check cluster tendency first.
  • The average silhouette can hide poorly clustered points or whole weak clusters — inspect individual and per-cluster values.
  • Centroid ≠ medoid: the centroid is a mean (not necessarily an observed instance); the medoid is always an observed instance.
  • Equal distances in a distance matrix create ties — either agglomeration may occur first; say so.
  • Features on larger scales dominate distance calculations — normalise before clustering (but think before scaling coordinates).

Prescribed reading

  • Kelleher et al. (2e): Chapter 10 §10.1, 10.2, 10.3 and 10.4.1–10.4.5.
  • Additional: Kelleher et al. (2e) Chapter 5 for a deeper treatment of similarity and distance measures.

01Clustering as unsupervised learning

In supervised learning (e.g. classification) historical instances with known target values are used to learn a model that assigns the correct class label to unseen instances. In unsupervised learning there is no target feature: the structure in the data must be discovered rather than predicted.

Definition

Clustering is an unsupervised learning technique that partitions data instances into meaningful groups called clusters. A cluster contains instances that are more similar to each other than they are to instances in other clusters. Like classification, clustering assigns discrete group labels to instances — but the labels are not known in advance; they are discovered.

Clustering can be used as a stand-alone exploration tool or as a pre-processing step for other algorithms. Typical applications:

  • Customer segmentation — identify customer groups for targeted products or offers.
  • Text collection organisation — group documents into previously unknown topics.
  • Data aggregation — represent many instances by a single representative example.
  • Imputation — replace missing values using representative instances from the same cluster.
  • Outlier/fraud detection — e.g. group similar hospitals by claim behaviour, then investigate outliers within groups for possible fraud (clusters give the “normal” baseline; outliers become visible against it).
When is clustering appropriate?

Clustering suits problems where (i) no labels exist, (ii) you expect natural groupings, and (iii) the groups could drive a decision (targeting, monitoring, compression). It is not appropriate when labels are available and the goal is prediction (use classification), or when the data has no cluster structure at all — see cluster tendency in Section 4.

1.1 CRISP-DM applied to clustering

The Cross-Industry Standard Process for Data Mining applies to clustering with a few clustering-specific notes:

  • Business understanding — define what useful groups would mean for the objective.
  • Data understanding & data preparation — build the analytical base table; note it does not need a target feature. Many clustering techniques are sensitive to data quality issues, so these must be identified and fixed before clustering.
  • Modelling — choose and apply an appropriate clustering algorithm, considering the data type and quality, the size of the data set, and the kind of output the algorithm can produce (e.g. not all algorithms find clusters of any shape).
  • Evaluation — evaluate and interpret the clusters found (internal measures, stability, interpretation).
  • Deployment — deploy the clustering as a stand-alone process or as part of another process.

Families of clustering algorithms differ in how they define a cluster: centroid-based (similarity = closeness to a cluster centre, e.g. K-means), connection-based (points close in data space are more similar), density-based (dense regions separated by sparse regions) and probability-based (instances likely drawn from the same distribution).

02Similarity and distance measures

A similarity measure compares two instances and quantifies how similar or different they are. A similarity function uses large values for similar instances; a distance (dissimilarity) measure uses low values for similar instances. Clustering needs one of these to operate.

Definition

Similarity in clustering is defined by three modelling choices: (1) the features selected to describe the instances, (2) the representation of those features (encoding, scaling, units), and (3) the distance or similarity measure used to compare instances. Change any of the three and you change which instances are “similar” — and therefore which clusters you get.

The positive parameter p controls the behaviour of the metric: larger p places more emphasis on large differences between feature values. Euclidean distance (p = 2) is therefore more strongly influenced by a single large difference in one feature than Manhattan distance (p = 1).

2.2 Binary features: simple matching proportion

For instances described by m binary features, the distance can be the proportion of features that are not equal (simple matching):

\[ d_{\text{SSM}} = \frac{f_{01}+f_{10}}{f_{01}+f_{10}+f_{00}+f_{11}} \]
dSSM

where f01 = number of features where a is 0 and b is 1, f10 = features where a is 1 and b is 0, f00 = features where both are 0, and f11 = features where both are 1. (Some formulations drop f00 from the denominator when shared absences are not meaningful.)

Mini-example: a = 1 1 0 0 1 0 1 1 and b = 1 0 0 1 1 1 1 0 give f01 = 2, f10 = 2, f00 = 1, f11 = 3, so dSSM = (2+2)/(2+2+1+3) = 0.5.

2.3 Ordinal features: rank-scaled absolute difference

Ordinal features represent an order or ranking. To compute distances, assign each category a numerical value scaled to the range 0 to 1 according to its rank, then use the absolute difference between the scaled values. Example: High School = 0, Bachelor's = 1/3, Master's = 2/3, Ph.D = 1, so the distance from High School to Ph.D is 1, and from Bachelor's to Ph.D is 2/3.

2.4 Categorical (non-ordinal) features: proportion non-matching

\[ d(a,b) = \frac{m-j}{m} \]

where m is the number of features and j the number of matching features. Example: a = (Rugby, Engineering, SA), b = (Cricket, Marketing, USA), c = (Rugby, Marketing, USA): d(a,b) = 3/3, d(a,c) = 2/3, d(b,c) = 1/3.

2.5 Other measures (awareness)

  • Mixed feature types — a weighted combination of type-appropriate distances per feature; with equal weights this is Gower's distance (range-scaled differences for interval features, rank-based differences for ordinal features, 0/1 matches for categorical features).
  • Cosine similarity — compares the angle between feature vectors rather than their magnitude; useful for text documents of different lengths, where Euclidean distance can be misleading. Cosine distance = 1 − cosine similarity.
  • Correlation — treats instances as similar when their feature-value patterns are highly correlated, regardless of magnitude (common in genetics).
  • Dynamic time warping (DTW) — aligns time series that carry the same information at different times (e.g. audio clips with different speech rates).

03Feature scale and normalisation

When distance is used as the similarity measure, features with larger values or larger variance dominate the distance calculation. Consider persons described by age and height: measuring height in centimetres rather than feet changes which person is “closest” to person A, because the height feature then contributes far more to every distance. The information in the data has not changed — only the units have — yet the clustering result can change. If the variance of one feature is much smaller than another's, K-means largely ignores the small-variance feature.

Common mistake

Forgetting to normalise: with features on different scales, the resulting clusters reflect mostly the largest-scale feature. It is often recommended to scale all features to a common range before clustering. But scaling is not always right: for longitude/latitude coordinates, scaling each feature independently would destroy the geographic information that two cities are genuinely close to each other. Decide per problem whether the original units carry meaning.

04Cluster tendency: should we cluster at all?

Perhaps the biggest limitation of clustering algorithms is that they always produce k clusters — even when the underlying data has no meaningful groupings. The classic illustration: the locations of bombs dropped on London during the (1940s) Blitz were, after the war, shown to be random — yet clustering the locations produces “clusters” that are meaningless. An improvement in the error measure after clustering can therefore be misleading.

Definition

Cluster tendency assessment determines, before applying a clustering algorithm, whether the data contains a non-random structure that could form useful clusters. Three tools: visual inspection (scatter plots), the Hopkins statistic, and the ordered dissimilarity image (ODI).

4.1 The Hopkins statistic

  1. Select m instances p1, …, pm randomly from the data set D.
  2. Select m instances q1, …, qm randomly from a uniform distribution with the same variance as D.
  3. For each pi, calculate the distance ai to its nearest instance in D.
  4. For each qi, calculate the distance ri to its nearest instance in D.
  5. Compute:
\[ H = \frac{\sum_{i=1}^{m} r_i}{\sum_{i=1}^{m} a_i + \sum_{i=1}^{m} r_i} \]
H
Hopkins statistic: about 0.5 for uniform data, close to 1 for clustered data.
m
Number of points sampled.
ri
Distance from uniform random point qi to its nearest instance in the data.
ai
Distance from sampled real instance pi to its nearest instance in the data.

Interpretation: if the data is clustered, real instances sit close to neighbours (ai small) while uniform random points fall in the gaps (ri large), so H is close to 1. If the data itself is uniform, ai ≈ ri and H ≈ 0.5 — no evidence of cluster structure.

Common mistake

Reading the Hopkins value backwards: H ≈ 0.5 means the data looks like random/uniform data (do not cluster); values approaching 1 indicate cluster structure. Also note some software packages define the statistic as ∑ai/(∑ai+∑ri), which flips the interpretation — always check which definition is being used.

4.2 Ordered dissimilarity image (ODI)

  1. Compute the dissimilarity matrix between all instances (e.g. Euclidean distance).
  2. Reorder the matrix so that similar objects are placed next to each other (ordered dissimilarity matrix, e.g. by walking from a random instance to its nearest neighbour repeatedly).
  3. Display the matrix as a heat map — the ordered dissimilarity image — and inspect it visually.

If the data contains clusters, the ODI shows distinct dark low-dissimilarity blocks along the diagonal — each block is a group of mutually similar instances. A structureless data set shows no clear block pattern. The number of visible blocks suggests an initial number of clusters to investigate.

Intuition

Worked reasoning of the kind asked in the study guide (Q6): a scatter plot that is broadly scattered with no visible groups, a Hopkins statistic of 0.51, and an ODI without block structure all agree — that data set has no meaningful cluster structure, and clustering it is not appropriate. A data set with Hopkins 0.89 and three diagonal ODI blocks does contain structure, and k = 3 is a sensible first value to investigate. Assessing tendency first avoids spending effort interpreting clusters that are pure artefacts.

05Partition-based clustering: K-means

K-means is the most well-known clustering algorithm: easy to understand, computationally efficient, and generally producing good results. It divides n instances into k disjoint clusters (k is user-specified), with each instance assigned to exactly one cluster, by minimising the within-cluster sum of squared error:

\[ \text{SSE} = \sum_{j=1}^{k}\ \sum_{d_i \in C_j} \operatorname{Dist}(d_i, c_j)^2 \]
SSE
Within-cluster sum of squared errors; K-means tries to make it small.
k
Number of clusters.
Cj
Cluster j.
di
An instance belonging to that cluster.
cj
Centroid of cluster j.
Dist
The distance measure, usually Euclidean.

where c1, …, ck are the cluster centroids and Dist is a distance measure such as Euclidean distance.

5.1 The algorithm

  1. Select k initial cluster centroids c1 … ck, each defined by values for every descriptive feature (commonly drawn randomly from a uniform distribution bounded by the min/max of each feature — a centroid does not have to start at an observed instance).
  2. Calculate the distance from each instance to each centroid.
  3. Assign each instance to the cluster whose centroid is nearest.
  4. Update each centroid to the mean of the descriptive feature values of the instances assigned to its cluster.
  5. Repeat the assignment and update steps until no instance changes cluster (the centroids stabilise — the algorithm has converged).

Each iteration reduces the SSE: assigning instances to the nearest centroid and moving centroids to the mean of their members both lower the error. K-means usually converges quickly, but it converges to a local minimum (more precisely, a stationary point) — not necessarily the global optimum.

5.2 Sensitivity to initialisation and K-means++

The clusters obtained by K-means are sensitive to the initial centroid values: poor initial centres can lead to a sub-optimal local minimum. A simple mitigation is to run K-means several times from different initial centroids and keep the best result. But random initialisation has its limits: with four well-separated clusters of ten instances each, the probability that four randomly chosen initial centroids each land in a different cluster is only 4!/44 = 9.4%.

K-means++ initialisation spreads the initial centroids out, making a bad starting configuration less likely and convergence faster:

  1. Select the first centroid c1 uniformly at random from the data instances.
  2. For every instance di, let Dist(di) be its distance to the nearest centroid already chosen.
  3. Choose the next centroid from the instances with probability proportional to the selection weight
\[ w(d_i) = \frac{\operatorname{Dist}(d_i)^2}{\sum_{p=1}^{n}\operatorname{Dist}(d_p)^2} \]
w(di)
Probability that instance di is picked as the next centroid.
Dist(di)
Distance from the instance to the nearest centroid already chosen.
Denominator
Sum of the squared distances over all instances, so the weights add up to 1.
n
Number of instances.

so instances far from existing centroids are more likely to become the next centroid. Repeat until k centroids exist, then run the ordinary K-means loop.

5.3 Limitations of K-means

K-means produces “incorrect” clusters when the true clusters have (i) different sizes (points of a large-diameter cluster get claimed by a smaller one), (ii) different densities (a dense cluster gets split before a sparse one is completed), (iii) non-spherical shapes (nearest-centroid assignment cuts straight through elongated groups), or (iv) features on different scales (large-scale features dominate). And fundamentally: K-means always returns k clusters, even for uniform data — a falling SSE is not evidence of real structure.

Typical pre-processing: scale/normalise continuous features, encode categorical features appropriately, eliminate outliers. Post-processing: drop tiny clusters (probably outliers), split clusters with high SSE, merge clusters that are close together.

06K-medoids: clustering around observed instances

K-medoids addresses two weaknesses of K-means: sensitivity to outliers (the mean is easily pulled by extreme values, and squared errors amplify them) and the restriction to distances that work with means. Instead of a mean, each cluster is represented by a medoid — an actual observed instance.

Definition

The medoid of a partition is the instance in the partition with the least total distance to all other instances in the partition. Using an observed instance as the cluster representative also makes the cluster easier to interpret than an abstract mean, which may not correspond to any real instance.

6.1 Partitioning Around Medoids (PAM)

  1. Specify the number of clusters k.
  2. Arbitrarily select k instances as the initial medoids.
  3. Assign each instance to the nearest medoid (using the chosen distance, e.g. Manhattan distance).
  4. For each cluster, determine the new medoid: the instance in the cluster with the lowest total cost (sum of distances to all other members).
  5. Repeat the assignment and medoid-update steps until the medoids do not change.
Common mistake

Confusing centroid and medoid. A centroid is the feature-wise mean of a cluster's members — it can lie at a point where no instance exists and is sensitive to extremes. A medoid is always one of the observed instances and is therefore less sensitive to extreme observations: swapping in an outlier never lowers the total distance much, whereas an outlier drags a mean towards it. Trade-off: K-medoids is more expensive to compute than K-means.

07Hierarchical clustering

Instead of one flat partition, hierarchical clustering learns a hierarchy of clusters — like grouping orchestra instruments into brass, percussion, strings and woodwinds, and then subdividing (strings into bowed and plucked, etc.). This reveals richer grouping structure at the cost of more computation. There are two directions:

  • Agglomerative (bottom-up): start with every instance in its own cluster and repeatedly merge the two most similar clusters until everything is in one cluster. This is the approach used in practice.
  • Divisive (top-down): start with all instances in one cluster and recursively split until each instance is alone. More computationally expensive; e.g. the DIANA algorithm (split the cluster containing the instance with the greatest average distance to the others, then move any instance that is on average closer to the new sub-cluster).

7.1 Agglomerative clustering (AGNES)

  1. Compute the proximity (distance) matrix between all instances.
  2. Identify the two closest clusters and merge them into a new cluster.
  3. Update the proximity matrix: compute the distance between the new cluster and every other cluster using a linkage rule.
  4. Repeat until only one cluster remains.

The linkage rule defines the distance between two clusters C1 and C2:

\[ \text{Single: } d(C_1,C_2) = \min_{i\in C_1,\ j\in C_2} d(i,j) \qquad \text{Complete: } d(C_1,C_2) = \max_{i\in C_1,\ j\in C_2} d(i,j) \]
d(C1,C2)
Distance between the two clusters.
i, j
An instance from C1 and one from C2.
d(i,j)
Distance between those two instances.
min
Single linkage: the closest pair decides.
max
Complete linkage: the farthest pair decides.
\[ \text{Average: } d(C_1,C_2) = \frac{1}{|C_1|\cdot|C_2|}\sum_{i\in C_1,\ j\in C_2} d(i,j) \]
|C1|, |C2|
Number of instances in each cluster.
d(i,j)
Distance between an instance of C1 and one of C2.
∑
Sum over every cross-cluster pair, so the result is the mean pairwise distance.
  • Single linkage uses the closest pair of instances. Because the merge criterion is strictly local, chains of instances can be extended for a long distance without regard to the overall shape of the cluster — the chaining effect — producing undesirable elongated clusters. Outliers typically end up in their own cluster; if they are noise, single linkage gives poor clusters.
  • Complete linkage uses the furthest pair, tending to produce compact, roughly spherical clusters, but it can struggle with clusters of varying density or irregular shape.
  • Average linkage uses the mean over all cross-pairs, a compromise between the two.

7.2 Dendrograms

A dendrogram records the agglomeration history: every instance appears on the x-axis with a vertical line; moving from bottom to top, each horizontal line represents a merge, and the height of the merge is proportional to the dissimilarity between the merged clusters. The first horizontal line from the bottom joins the most similar instances/clusters. To obtain a flat clustering with a specific number of clusters, cut the dendrogram horizontally at any height — the number of vertical lines the cut crosses is the number of clusters.

Advantages and limitations

Hierarchical vs partition-based. Advantage: no need to fix k in advance — the dendrogram exposes every possible number of clusters, and a cut can be chosen afterwards; the hierarchy itself is informative. Limitation: computationally more expensive than K-means, and once two clusters are merged the decision can never be undone (a bad early merge contaminates everything above it). K-means is fast and simple but needs k up front, is sensitive to initialisation, and finds only one flat partition.

Single linkage — first three agglomerations.

  1. Iteration 1: the smallest entry in the matrix is d(d2, d3) = 0.334 → merge {d2, d3}.
  2. Iteration 2: update distances. With single linkage, d(d1, {d2,d3}) = min(0.600, 0.375) = 0.375. Also d(d5, d6) = 0.375. Tie at 0.375 — either agglomeration may occur first. Taking d1 first: merge {d1, d2, d3}.
  3. Iteration 3: the remaining 0.375 pair is merged: {d5, d6}. (The next smallest value would be 0.429, itself a tie: d4 joining {d1,d2,d3} since min(0.429, 0.500, 0.700) = 0.429, and d8 joining {d5,d6} since min(0.500, 0.429) = 0.429.)

Average linkage — how it differs. Iteration 1 is identical (0.334 merges {d2, d3}, since for singletons every linkage agrees). But now d(d1, {d2,d3}) = (0.600 + 0.375)/2 = 0.4875, while d(d5, d6) = 0.375 — the tie disappears and iteration 2 merges {d5, d6}. For iteration 3: {d5,d6} to d8 = (0.500 + 0.429)/2 = 0.4645, {d5,d6} to d7 = (0.444 + 0.700)/2 = 0.572, and d1 to {d2,d3} = 0.4875. The smallest is 0.4645, so iteration 3 merges {d5, d6, d8} — a different merge sequence from single linkage.

Why results differ although the matrix is unchanged: the original instance-to-instance distances are the same in both runs, but the linkage rule defines the distance between clusters differently. Single linkage looks only at the nearest pair (which is why ties and chaining appear); average linkage considers every cross-pair. Different inter-cluster distances → different merge order → different dendrogram and different cluster solutions.

Reading  Kelleher et al. (2e), Ch 10 §10.4.1–10.4.5 — hierarchical clustering: agglomerative and divisive approaches, linkage and dendrograms.

08Choosing the number of clusters

K-means and K-medoids require the user to specify k, and the true number of classes is unknown. Selecting k is difficult because high-dimensional data cannot easily be visualised.

Common mistake

Choosing the k with the smallest within-cluster error. Increasing the number of clusters always reduces the within-cluster variation — with k = n (one cluster per instance) the error is exactly zero. The smallest error is therefore meaningless on its own; methods for choosing k trade off performance (low error) against complexity (number of clusters).

8.1 The elbow method

Run the clustering for several values of k, record the sum of squared error each time, and plot error against k. A good value of k is at the first elbow — the point where the rate of decrease changes markedly (before the elbow, each extra cluster buys a lot of error reduction; after it, only marginal gains). Caveats: it is a heuristic with no guarantee of optimality, and the plot does not always show a visible elbow.

8.2 Silhouette analysis

For each instance di:

  • a(i) — the average distance between di and all other instances in its own cluster (how well it fits its cluster).
  • b(i) — the average distance between di and the instances of the nearest other cluster (the lowest average over all clusters di does not belong to).
\[ s(i) = \frac{b(i)-a(i)}{\max\big(a(i),\,b(i)\big)} \qquad \text{overall: } \bar{s} = \frac{1}{n}\sum_{i=1}^{n} s(i) \]
s(i)
Silhouette of instance i, between −1 and +1.
a(i)
Average distance to the other instances in its own cluster.
b(i)
Average distance to the instances of the nearest other cluster.
s̄
Overall silhouette: the mean over all instances.
n
Number of instances.

Interpretation: s(i) lies between −1 and +1. Near +1: b >> a — the instance is much closer to its own cluster than to the nearest rival; well matched. Near 0: a ≈ b — the instance sits on the boundary between two clusters. Negative: a > b — the instance is on average closer to another cluster than to its own and is likely misassigned. To select k, compute the overall silhouette for each candidate k and prefer the k with the highest average.

Worked example — silhouette values (study guide Q2)

Two clusterings of the oil-well data are compared: k = 2 and k = 3. For each instance, a(i) and b(i) are given; compute s(i) = (b−a)/max(a,b).

  • d2 (k=2): a = 1.608, b = 2.879 → s = (2.879 − 1.608)/max(1.608, 2.879) = 1.271/2.879 = 0.442. Positive but moderate: d2 is reasonably assigned to C1, but not strongly — it sits closer to the boundary with C2 than a well-clustered point would.
  • d3 (k=2): a = 0.624, b = 2.594 → s = (2.594 − 0.624)/2.594 = 1.970/2.594 = 0.760. Close to +1: d3 is tightly surrounded by its own cluster and far from the nearest other cluster — strongly, correctly clustered.
  • d8 (k=2): a = 1.272, b = 2.432 → s = (2.432 − 1.272)/2.432 = 1.160/2.432 = 0.477.

Low or negative values. A low positive value (e.g. d5 with s = 0.308) means the instance lies between clusters — its assignment is borderline and could plausibly go either way. A negative value means a > b: the instance is on average closer to another cluster than to its own, so it is likely misassigned and should be inspected as a possible outlier or moved.

Why the average alone is insufficient. The overall silhouette is a single number that can conceal a lot: one very weak cluster, or a handful of badly placed points, can be averaged away by many well-clustered points. Always also inspect individual values (e.g. via a silhouette plot) and per-cluster averages before trusting the mean.

Choosing between k = 2 and k = 3. Completing all 15 instances from the supplied distance matrix gives an average silhouette of about 0.52 for k = 2 and about 0.71 for k = 3 (values rounded; small differences arise from rounding in the distance matrix). The higher average supports k = 3, and the individual values confirm it: under k = 2 several C1 members have silhouettes near 0.3–0.4, while under k = 3 almost every instance exceeds 0.5.

The lectures also mention X-means as an automated alternative: start from an initial k, repeatedly split clusters and keep a split only when it improves the Bayesian Information Criterion (BIC) — an explicit trade-off between error and complexity — until no split improves the BIC.

09Internal measures: compactness and separation

Because there are no ground-truth labels, clustering quality is judged with internal measures computed from the data and the assignments alone. A good clustering is:

  • Compact — intra-cluster distances are minimised (instances close to each other are in the same cluster);
  • Well separated — inter-cluster distances are maximised;
  • some measures also consider connectivity (neighbouring points should share a cluster).

9.1 The Dunn index

  1. For each cluster, compute the distances between its objects and the objects of the other clusters; the separation is the minimum of these pairwise inter-cluster distances.
  2. For each cluster, compute the distances between objects within the same cluster; the diameter is the maximum intra-cluster distance.
  3. The Dunn index divides separation by diameter:
\[ \text{DI} = \frac{\text{min inter-cluster distance (separation)}}{\text{max intra-cluster distance (diameter)}} \]
DI
Dunn index; larger means compact, well separated clusters.
Separation
Smallest distance between any two clusters.
Diameter
Largest distance between two instances inside one cluster.

Higher is better: compact, well-separated clusters give a large DI. Example from the lectures: separation 0.56 and diameter 1.14 give DI = 0.56/1.14 = 0.49.

9.2 Comparing solutions

To compare clusterings of the same data (different algorithms, different k, different initialisations), compare their internal measures: lower SSE, higher average silhouette, higher Dunn index — but remember each measure trades off compactness, separation and complexity differently, and none of them knows whether the clusters are meaningful. A silhouette plot (silhouette width per instance, grouped by cluster) gives an overall view of how well each instance belongs to its cluster and is an easy way to spot possible outliers (instances with small scores typically lie between clusters).

Reading  Internal evaluation is lecture material; Kelleher et al. (2e), Ch 10 provides the surrounding context on clustering evaluation.

10Interpreting clusters

Internal measures say how well a clustering matches an ideal expectation, but not what each cluster represents. Interpretation uses descriptive statistics and visualisations:

  • Summary statistics per cluster and feature — count, mean, standard deviation, min, quartiles, max. Comparing these across clusters reveals the distinguishing features (e.g. “instances with small petal length are most likely assigned to cluster 1”).
  • Visualisations — e.g. a parallel coordinates plot, where each vertical axis is a feature and each line is an instance, coloured by cluster, so cluster profiles are visible at a glance (each feature may use its own scale).
  • Examining individual observations within a cluster, not just the centroid, guards against over-summarising: the centroid hides spread, skew and outliers inside the cluster.
Domain knowledge is required

Consider clustering accelerometer windows (mean X, Y, Z acceleration) with k = 2: one centroid is (−0.106, 0.438, −0.055), the other (0.279, 0.044, −0.279). The centroids clearly differ in all three axes, so the clusters capture two distinct acceleration patterns — but the clustering alone cannot say whether those patterns are “walking” and “running”. The meaning assigned to a cluster requires domain knowledge (labelled reference data, expert knowledge of the phenomenon); the algorithm only supplies the groups.

11Cluster stability

Even a compact, separated clustering might be an artefact of the particular sample. Stability analysis asks whether the discovered clusters reflect genuine structure by testing whether the results remain consistent under reasonable changes to the data.

11.1 Bootstrap stability procedure

  1. Cluster the original data set (this is the reference solution).
  2. Repeat multiple times: draw a subsample of the data with replacement and apply the same clustering algorithm to it.
  3. For each cluster in the original solution, find the most similar cluster in each resampled solution and compute the Jaccard coefficient between the two matched clusters.
  4. Compute the mean Jaccard coefficient per cluster across the resamples.
\[ \begin{gathered} \text{Jaccard}(A,B) = \frac{|A\cap B|}{|A\cup B|} \\ \text{(instances in both clusters, divided by instances in either cluster)} \end{gathered} \]
A, B
Two clusters, as sets of instances, for example from two runs.
|A ∩ B|
Number of instances in both.
|A ∪ B|
Number of instances in either.

The Jaccard coefficient ranges from 0 to 1; higher values mean the two matched clusters contain (almost) the same instances. Lecture example: 5 shared out of 6 instances in the union gives 5/6 = 0.83. As a rule of thumb used in the lectures, a cluster whose mean Jaccard coefficient is below 0.6 is considered unstable.

Worked example — stability (study guide Q7)

A 3-cluster solution was re-obtained on four resampled data sets; the Jaccard coefficients between each original cluster and its best match are:

ClusterSample 1Sample 2Sample 3Sample 4Mean
C10.910.860.880.90(0.91+0.86+0.88+0.90)/4 = 3.55/4 = 0.888
C20.620.710.580.66(0.62+0.71+0.58+0.66)/4 = 2.57/4 = 0.643
C30.790.820.760.80(0.79+0.82+0.76+0.80)/4 = 3.17/4 = 0.793
Mean Jaccard coefficient per cluster across four resamples.

Most stable: C1 (mean 0.888) — it is recovered almost identically in every resample, so it reflects a robust, genuine grouping. Least stable: C2 (mean 0.643, with one resample at 0.58, below the 0.6 threshold) — its membership changes substantially when the data is perturbed, suggesting its observations are borderline cases that do not consistently group together; C2 is the cluster to scrutinise (or merge/split) before trusting the solution.

Common mistake

Treating stability as the same information as SSE or silhouette. Within-cluster error and silhouette measure how well one clustering fits one data set; stability measures whether the clustering is reproducible when the data is perturbed. A solution can have a high silhouette yet poor stability (the tidy structure depends on a few influential points or on sampling luck), and vice versa. Report both.

12The final judgement

No single number certifies a clustering. A solution is acceptable for the intended analytics objective when it is:

  • Compact — small within-cluster variation (low SSE, high a-values);
  • Well separated — clusters are far apart relative to their size (high silhouette, high Dunn index);
  • Interpretable — the clusters can be characterised with descriptive statistics and given a plausible meaning with domain knowledge;
  • Stable enough — matched clusters across resamples show high Jaccard coefficients (rule of thumb: mean ≥ 0.6).

The week's evaluation pipeline, in order: (1) cluster tendency before clustering (Hopkins, ODI, visual inspection); (2) internal measures to choose k and compare solutions (elbow, silhouette, Dunn); (3) stability validation via resampling and Jaccard coefficients; (4) understanding the result with summary statistics and visualisations.
