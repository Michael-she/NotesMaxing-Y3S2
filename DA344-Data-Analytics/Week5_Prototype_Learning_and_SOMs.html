Week 5 — Prototype-Based Learning and Self-Organising Maps

Unsupervised neural networks that learn structure through competition and association: learning vector quantisation (LVQ1, LVQ2), self-organising maps (SOMs), and how to train, configure and interpret them.

Week 5 at a glance

Core ideas

  • Unsupervised neural networks discover structure without target labels, by association and competition.
  • LVQ1: prototype vectors compete to represent each input; the winning prototype moves towards the input, step size set by the learning rate α.
  • A conscience factor penalises prototypes that win too often, giving other prototypes a chance to win.
  • LVQ2 uses known target labels during training: winner of the correct class moves towards the input; a wrong-class winner moves away.
  • SOM: a grid of neurons projects high-dimensional data onto a 2-D map. Training = competition (find the BMU) + collaboration (update the BMU's neighbourhood) + learning (move codebook vectors towards the input), preserving topology.
  • Both the learning rate η and neighbourhood width σ decay during training (coarse ordering first, fine-tuning later).
  • A trained SOM is interpreted via its weight vectors, component planes and the U-matrix; used for clustering, visualisation, dimensionality reduction, classification, imputation and recommendation.

Key definitions

  • Prototype vector — weight vector of an output unit; represents a region/cluster of the input space.
  • Best matching unit (BMU) — neuron/prototype whose weight vector is closest (Euclidean distance) to the current input.
  • Neighbourhood function h — scales each neuron's update by its grid distance from the BMU (usually Gaussian).
  • Topology preservation — inputs close in input space are mapped to nearby neurons on the map.
  • Conscience factor — penalty added to the distance of frequently winning units during winner selection.
  • Quantisation error — average squared distance between inputs and the weight vector of their BMU; measures fit.
  • U-matrix — per-neuron average distance to neighbouring codebook vectors; high values mark cluster boundaries.

Formulas

  • Distance: d = √∑(xi − wi)²
  • LVQ1 update (winner only): wnew = wold + α(x − wold)
  • Gaussian neighbourhood: h = η(t)·exp(−d² / 2σ²(t))
  • SOM update: wkj(t+1) = wkj(t) + h·[x − wkj(t)]
  • Schedules: η(t) = η(0)e−t/τ2,  σ(t) = σ(0)e−t/τ1

Exam traps

  • LVQ1 moves only the winner (and, where applicable, units within the neighbourhood radius) — and always towards the input.
  • LVQ2 can move a prototype away from the input (wrong class); LVQ1 never does.
  • The conscience factor changes winner selection (penalty added to distance), not the weight-update rule.
  • Reducing σ shrinks how many neurons update; reducing η shrinks how much they update. Both aid convergence.
  • U-matrix: low = similar neurons (cluster interior); high = separation (boundary). Do not swap these.
  • Map too small → dissimilar observations share a neuron (structure lost); too large → overfitting, zero-frequency neurons, higher cost.

1. Learning by association and associative memory networks

The starting point of this week is a very old observation about memory, going back to Aristotle: human memory forms associations between things that are similar, contrasting, or experienced close together in space or time. Once an association has been learned, a stimulus that is merely similar to the original can trigger the associated memory or response. A familiar example: we learn to associate the written form of a musical note with its pitch, and we still recognise the association when the note is presented in a slightly different form.

Definition — associative memory neural network

An associative memory neural network is an unsupervised neural network that models the pattern-association ability of the human brain. It is usually a two-layer network (an input layer and an output layer, fully connected by a weight matrix). The weights are adjusted so that the network stores a set of pattern associations — without any external help from a teacher. When later presented with an input stimulus that is similar, but not identical, to a stored pattern, the network recalls the associated response pattern.

Structure and operation

  • Two layers: input units z1, …, zI and output units o1, …, oK. The single weight matrix uki determines the mapping from input vector z to output vector o.
  • Storing associations: the network is unsupervised — weights are adjusted so that the set of input–output pattern associations is stored in the weights themselves. Unsupervised networks store associations using weights.
  • Retrieval from partial or noisy inputs: because the association is distributed over the whole weight matrix, a degraded cue (a partial or noisy version of a stored input) still activates a pattern of output activations close to the stored response, so the network can reproduce the full associated pattern. This is pattern completion.
  • Stability of old knowledge: associative memory networks are also motivated by the brain's ability to keep old information when new information arrives. A supervised network retrained only on new data tends to forget what it had already learned; unsupervised associative networks were designed to avoid this.
Intuition

Think of the network as learning a melody. If you later hum only the first few notes (partial, possibly out-of-tune input), the memory still completes the rest of the tune. The stored association is robust because it was learned as a relationship between whole patterns, not as an exact lookup table.

Background learning rules (Engelbrecht §4.2–4.3)

Engelbrecht develops associative learning through two classic rules, which you should know as background:

  • Hebbian learning (§4.2): the oldest and simplest learning rule. Weights are adjusted based on the correlation of neuron activation values: if a neuron repeatedly contributes to firing another neuron, the weight between them is strengthened. The change in weight is proportional to the product of the output and input activations, scaled by a learning rate η. A known problem: repeated presentation of patterns makes weights grow without bound (saturation), which is countered by adding a forgetting factor.
  • Principal component learning (§4.3): Oja's rule extends Hebbian learning with a feedback/forgetting term so that the network extracts the principal components of the data — the directions of largest variance. This is the neural-network route to dimensionality reduction, and it previews why networks such as the SOM can project high-dimensional data to a lower-dimensional map.
Δuki(t) = η·ok,p·zi,p   ⇒   uki(t) = uki(t−1) + Δuki(t)

2. Learning Vector Quantisation I (LVQ1)

Definition — LVQ1 and prototype vectors

A learning vector quantiser (LVQ1) is an unsupervised, competitive neural network with two layers: an input layer and an output layer whose units each carry a prototype vector. Each prototype vector represents one region (cluster) of the input space. For a given input instance, the output neuron whose prototype vector is closest to the input (usually by Euclidean distance) is activated; the input is then represented by (quantised to) that prototype vector. Clustering emerges because prototypes compete to represent instances and gradually move to reflect the data's structure.

Structure and operation

  1. Initialise the prototype vectors — either by sampling random values within the range of each input feature, or by selecting actual training patterns as the first prototypes. Also set the learning rate η, a (possible) neighbourhood radius r, and t = 0.
  2. Compete: for the current input pattern, compute the distance from the input to every prototype vector.
  3. Winner: the prototype with the smallest distance is the winner — also called the best matching unit (BMU).
  4. Adapt: adjust the winner's prototype vector (and, where applicable, prototypes within the neighbourhood radius r) towards the input instance.
  5. Repeat over epochs, adjusting the learning rate and neighbourhood radius, until a stopping condition holds.

Through repeated updates, the prototype vectors position themselves so that the regions they represent better reflect the structure of the input data — each prototype settles near the centre of the group of observations it wins most often.

Algorithm — LVQ1 training
  1. Initialise the network weights (prototype vectors — by sampling within the input feature ranges or by selecting training patterns), the learning rate η, the neighbourhood radius r; set t = 0.
  2. While the stopping condition is not true:
    1. for each input pattern p:
      1. for each output unit k, compute the Euclidean distance dk,p(xp, uk);
      2. determine the best matching unit (smallest distance);
      3. adjust the BMU's prototype (and units within neighbourhood radius r, where applicable) towards the input;
    2. increment t;
    3. adjust the learning rate and the neighbourhood radius.
  3. Stop when (i) the maximum number of epochs is reached, (ii) weight adjustments are sufficiently small, or (iii) the quantisation error is sufficiently small.

Distance and winner selection

dk,p(zp, uk) = √ ∑i=1I (zi,p − uki)²      winner = arg min∀k dk,p

LVQ1 weight-update rule

When output unit ok wins, its prototype vector uk is moved towards the input instance. The size of the adjustment is controlled by the learning rate η(t):

uk(t) = uk(t−1) + η(t)[zp − uk(t−1)]     (equivalently  wnew = wold + α(x − wold))

The update is a fraction η of the vector that points from the old prototype to the input, so the prototype steps along the straight line joining it to the input. Prototypes that are not the winner (and lie outside any neighbourhood radius) are not changed.

Effect of the learning rate

  • η = 0: no adjustment at all — nothing is learned.
  • Large η: larger adjustments and faster initial learning, but the prototype may overshoot or oscillate, which can prevent stable convergence.
  • Very small η: training is very slow.
  • η = 1: the prototype jumps exactly onto the input point.
  • In practice: start with a relatively large learning rate and decrease it gradually during training — large steps for coarse positioning early, small steps for stable settling later.

Conscience factor — penalising frequent winners

A common problem: one output unit may win too frequently, so that many observations end up represented by the same prototype while other prototypes never win. To level the playing field, LVQ1 introduces a conscience factor that modifies the distance used to select the winning unit: prototypes that have won frequently are penalised, giving other prototypes a greater opportunity to win.

ok,p = 1 for min∀k{ dk,p(zp, uk) − bk(t) },   0 otherwise
bk(t) = γ(1I − gk(t))     gk(t) = gk(t−1) + β(ok,p − gk(t−1))
  • gk(t) tracks how often unit k has been winning (with gk(0) = 0, so initially every unit has an equal chance).
  • The more often a unit wins, the larger gk(t) becomes and the more negative bk(t) becomes — so a penalty |bk| is effectively added to that unit's distance, making it less likely to be selected again.
  • Typical values for normalised inputs: β = 0.0001 and γ = 10.

Stopping conditions and quantisation error

Training stops when (i) a maximum number of epochs is reached, (ii) weight adjustments become sufficiently small, or (iii) the quantisation error is sufficiently small:

QT = 1PT ∑p=1PT ||zp − uk||²2

where each instance is compared with the prototype vector of its own best matching unit. The quantisation error is therefore the average squared distance between instances and the prototypes that represent them — smaller is better.

Common mistakes
  • Updating all prototypes. In LVQ1 only the winner (and units within the neighbourhood radius, where applicable) moves.
  • Moving the winner away from the input. LVQ1 always moves the winner towards the input; moving away only happens in LVQ2 for a wrong-class winner.
  • Confusing the conscience factor with the update rule. The conscience factor changes which unit wins (it penalises the distance), not how weights are updated.
  • A too-large learning rate does not just “learn faster” — it can prevent convergence altogether (prototypes oscillate around the data instead of settling).
Worked example 1 — LVQ1 winner and update

Setup. Prototypes w1 = (1,2), w2 = (5,4), w3 = (7,7); input x = (4,3); learning rate α = 0.2; Euclidean distance.

Step 1 — distances to each prototype.

  • d(x, w1) = √((4−1)² + (3−2)²) = √(9 + 1) = √10 ≈ 3.162
  • d(x, w2) = √((4−5)² + (3−4)²) = √(1 + 1) = √2 ≈ 1.414
  • d(x, w3) = √((4−7)² + (3−7)²) = √(9 + 16) = √25 = 5.000

Step 2 — winner. The smallest distance is 1.414, so w2 = (5,4) wins.

Step 3 — apply the LVQ1 update rule to the winner.

  • w2new = w2 + α(x − w2) = (5,4) + 0.2·[(4,3) − (5,4)]
  • = (5,4) + 0.2·(−1,−1) = (5 − 0.2, 4 − 0.2) = (4.8, 3.8)
  • Check: the new distance to x is √(0.8² + 0.8²) ≈ 1.131, smaller than 1.414 — the prototype moved towards the input, as required.

Learning-rate effects. α scales the step: here the prototype covers 20% of the gap to x in one update. A larger α gives faster initial learning but risks overshooting and oscillation, so that training never settles; a very small α converges but extremely slowly. If α were too large (near or above 1), prototypes would jump onto or past individual points each epoch, chasing single observations instead of the centre of their region — the map would not converge to a stable representation of the data structure.

Conscience factor. If one prototype keeps winning, it keeps moving while others stagnate, and many dissimilar observations end up represented by the same prototype. The conscience factor tracks each unit's win frequency and adds a penalty to the effective distance of frequent winners, so other prototypes get a fair chance to win and the input space stays covered evenly. It affects winner selection only, not the update equation.

3. LVQ2 — using known target values during training

Learning Vector Quantiser II (LVQ2) is a supervised prototype-based method. As presented in the lectures, it uses the known target labels of the training patterns while adjusting prototypes: prototypes are adjusted not only according to their proximity to the input pattern, but also with consideration of their target class.

  • Correct classification: if the winning prototype represents the correct class of the input, it is moved towards the input pattern (as in LVQ1).
  • Incorrect classification: if the winning prototype represents an incorrect class, it is moved away from the input pattern, so that the boundary between the classes is pushed into a better position.
Exam trap — LVQ1 vs LVQ2

Both LVQ1 and SOM are unsupervised (no labels used; structure emerges from competition), while LVQ2 is supervised (labels steer the updates). In an exam question, check first whether labels are used: it determines whether a prototype may ever move away from the input. Also note the difference in representation: LVQ1 produces a set of prototypes, one per cluster region, whereas a SOM additionally arranges its neurons on a grid so that neighbouring neurons represent neighbouring regions (topology preservation).

4. Self-organising maps: definition and structure

Definition — self-organising map (SOM)

A self-organising map (SOM) uses a grid of neurons, each associated with a codebook (weight) vector, to represent regions of the input space. It projects high-dimensional data onto a lower-dimensional (usually two-dimensional) map while attempting to preserve topological relationships: observations that are similar in the input space tend to be represented by nearby neurons on the map. Training involves both competitive and collaborative learning processes. The SOM was developed by Kohonen, motivated by the topologically ordered maps found in the brain's sensory cortex.

Structure

  • Input layer: the I-dimensional input vector (features z1, …, zI); each input is connected to all map neurons.
  • Map neurons: normally arranged on a two-dimensional rectangular or square grid of K rows and J columns. The number of neurons is usually smaller than the number of training patterns.
  • Weight (codebook) vectors: each neuron carries an I-dimensional codebook vector — the same dimension as the input — which is adjusted during training. Each codebook vector forms the centroid of one small region of the input space; larger clusters are formed by grouping similar neighbouring neurons.
  • Neighbourhood structure: because the neurons sit on a grid, every neuron has well-defined grid neighbours (e.g. the surrounding 3×3 block). This grid neighbourhood — not the weight values — defines who collaborates during training.

Uses of SOMs

  • Clustering: similar observations are gathered into neighbouring map regions; clusters can then be read off the map.
  • Visualisation: high-dimensional observations become points/cells on a 2-D grid that can be displayed with colour scales (component planes, U-matrix).
  • Dimensionality reduction: the map is a multidimensional scaling of the input space — a compression onto a set of codebook vectors.
  • Pattern discovery: the organised map reveals structure (groups, gradients, boundaries) for exploratory data analysis.

5. SOM training: competition, collaboration, learning

Training a SOM consists of three main phases, repeated for each input pattern over many epochs:

  1. Compete — neurons compete to represent the data instance; the neuron with the closest codebook vector wins (the BMU).
  2. Collaborate — the neurons in the neighbourhood of the winning neuron are identified.
  3. Learn — the codebook vectors of the winning neuron and its neighbours are updated towards the input instance.
Algorithm — SOM training (stochastic)
  1. Initialise the codebook vectors wkj (random in-range, random patterns, or hypercube interpolation); set t = 0.
  2. While the stopping condition is not true:
    1. for each input pattern p:
      1. for each neuron kj, compute the Euclidean distance d(zp, wkj);
      2. determine the best matching unit mn;
      3. for each codebook vector in the neighbourhood, update with wkj(t+1) = wkj(t) + hmn,kj(t)[xp − wkj(t)];
    2. increment t;
    3. adjust the learning rate and the amount of collaboration (neighbourhood width).
  3. Stop when the quantisation error ET = ∑p ||zp − wmn(t)||²2 is sufficiently small (or a maximum number of epochs is reached).

Step 1 — Competition: finding the best matching unit

The Euclidean distance from each codebook vector to the input vector is computed, and the closest neuron wins:

||wmn − zp||²2 = min∀kj{ ||wkj − zp||²2 }

where mn denotes the row and column index of the winning neuron. This is exactly the same winner-takes-all competition as in LVQ1.

Step 2 — Collaboration: the neighbourhood function

The SOM differs from LVQ1 in that neighbours of the winner also adapt. The amount of collaboration is controlled by a neighbourhood function; a Gaussian kernel is commonly used:

hmn,kj(t) = η(t)·e − ||cmn − ckj||²2 / 2σ²(t)
  • η(t) — learning rate at time step t;
  • σ(t) — neighbourhood width at time step t;
  • cmn — map coordinates of the winning neuron;
  • ckj — map coordinates of the neuron being updated.

The exponential term depends only on the grid distance between the winner and the neuron being updated: at the BMU itself the distance is 0 and the exponential equals 1; the further away a neuron sits on the grid, the smaller its update factor. For convergence, the neighbourhood function must go to 0 as training proceeds.

Step 3 — Learning: the SOM weight-update rule

wkj(t+1) = wkj(t) + hmn,kj(t)·[xp − wkj(t)]

Every neuron in the neighbourhood moves towards the input, but by different amounts: the BMU receives the largest update, and updates decay smoothly with grid distance. Codebook vectors farther from the winning neuron receive smaller updates because the neighbourhood function decreases with map distance.

Intuition — topology preservation

Because neighbours on the grid always move together towards the same input, neurons that are close on the map end up with similar codebook vectors. After training, the map is ordered: nearby locations on the map represent similar regions of the input space, and observations similar in the input space are represented by nearby neurons. The grid thereby preserves the topological structure of the input space — which is precisely what makes the SOM useful for visualisation.

Weight initialisation

  • Random input-range initialisation: each weight gets a random value within the range of the corresponding input feature. Simple, but introduces large variance and increases training time.
  • Random-pattern initialisation: codebook vectors are set to randomly selected training patterns. Faster ordering, but may converge prematurely unless perturbed slightly.
  • Hypercube initialisation: select the four most extreme training patterns as the corners of the map and initialise the remaining codebook vectors by interpolation between the corners, so the map starts spread out over the data.

Why distant neurons receive smaller updates. The Gaussian factor decays with grid distance from the BMU, so far-away neurons move only slightly. This keeps the map smooth and ordered: a neuron updates most for inputs it already represents well, and only a little for inputs represented by distant parts of the map — which is what preserves topology.

Which neuron receives the largest update? The BMU, because its grid distance is 0, giving the largest neighbourhood value (h = 1 before the learning rate is applied).

If σ were reduced: the exponent −d²/2σ² becomes more negative for every d > 0, so all off-centre values drop faster — e.g. with σ = 1 the value at d = 1 falls from 0.882 to e−0.5 ≈ 0.607 and at d = 2 to e−2 ≈ 0.135. Fewer neurons receive substantial updates; adaptation becomes more local. This is exactly how training narrows the collaboration region over time.

6. Training schedule, map size and growing SOMs

Learning rate and neighbourhood width decay over time

Both the learning rate and the neighbourhood width are monotonically decreasing functions of time. A relatively large learning rate and a wide neighbourhood are used initially, then both are reduced:

η(t) = η(0)·e−t/τ2      σ(t) = σ(0)·e−t/τ1
  • Early training (large σ, large η): wide regions of the map move together on each presentation — this produces the coarse global ordering of the map.
  • Late training (small σ, small η): only the BMU's immediate neighbourhood adapts, and only slightly — this allows local refinement and stable convergence.
  • Very small neighbourhood-function values can be clipped (set to zero below a threshold) to avoid unnecessary updates without degrading performance.

Improving convergence and computational efficiency

SOM training is computationally expensive: for every training instance the distance to many codebook vectors must be computed to find the BMU, and the neighbourhood codebook vectors must then be updated. Three standard remedies:

  • Batch training: instead of updating after every single pattern, assign all observations to their BMUs, determine which observations contribute to each neuron and its neighbourhood, and update each codebook vector to the mean of the corresponding observations. Fewer individual weight updates are needed than in online (stochastic) training; repeat until convergence.
  • Shortcut winner search: the BMU of an observation usually changes only gradually between epochs, so instead of searching the whole map: start from the observation's BMU of the previous epoch, compare with that neuron's direct neighbours, and if a closer neuron is found continue the search from that region; stop once the winner is no longer on the boundary of the search region.
  • Reduce the neighbourhood work: clip very small Gaussian values at a threshold (neurons far from the BMU would change negligibly anyway), and let the neighbourhood width shrink dynamically as training proceeds.

Selecting the map size

  • Too small: many dissimilar observations are represented by the same neuron — high within-neuron variation and loss of structure (underfitting).
  • Too large: individual training observations may be represented by separate neurons (overfitting); many neurons end up with very low or zero frequency (never win), and computational cost increases.
  • Ideally the number of neurons relates to the number of independent training patterns; the map size is a bias-variance style trade-off that is often tuned by experiment.

Growing the SOM when structure is insufficient

Rather than fixing a large map before training, one can grow the SOM:

  1. Initialise a small, undersized SOM.
  2. Train for a fixed number of pattern presentations, then check whether a growth condition has been triggered.
  3. If growth is required, identify the neuron with the largest quantisation error (the region of the input space worst represented).
  4. Find its most distant immediate neighbours in the row and column directions, and insert a new row and column around that region (preserving the square structure).
  5. Initialise the new codebook vectors by interpolation from neighbouring neurons, then continue training.

Growing stops when (i) the maximum map size is reached, (ii) the largest neuron quantisation error falls below a user-specified threshold ε, or (iii) the map reaches the required overall quantisation error. The map therefore grows only while additional neurons are genuinely needed to represent the data.

Common mistake

Do not describe the learning rate and neighbourhood width as fixed hyperparameters chosen once. The expected answer is that both start large and decrease during training, with the reason: large early values order the map globally, small late values refine it locally and stabilise convergence.

7. Interpreting a trained SOM: weight vectors and the U-matrix

Neuron weight vectors

After training, each neuron's codebook vector is the representative (centroid) of the region of input space mapped to that neuron. Inspecting weight vectors tells you what each part of the map has learned. A component plane (component map) shows the value of one feature across all neurons of the trained map using a colour scale — e.g. the lectures' Acacia tree analysis, where a component map displays how strongly each neuron represents “straight thorn”. Comparing component planes reveals how features relate across the map.

Definition — U-matrix (unified distance matrix)

The U-matrix expresses, for each neuron, the (average) distance between that neuron's codebook vector and the codebook vectors of its neighbouring neurons. It is a geometric summary of how codebook vectors are distributed across the map: low values indicate similar neighbouring neurons; high values indicate greater separation and reveal possible cluster boundaries.

  • Construction: for every neuron, compute the distance (typically Euclidean) between its codebook vector and each neighbouring neuron's codebook vector, and average these distances; display the result as a grid of the same layout as the map.
  • Low values: the neuron and its neighbours represent similar input patterns — the interior of a cluster.
  • High values: the neuron is far from its neighbours — a ridge separating regions, i.e. a candidate cluster boundary.

  • Low values indicate that a neuron's codebook vector is close to those of its neighbours — the neurons represent similar input patterns and belong to the same region/cluster.
  • High values indicate strong separation from neighbouring neurons — a possible boundary between clusters.
  • Structure suggested: two clearly separated groups of values: columns 1–2 (0.16–0.27) and column 4 (0.18–0.23) are all low, while column 3 (0.79–0.86) is roughly three to four times higher in every row. The vertical band of high distances in column 3 suggests a boundary running down the middle of the map, separating a left region (columns 1–2) from a right region (column 4).
  • Reading off clusters: observations whose BMUs lie in columns 1–2 form one cluster; those mapping to column 4 form a second cluster; column 3 neurons sit on the boundary between them. One could confirm this by clustering the codebook vectors (e.g. hierarchical/Ward clustering) and displaying the groups on the map.
  • Why this is useful: the original data may have many dimensions, where separation is invisible by eye. The U-matrix converts those high-dimensional distances into a 2-D landscape on the map, making cluster structure directly visible.

Exploring high-dimensional data

Because training organises similar observations into nearby map regions, a trained SOM lets you investigate relationships and patterns in high-dimensional data: project each observation onto its BMU, then look for groups of neurons that capture many observations, inspect component planes to characterise each region, and use the U-matrix to locate boundaries. The lectures' Acacia example (127 attributes across habit/thorns, flowers, pods/seeds and leaves) shows how a SOM plus component maps supports classification and exploration of complex data.

8. Applications of trained SOMs

  • Classification: SOM training is unsupervised, so after training the clusters/neurons are inspected and labelled with known classes. A new observation is then presented, its BMU determined, and the BMU's label assigned as the predicted class. (Example from the study guide: neurons A–E representing aeroplane types by size, speed and passenger capacity; a fighter jet x = (2,5,1) is classified by its winning neuron.)
  • Missing-value estimation (imputation): for an observation with a missing feature, find the BMU using the available features only, then estimate the missing value from, e.g., the corresponding component of the BMU's codebook vector; the mean over the BMU and its neighbouring neurons; the mean of the selected cluster; or a neighbourhood-weighted mean. The result is an estimate, not the true value, and its quality depends on how well the map represents that region.
  • Recommendation: group users (or products) by their BMUs; users mapping to the same or nearby neurons are similar, so items liked by one group can be recommended to similar users.
  • Regression: find the BMU and estimate the target from the targets associated with nearby neurons.
  • Data compression: represent each observation by its BMU's codebook vector instead of the full feature vector.
Intuition — applying a SOM to customer analysis

Study guide Question 10: an insurer with thousands of customers described by 50 features. Each customer's 50 feature values form the input vector; a suitably sized map is chosen (balancing detail against overfitting and cost) and trained with a decaying learning rate and neighbourhood width. Similar customers then map to nearby neurons; the U-matrix or hierarchical clustering of codebook vectors reveals customer segments; component planes characterise each segment (e.g. high claim frequency, young age); and the 2-D map gives strategic managers an intuitive visual summary of the customer base — far easier to communicate than 50-dimensional feature tables.

Common mistakes
  • Claiming a SOM classifies directly after training. It does not — labels must be attached to neurons/regions after training, since training itself is unsupervised.
  • Using the missing feature to find the BMU during imputation — it is missing; use only the available features.
  • Treating an imputed value as observed data. It is an estimate whose reliability depends on the map and the region's density.
