DATA ANALYTICS 344 · WEEK 2

Data Exploration (Part 1)

Systematically examining the analytical base table before modelling: feature data types, statistical summaries, and visualisations for understanding individual features and the relationships between them.

Week 2 at a glance

Core ideas

  • Data exploration is the systematic examination of the analytical base table before modelling. It sits in the data-understanding phase of CRISP-DM (and feeds data preparation).
  • Two aims: (1) understand each feature — the values it can take, their range, and how they are distributed; (2) surface data-quality issues — missing values, invalid values and outliers, noise, different units of measure.
  • A feature’s data type (numeric, interval, ordinal, categorical, binary, textual) determines which statistics and plots are valid.
  • Use statistical summaries and visualisations together: summaries condense key characteristics; plots reveal shape, groups and outliers that identical summaries can hide.
  • Explore univariate first, then bivariate: cont × cont → scatter plot + correlation; cont × cat → comparative box plots; cat × cat → contingency table + chi-square test.
  • Exploratory evidence classifies descriptive features as potentially informative, weakly informative, redundant, complementary, irrelevant or invalid; final feature-set choices are settled by validation performance, not by single summaries.

Key definitions

  • Cardinality — the number of distinct values (levels) a feature takes.
  • Mode — the most frequent level of a categorical feature.
  • IQR — Q3 − Q1; the spread of the middle 50% of values.
  • Correlation — a standardised measure of linear association between two continuous features; ranges from −1 to +1.
  • Chi-square test of independence — hypothesis test of whether two categorical features are associated.
  • Informative / redundant / irrelevant — correlated with the target and not with other features / correlated with the target but also with other features / no correlation with the target.
  • Target leakage — a feature that is only available because the target event has already happened; invalid for prediction.

Formulas

  • cov(a,b) = 1n−1 ∑(ai − ā)(bi − b̄);   corr(a,b) = cov(a,b)σaσb ∈ [−1, +1].
  • Expected frequency: E = (row total × column total) ÷ grand total.
  • χ² = ∑ (O − E)² ÷ E, summed over all cells;   df = (r − 1)(c − 1).

Exam traps

  • Correlation measures linear association only — a clear non-linear pattern can give r ≈ 0.
  • Correlation ≠ causation; hidden groups or one extreme observation can create or destroy r.
  • A box plot cannot show multiple modes — use a histogram (or violin plot).
  • Mean and standard deviation are sensitive to outliers and skew; compare with median and IQR.
  • Chi-square works on counts, not percentages; expected frequencies come from the row/column totals.
  • Do not drop a feature on one weak summary alone — check for non-linear or subgroup effects, then compare feature sets on validation performance.
  • A feature available only after the target event is invalid (leakage) however strongly it is associated.

Prescribed reading

01The purpose of data exploration and its place in CRISP-DM

Definition

Data exploration is the systematic examination of the data in an analytical base table using statistical summaries and visualisations, in order to understand the characteristics of each feature and the relationships between features before predictive modelling begins.

CRISP-DM proceeds through six phases: business understanding, data understanding, data preparation, modelling, evaluation and deployment. Data exploration forms part of the data-understanding phase (and directly informs data preparation). Models depend on data: a modelling algorithm can only exploit structure that is actually present in, and compatible with, the data it is given, so exploration is not an optional extra — it is how we learn what the data can support.

Through data exploration we aim to:

  1. Fully understand the characteristics of each feature in the analytical base table:
    • the types of values a feature can take,
    • the ranges into which the values fall,
    • how the values are distributed across that range;
  2. Determine whether the data suffer from quality issues, such as instances with:
    • missing values,
    • invalid values and outliers,
    • noise,
    • different units of measure.

Exploration also guides the analytical treatment applied later:

  • Feature engineering — using domain knowledge to extract features from raw data to improve modelling results;
  • Data-quality plan — developing strategies to handle the quality issues found;
  • Data transformation — choosing transformations that make features more compatible with specific analytical models.
Definition

Univariate exploration analyses one feature at a time (distribution, shape). Multivariate exploration studies two or more features simultaneously, and is critical for understanding relationships between features — in particular whether a feature is useful for predicting the target feature. (Bivariate exploration, the two-feature case, is the focus of this week.)

Data exploration itself is broadly classified into descriptive statistics (condensing key characteristics of a data set into simple numeric metrics such as the mean, standard deviation and correlation) and data visualisation (projecting data, or parts of it, into multi-dimensional space or abstract images such as histograms, box plots and scatter plots). Both are used together — Section 3 explains why.

Reading  Kelleher et al. (2e), Ch 2 §2.4–2.5 — data exploration and visualisation. Ch 3 §3.1–3.3 — data-quality issues and the data-quality report. Corrective actions for data-quality problems (Ch 3 §3.4 onward) are Week 3 material and are only flagged here as a forward pointer.

02Feature data types

The features in an analytical base table can be several different types. At the highest level they are grouped into continuous and categorical types, with six sub-types in total. The data type matters because it constrains which statistical summaries and visualisations can validly be applied.

High-level groupData typePropertiesExamples
ContinuousNumericTrue numeric values that allow arithmetic operations (addition, subtraction, multiplication, division).price, age, vibration level
IntervalValues that allow ordering and subtraction, but not other arithmetic operations (no meaningful ratios).date, time
CategoricalOrdinalA finite set of values that allow ordering but do not permit arithmetic.size: small / medium / large
Categorical (nominal)A finite set of values that cannot be ordered and do not permit arithmetic.country, product code
BinaryA set of just two values — a special case of categorical.fraud vs not-fraud; failed vs not failed
TextualFree-form, usually short, text data; must usually be transformed (feature engineering) before statistical treatment.name, address

How the type constrains valid summaries and visualisations:

  • Numeric features support the full set: mean, standard deviation, quartiles, histograms, box plots, scatter plots, correlation.
  • Interval features support ordering and differences (e.g., time between two dates) but not ratio statements (“twice as much”) or, in general, meaningful means of the raw values.
  • Ordinal features support ordering-based summaries (median, percentiles, mode, bar plots) but not arithmetic summaries such as the mean — the “distance” between small and medium is not defined.
  • Categorical / binary features support only counting-based summaries: frequencies, percentages, mode, bar plots, contingency tables. A binary feature is additionally summarised by the proportion of one of its two levels.
  • Textual features are not summarised statistically in their raw form; they must first be engineered into numeric or categorical features.
Common mistake

Computing a mean or standard deviation of an ordinal or nominal feature (e.g., averaging “small/medium/large” after coding it 1/2/3), or drawing a histogram of a categorical feature. The arithmetic is meaningless for those types — use the mode, frequencies and a bar plot instead. Always state the data type first, then choose the summary and plot that the type permits.

Reading  Kelleher et al. (2e), Ch 2 §2.4–2.5 — data types and data exploration.

03Why statistical summaries and visualisations must be used together

Descriptive statistics and visualisation are complementary, and neither is sufficient on its own:

  • Summaries condense but hide structure. A small number of numeric values cannot consistently convey the wealth of information in a data set: two data sets can be nearly identical on several statistical properties (means, standard deviations, correlation) yet look noticeably different once plotted.
  • Plots reveal what numbers hide — distribution shape, multiple peaks, gaps, clusters, outliers and non-linear patterns — but a plot alone gives no precise, comparable quantities.
  • Human vision is trained to find patterns and anomalies, even in large volumes of data, but the effectiveness of that pattern detection depends on how effectively the information is visually presented. Selecting suitable visuals is therefore critical; a graphic should display as much information as possible with the lowest possible cognitive strain. Visualisation is an iterative process whose purpose is to answer questions about the data.
Intuition

Think of the summary statistics as a passport photo of the data: compact and comparable, but flattened. The plot is meeting the data in person. You need both — the photo to compare many data sets quickly, the meeting to notice anything the photo could not show.

Common mistake

Exploring a feature with only its mean and standard deviation, then concluding two features (or two groups) behave the same. Identical summaries do not imply identical data — always look at the plot before drawing conclusions.

Interpreting centre and skew: if the mean and median are close, the distribution is roughly symmetric; if the mean is noticeably larger than the median the distribution is skewed to the right (a few very high values pull the mean up), and if the mean is noticeably smaller it is skewed to the left. Common mistake

Reporting the mean and standard deviation alone for a skewed distribution or one with outliers. A single extreme value can move the mean and inflate the standard deviation substantially; the median and IQR will not. Report both views and comment on the difference.

05Univariate exploration: categorical and binary features

Categorical features (including binary ones) cannot be summarised by means or quartiles. Their valid summaries are counting-based:

StatisticMeaning
CountNumber of (non-missing) observations.
CardinalityNumber of distinct values (levels) the feature takes. Low cardinality: a handful of levels; high cardinality: dozens or more (e.g., identifiers).
ModeThe most frequent level.
Level frequenciesThe count of observations in each level.
Level percentagesEach level’s frequency as a percentage of the total; sums to 100%.

For a binary feature the whole distribution reduces to one number: the percentage (or proportion) of observations in either level — e.g., the failure rate. Cardinality also matters for visualisation: a categorical feature with very high cardinality produces a bar plot with too many bars to read, and may indicate a feature that is really an identifier rather than a useful predictor.

Intuition

Level percentages let you compare categories against a baseline. If the overall failure rate is 13.3%, then a machine type whose failure percentage is close to 13.3% behaves like the fleet average, while one far above or below it stands out. Exploration is about spotting those deviations — and then testing whether they are larger than chance would produce (Section 10).

06Univariate visualisations: histograms, box plots and bar plots

6.1 Histograms (continuous features)

To construct a histogram, the data are binned into equal-size regions (bins); the number of observations in each bin is counted, and a bar is drawn whose height is the frequency or percentage of observations in that bin. Histograms reveal the shape of the distribution. The standard shapes to look out for are:

  • Uniform — values roughly equally likely in any range (e.g., IDs);
  • Normal (unimodal, symmetric) — strong tendency toward a central value with symmetric variation either side (e.g., heights of randomly selected females);
  • Unimodal skewed right — tendency toward very high values (e.g., salaries);
  • Unimodal skewed left — tendency toward very low values (e.g., life expectancy);
  • Exponential — very high probability of low values that diminishes rapidly for higher values (e.g., number of times a person has been married);
  • Multimodal — two or more commonly occurring ranges of values separated from each other (e.g., height of randomly selected students), suggesting several distinct mechanisms or subgroups in the data.

6.2 Box plots (continuous features)

The box plot (developed by John Tukey) is a compact way to assess a distribution from its five-number summary: minimum, lower quartile, median, upper quartile and maximum. The box spans the middle 50% of the data (Q1 to Q3); the whiskers extend from the box and indicate the region of the lower and upper 25% of the data; individual points beyond the whiskers are plotted as outliers. A symmetric distribution has roughly equal spacing across the quartiles, so the box and whiskers appear symmetric; skew shows up as a lopsided box and unequal whiskers.

While compact, a box plot cannot identify distributions with multiple peaks (modes). To detect multimodality, use a histogram or a violin plot — a compact density-based visualisation that retains histogram-like characteristics (a density curve and its mirror image), optionally with the quartiles and median added.

6.3 Bar plots (categorical and binary features)

A bar plot draws one bar per level of a categorical feature, with bar height equal to the level’s frequency or percentage. It is the categorical analogue of the histogram. For binary features a single bar (or two bars) showing the level percentages is enough.

6.4 Choosing the univariate visualisation

  • Continuous feature → histogram or box plot. Use a histogram (or violin plot) when the shape — especially multiple modes — matters; use a box plot for a compact summary and outlier detection, or to place several distributions side by side.
  • Categorical feature, low cardinality → bar plot of frequencies or percentages.
  • Categorical feature, high cardinality → a bar plot becomes unreadable; consider grouping levels, showing only the most frequent levels, or reconsidering whether the feature is really an identifier.
  • Ordinal feature → bar plot with the levels ordered meaningfully.

Additional dimensions can be added to almost any plot using facets, colours and shapes: faceting creates the same plot type split into panels by another feature. Such augmentations are simple but powerful for identifying patterns and engineering new features (e.g., splitting a ridership histogram into weekday and weekend panels revealed two distinct regimes).

Common mistake

Using a box plot to argue that a distribution is “normal” or unimodal — the box plot cannot show the number of peaks. Conversely, using a histogram to read exact quartiles is unreliable. Match the plot to the question.

07Bivariate exploration: choosing the right tool

The goal of a predictive model is to explain variation in the target feature, so bivariate exploration asks: is this descriptive feature associated with the target (or with other descriptive features)? The correct visualisation and statistical method are determined by the data types of the two features involved.

08Two continuous features: scatter plots, covariance and correlation

8.1 Scatter plots

A scatter plot places one feature on the x-axis and another on the y-axis; each instance is represented by a point determined by its values of the two features. Reading a scatter plot means describing the relationship along three dimensions:

  • Direction — positive (both features increase together) or negative (one increases as the other decreases);
  • Strength — how tightly the points cluster around a common trend (weak / moderate / strong);
  • Form — the shape of the trend (linear, curved, or none).

8.2 Covariance

For two features a and b over n instances, the sample covariance is

\[ \operatorname{cov}(a,b) = \frac{1}{n-1}\sum_{i=1}^{n}(a_i-\bar{a})(b_i-\bar{b}) \]
cov(a, b)
Sample covariance of features a and b.
ai, bi
Values of the two features for instance i.
ā, b̄
Means of the two features.
n

where ā and b̄ are the sample means. Covariance lies in [−∞, +∞]: negative values indicate a negative linear relationship, positive values a positive linear relationship, and values near zero little or no linear relationship. However, covariance is measured in the units of the two features, so comparing covariances across differently scaled feature pairs is not meaningful — which motivates correlation.

8.3 Correlation

Correlation is the normalised version of covariance, obtained by dividing by the two standard deviations, so it always lies between −1 and +1:

\[ \operatorname{corr}(a,b) = \frac{\operatorname{cov}(a,b)}{\sigma_a \times \sigma_b} \]

  • values close to +1: very strong positive linear correlation;
  • values close to −1: very strong negative linear correlation;
  • values close to 0: no linear correlation.

When several continuous features are explored together, the pairwise correlations form a correlation matrix, often displayed in the upper triangle of a scatter plot matrix (SPLOM) — a grid of scatter plots for every pair of features. A SPLOM is useful for exploring relationships among all continuous features at once, but its effectiveness diminishes once the number of features exceeds about eight, because the individual panels become too small to interpret. For larger feature sets, the correlation matrix can also be visualised as a heatmap.

8.4 Caveats: what correlation can and cannot tell you

  • Correlation measures linear association only. A clear curved (non-linear) relationship can produce a correlation near zero — the pattern is invisible to r. Always inspect the scatter plot.
  • Different shapes, same correlation. Data sets with very different scatter-plot shapes can share the same correlation value (and even the same means, standard deviations and correlation), so r alone never fully describes a relationship.
  • Hidden groups. Separate subpopulations within the data can create, strengthen, weaken or mask a correlation. Faceting or colouring points by a grouping feature can reveal this.
  • One extreme observation can create the appearance of a relationship where none exists in the bulk of the data, or destroy the appearance of one that does.
  • Correlation does not imply causation. Two features can be correlated because both are driven by a third factor. The classic illustration: ice-cream sales and shark attacks both rise in hot, sunny weather — they are correlated, but neither causes the other; the common cause is good weather bringing people to the beach.
Worked example — interpreting a strong positive correlation

Setting. Exploring ten weekly machine assessments, the scatter plot of average vibration against maximum temperature shows points tightly clustered around an upward-sloping straight line, and the computed correlation is strongly positive (close to +1).

What can be concluded:

  • There is a strong, positive, linear association between the two features within the observed range: weeks with higher average vibration tend to also have higher maximum temperature.
  • The two features vary together at a consistent rate — knowing one gives information about the other (relevant for redundancy screening, Section 11).

What cannot be concluded:

  • No causation. The correlation does not show that vibration causes temperature to rise, that temperature causes vibration, or anything about the mechanism — both could be driven by a third factor (e.g., machine load or wear).
  • No claim about form beyond linearity. r summarises only the linear component; the relationship could bend or saturate outside the observed range, and r would not show it.
  • No claim of universality across subgroups. The trend might differ between machine types or operating conditions (hidden groups); a single pooled r can mask that.
  • No claim of robustness. One extreme observation could be responsible for much of the apparent association — check the scatter plot with and without suspect points.
Common mistake

Describing a correlation of 0.05 as “no relationship”. The correct statement is “no linear relationship” — a strong non-linear relationship may still be present. Likewise, reading a high correlation as evidence that one feature causes the other is an automatic error.

09Continuous vs categorical: comparative box plots

To explore the relationship between a continuous feature and a categorical feature (for example, average vibration vs failure outcome, or vibration level vs machine type), split the continuous feature by the levels of the categorical feature and draw side-by-side (comparative) box plots, one per level. This works especially well when the continuous features are on the same order of magnitude.

Interpretation compares three things across the groups:

  • Centre — do the medians differ between groups?
  • Spread — do the groups differ in variability (box height, whisker length, number of outliers)?
  • Overlap — how much do the distributions overlap? Little overlap means the continuous feature separates the groups well.

If the distributions differ clearly in centre or spread with limited overlap, the continuous feature is potentially informative for predicting the categorical feature. If the box plots are nearly identical across groups, the feature shows no evidence of being useful. The same logic applies when comparing several continuous descriptive features side by side, or when comparing a continuous feature against a binary target (e.g., failed vs not failed).

Intuition

In the study-guide machine data, machines that failed generally had higher average vibration than machines that did not. The comparative box plots would show the “failed” box shifted upward relative to the “not failed” box; the less the two boxes overlap, the more vibration looks like a useful predictor of failure.

10Two categorical features: contingency tables, bar plots and the chi-square test

10.1 Contingency tables and bar plots

The relationship between two categorical features is summarised in a contingency table: rows are the levels of one feature, columns the levels of the other, and each cell holds the count of instances with that combination, with row and column totals added. Visually:

  • Grouped bar plots show the counts (or frequencies) of one feature within each level of the other;
  • Proportional bar plots show percentages instead of counts, which makes it easier to see whether the distribution of one feature deviates from the overall baseline proportion within each level of the other. Proportions reveal relative differences, but they carry no measure of uncertainty — an apparent deviation might be due to random chance, which is exactly what the chi-square test addresses.

10.2 The chi-square test of independence

The chi-square (χ²) test of independence assesses whether there is evidence of an association between two categorical features. Its logic: assume the two features are independent, compute what the cell counts should look like under that assumption, and measure how far the observed counts deviate from those expectations.

  1. Null hypothesis H₀: the two categorical features are independent (no association). Any deviation between observed and expected counts is due to random chance.
  2. Expected frequencies. Under independence, the expected count of each cell is
    \[ E = \frac{\text{row total} \times \text{column total}}{\text{grand total } (n)} \]

    column total

    Total number of instances in the table.

    \[ \chi^2 = \sum \frac{(O-E)^2}{E} \]

  5. Decision. Compare the statistic to the critical value of the χ² distribution at the chosen significance level (or convert it to a p-value). If χ² exceeds the critical value (equivalently, p-value < α), reject H₀: there is evidence of an association. Otherwise, do not reject H₀.
  6. Interpretation. The test says whether an association exists, not what causes it. Describe the pattern of the association using the conditional percentages from the table.
Worked example — chi-square test of independence

Setting. Three machine types (A, B, C), 200 machines of each type, are observed for failure in the next seven days:

Machine typeNo failureFailureTotalFailure %
Type A1802020020/200 = 10.0%
Type B1505020050/200 = 25.0%
Type C1901020010/200 = 5.0%
Total5208060080/600 = 13.3%

Step 1 — conditional failure percentages. A: 10.0%, B: 25.0%, C: 5.0%, against an overall failure rate of 13.3%. Type B fails far more often than average; Type C far less. The question is whether these differences are larger than chance could plausibly produce.

Step 2 — hypotheses. H₀: machine type and failure outcome are independent (every type has the same failure rate). H₁: there is an association between machine type and failure outcome.

Step 3 — expected frequencies under independence. Each cell: E = (row total × column total) ÷ 600. All row totals are 200, so every type has the same expected counts:

  • E(Failure) = 200 × 80 ÷ 600 = 26.67
  • E(No failure) = 200 × 520 ÷ 600 = 173.33

Step 4 — chi-square statistic. χ² = ∑ (O − E)² ÷ E, over all six cells:

CellOE(O − E)² ÷ E
A — Failure2026.67(20 − 26.67)² ÷ 26.67 = 44.49 ÷ 26.67 ≈ 1.67
A — No failure180173.33(180 − 173.33)² ÷ 173.33 = 44.49 ÷ 173.33 ≈ 0.26
B — Failure5026.67(50 − 26.67)² ÷ 26.67 = 544.69 ÷ 26.67 ≈ 20.42
B — No failure150173.33(150 − 173.33)² ÷ 173.33 = 544.69 ÷ 173.33 ≈ 3.14
C — Failure1026.67(10 − 26.67)² ÷ 26.67 = 277.89 ÷ 26.67 ≈ 10.42
C — No failure190173.33(190 − 173.33)² ÷ 173.33 = 277.89 ÷ 173.33 ≈ 1.60

χ² = 1.67 + 0.26 + 20.42 + 3.14 + 10.42 + 1.60 = 37.50.

Step 5 — degrees of freedom. df = (3 − 1)(2 − 1) = 2.

Step 6 — decision. At the 5% significance level with df = 2 the critical value is 5.99. Since 37.50 > 5.99 (equivalently, the p-value is far below 0.05), we reject H₀: there is strong evidence of an association between machine type and failure outcome.

Step 7 — interpretation. The association is driven by Type B failing much more often than the fleet average (25% vs 13.3%) and Type C much less often (5%).

Caution. Association is not causation: the test does not show that machine type causes failure. A third factor — such as machine age, duty cycle, or maintenance history, which may differ between types — could explain the observed relationship.

Common mistake

Running the chi-square test on percentages instead of counts, or computing expected frequencies from anything other than the row and column totals of the observed table. Also remember the test only answers “is there evidence of some association?” — it does not measure the strength or direction of the association, and rejecting H₀ never establishes causation.

11From exploration evidence to feature classification

The practical payoff of exploration is a first verdict on each descriptive feature: is it worth offering to the model? Not all collected features are relevant. The core classification (with respect to the target feature) is:

Definition
  • Informative feature — correlated with the output target, but not correlated with other descriptive features.
  • Redundant feature — correlated with the output target, but also correlated with other descriptive features (it duplicates information another feature already provides).
  • Irrelevant feature — has no correlation with the output target.

Week 2 refines this into the working vocabulary used for exploratory evidence:

  • Potentially informative — shows a clear relationship with the target (different distributions across target levels, or a strong association); a serious candidate for the model.
  • Weakly informative — only a weak overall relationship with the target (e.g., a weak linear correlation), but possibly still useful: the relationship may be non-linear, threshold-like, or visible only in subgroups. Do not discard on a single weak summary alone.
  • Redundant — strongly associated with the target but nearly a duplicate of another feature (very high pairwise correlation, almost identical relationship with the target); one of the pair can usually be removed.
  • Complementary — carries information not already provided by the other features, for example a relationship that differs between subgroups (an interaction); most valuable in combination with other features.
  • Irrelevant — no relationship with the target (e.g., identifiers with a different value per instance, or attributes whose level distributions are identical across target classes).
  • Invalid — unusable for prediction, most notably through target leakage: the feature is only recorded because the target event has already occurred, so it would not be available when a prediction must be made.

Why this matters for modelling. Feature selection — choosing a subset of the most informative features — is worthwhile because (1) some models, notably support vector machines and neural networks, are sensitive to irrelevant features; (2) models such as linear and logistic regression are vulnerable to correlated (redundant) predictors; and (3) even when a model is insensitive to extra predictors, fewer features give simpler models, shorter training times and less potential to overfit. Common selection strategies include filter methods (statistical tests between descriptive and target features, and between descriptive features, to flag relevant and redundant features), wrapper methods (add or remove features, build the model, compare performance) and embedded methods (the algorithm performs selection as part of training). These are developed further later in the module; this week only the exploratory evidence behind the classifications is required.

Follow-up conclusions: (1) average vibration and vibration RMS contain substantially overlapping information; (2) days since maintenance must not be removed on the weak linear correlation alone because its effect is non-linear (threshold-like); (3) maximum temperature is the feature suggesting an interaction / subgroup-specific relationship; (4) maintenance work order is the feature that would create target leakage; (5) no feature should be removed on a single summary statistic alone — summaries can miss non-linear and subgroup effects.

Common mistake

Two classic errors: (1) keeping a leakage feature because its association with the target is strong — strength of association is irrelevant if the feature would not be available at prediction time; (2) discarding a feature because one correlation is weak — check plots for non-linear, threshold or subgroup patterns before deciding.

12Comparing alternative feature sets using validation performance

Exploratory summaries and plots generate hypotheses about which features might be useful, but they are not the final arbiter. Individual summaries can mislead — a weak correlation can hide a threshold effect, a strong one can be driven by an outlier, and two features that look similar marginally can behave very differently inside a model. Alternative feature sets should therefore be compared by building models with each candidate set and comparing their performance on validation data (data not used to build the models):

  • use exploration to propose candidate feature sets (drop clear irrelevancies and leakage, keep weakly informative and complementary features that plots support);
  • train the same modelling approach on each candidate set;
  • evaluate and compare the sets on validation performance;
  • prefer the set that generalises best, balancing performance against simplicity.

This is the wrapper idea in miniature: add or remove features, build the model, evaluate, and let validation performance — not any single summary or plot — settle the choice. Features should therefore never be selected solely from their individual statistical summaries or visualisations.

Intuition

Exploration is the scout that maps the terrain; validation performance is the referee that decides the match. A scout’s report (“this feature looks weak”) is worth acting on only as a proposal — the referee’s verdict (the model actually performs worse/better without it) is what counts.
