Decision Trees and Information-Based Learning

How a decision tree predicts, how entropy, information gain, gain ratio and the Gini index choose its tests, how ID3 grows it, and how continuous features, regression targets, pruning and rule extraction fit in. After this page you should be able to build the first split of a tree by hand and explain every choice.

01Decision trees

A decision tree is a supervised model that predicts by asking a sequence of questions about the descriptive features. Each non-terminal (decision) node tests one feature. Each branch is one outcome of the test. Each terminal (leaf) node holds a prediction of the target feature. To predict for a query, start at the root and follow the branch that matches the query at each test until a leaf is reached.

Definition

Information-based learning builds a model by choosing, at every step, the descriptive feature that tells you most about the target. "Most information" is measured with entropy (or the Gini index): a test is good if the child nodes it creates are purer than the parent.

Figure 1.1: Rectangles are decision nodes and rounded boxes are leaves. A query with Income = 35 000 and History = poor follows root → yes → no and is rejected. The tree has three leaves, so it encodes three rules (Section 6).

Two properties make a tree good:

  • Effectiveness depends on the quality of the tests: good tests separate the classes well, so leaves are accurate.
  • Efficiency depends on the order of the tests: informative tests near the root let most queries reach a leaf after few questions.

A prediction visits exactly one node per level. In a balanced tree with \(L\) leaves the path length is about \(\log_2 L\), so shallow trees predict quickly. Shallow trees are also simpler, easier to interpret and less likely to overfit. The algorithms below are greedy recipes for growing shallow, accurate trees.

Intuition

Think of the game "Guess who?" (Kelleher Fig 4.3). Asking "Is it a man?" splits the remaining people roughly in half, whatever the answer. Asking "Is it Brian?" usually rules out only one person. Good tests are the ones whose answers you cannot predict in advance: they carry the most information.

Worked example 1.1 Tracing a prediction

A tree predicts whether a pump needs maintenance. Root: Vibration ≥ 7 mm/s? yes → Service. No → Hours since service ≥ 2 000? no → OK; yes → Temperature ≥ 80 °C? yes → Service, no → OK. Predict for Vibration = 4 mm/s, Hours = 2 600, Temperature = 72 °C.

1
Root: 4 ≥ 7 is false, take the "no" branch.
2
Hours: 2 600 ≥ 2 000 is true, take "yes".
3
Temperature: 72 ≥ 80 is false, take "no", reaching the leaf OK.
Prediction: OK. Path: Vibration < 7 → Hours ≥ 2 000 → Temperature < 80 → OK (three tests).

Evaluating a classifier

The slides use a credit-approval tree (Yengejeh, 2023) to recall the confusion-matrix measures from earlier in the module. With TP, TN, FP and FN the counts of true positives, true negatives, false positives and false negatives:

Classification performance\[ \text{Accuracy} = \frac{TP+TN}{TP+TN+FP+FN}, \quad \text{Precision} = \frac{TP}{TP+FP}, \quad \text{Recall} = \frac{TP}{TP+FN}, \quad F_1 = \frac{2}{\frac{1}{\text{precision}} + \frac{1}{\text{recall}}} \]
\(TP\)
Positives predicted as positive (count).
\(TN\)
Negatives predicted as negative (count).
\(FP\)
Negatives wrongly predicted as positive (count).
\(FN\)
Positives wrongly predicted as negative (count).
\(F_1\)
Harmonic mean of precision and recall, between 0 and 1.

Recall is also called sensitivity. These measures return in Week 12, where you compute them for ensembles.

In practice trees are trained with libraries, for example rpart and rpart.plot in R or sklearn.tree.DecisionTreeClassifier in Python. These hide the calculations below, which is exactly what the exam asks you to do by hand.

02Measuring impurity

A test is chosen by how much it increases the purity of the child nodes with respect to the target feature. A node is pure when all its instances have the same target level.

The simplest measure is majority-class purity: the fraction of the node in its most common class. In the slides, splitting ten patients on FamilyHistory gives a False child with 5 of 7 Benign (purity 5/7) and a True child with 3 of 3 Malignant (purity 3/3). Majority purity looks at one level only, so it cannot tell a node split 5/2 from one split 5/1/1. Entropy fixes this by using every level.

Entropy

Shannon entropy measures the uncertainty in a node, in bits: the average number of yes/no questions needed to identify the target level of a randomly chosen instance. A pure node needs no questions, so its entropy is 0 bits. A node split evenly between two levels needs one question: 1 bit. The more diverse the node, the more bits.

Entropy (Kelleher Eq 4.2)\[ H(t, \mathcal{D}) = -\sum_{l \in \text{levels}(t)} P(t = l)\,\log_2 P(t = l) \]
\(H(t,\mathcal{D})\)
Entropy of target feature \(t\) in dataset (node) \(\mathcal{D}\), in bits.
\(l\)
One level (class value) of the target.
\(P(t=l)\)
Fraction of instances in \(\mathcal{D}\) whose target is \(l\).
\(\log_2\)
Base-2 logarithm; it makes the unit bits. Take \(0 \log_2 0 = 0\).

Recipe: for each target level, multiply its probability by the log of that probability; sum the products and negate. The negation makes the result non-negative, because logs of probabilities are negative. For \(k\) equally likely levels \(H = \log_2 k\), the maximum: 1 bit for two classes, 1.585 bits for three.

Figure 2.1: It starts at P(+) = 0.25, the node of worked example 2.1 (3 of 12). Slide to change the class mix. Both measures are zero for a pure node (P = 0 or 1) and largest at an even split (P = 0.5), where entropy is 1 bit and Gini 0.5. Entropy is steeper near the pure ends, which is the "better contrast" the slides mention. The dashed line is twice the Gini index: scaled, the two curves are very close, which is why they usually pick the same split.

Worked example 2.1 Entropy and Gini of a node

A node holds 12 loan applications: 3 Approve and 9 Reject. Find its entropy and Gini index.

1
Probabilities: \(P(\text{Approve}) = 3/12 = 0.25\), \(P(\text{Reject}) = 9/12 = 0.75\).
2
Entropy: \(H = -(0.25\log_2 0.25 + 0.75\log_2 0.75) = -(0.25(-2) + 0.75(-0.4150)) = 0.5 + 0.3113 = 0.8113\) bits.
3
Gini: \(1 - (0.25^2 + 0.75^2) = 1 - (0.0625 + 0.5625) = 0.375\).
\(H = 0.811\) bits and Gini \(= 0.375\). The node is fairly impure, though not as impure as an even split (1 bit, 0.5).
Watch out

Use base-2 logs. On a calculator, \(\log_2 x = \ln x / \ln 2\). A common slip is forgetting the leading minus sign, which gives a negative entropy: entropy is never negative.

Information gain

To score a test on descriptive feature \(d\), partition the node by the levels of \(d\), work out the entropy of each child, and take the weighted average: the remaining entropy. The information gain is how much the test reduced the entropy. Choose the test with the largest gain.

Remaining entropy and information gain (Kelleher Eqs 4.3, 4.4)\[ \text{rem}(d, \mathcal{D}) = \sum_{l \in \text{levels}(d)} \frac{|\mathcal{D}_{d=l}|}{|\mathcal{D}|}\, H(t, \mathcal{D}_{d=l}), \qquad IG(d, \mathcal{D}) = H(t, \mathcal{D}) - \text{rem}(d, \mathcal{D}) \]
\(\text{rem}(d,\mathcal{D})\)
Entropy left after splitting on \(d\), in bits.
\(\mathcal{D}_{d=l}\)
The child partition: instances whose feature \(d\) equals level \(l\).
\(|\mathcal{D}_{d=l}|/|\mathcal{D}|\)
Weight: the fraction of the parent's instances that go to that child.
\(IG(d,\mathcal{D})\)
Information gain of the test on \(d\), in bits; never negative.

The children must be weighted by size. A tiny pure child should not make up for a big impure one: a split that peels off one pure instance and leaves 99 mixed ones has hardly helped.

Slide check (ten-patient table): the parent has 5 Benign and 5 Malignant, so \(H = 1\) bit. FamilyHistory = False has 5 Benign, 2 Malignant: \(H = 0.8631\) bits. FamilyHistory = True is pure: 0 bits. \(\text{rem} = 0.7(0.8631) + 0.3(0) = 0.6042\) bits and \(IG = 1 - 0.6042 = 0.3958\) bits.

Information gain ratio

Information gain is biased toward features with many levels. With many levels each child is small, small children are likely to be pure by chance, and any impure ones carry little weight. An identifier feature is the extreme case: it gets the maximum gain and generalises not at all.

The information gain ratio divides the gain by the entropy of the feature itself (the split information). A feature that shatters the data into many small partitions has a large split information, so its ratio is pulled down.

Information gain ratio (Kelleher Eq 4.8)\[ GR(d, \mathcal{D}) = \frac{IG(d, \mathcal{D})}{-\displaystyle\sum_{l \in \text{levels}(d)} P(d = l)\,\log_2 P(d = l)} \]
\(GR(d,\mathcal{D})\)
Gain ratio of feature \(d\) (dimensionless).
\(IG(d,\mathcal{D})\)
Information gain from Eq 4.4, in bits.
\(P(d=l)\)
Fraction of instances with level \(l\) of the descriptive feature (not the target).
Denominator
Split information: the entropy of \(d\), in bits.

Slide check: FamilyHistory sends 7 of 10 to False and 3 to True. Split information \(= -(0.7\log_2 0.7 + 0.3\log_2 0.3) = 0.8813\) bits, so \(GR = 0.3958/0.8813 = 0.4491\).

Gini index

The Gini index is a cheaper impurity measure (no logarithms). It is the probability of misclassifying a random instance from the node if you label it at random according to the node's class distribution: the "expected misclassification".

Gini index (Kelleher Eq 4.9)\[ \text{Gini}(t, \mathcal{D}) = 1 - \sum_{l \in \text{levels}(t)} P(t = l)^2 \]
\(\text{Gini}(t,\mathcal{D})\)
Gini index of node \(\mathcal{D}\); 0 for a pure node, at most \(1 - 1/k\) for \(k\) levels.
\(P(t=l)\)
Fraction of the node with target level \(l\).

Gini-based information gain uses the same recipe as before, with Gini in place of entropy: parent Gini minus the size-weighted average of the child Gini values. Slide check: parent \(1 - (0.5^2 + 0.5^2) = 0.5\); FamilyHistory = False \(1 - ((5/7)^2 + (2/7)^2) = 0.4082\); True \(= 0\). Gain \(= 0.5 - (0.7 \times 0.4082 + 0.3 \times 0) = 0.2143\).

Comparing the two measures (slides 2.6):

  • Gini is bounded in \([0, 1)\), which makes values easy to read. Entropy is unbounded as the number of levels grows, which gives stronger contrast between impure nodes.
  • Both are expectations over the class distribution: entropy is the expected number of bits needed, Gini the expected misclassification rate.
  • They usually recommend the same split. Which is better depends on the data, so choose by performance on a validation set.
Worked example 2.4 Gini-based gain

Repeat worked example 2.2 for Employed and History with the Gini index.

1
Parent (6/6): \(\text{Gini} = 1 - (0.5^2 + 0.5^2) = 0.5\).
2
Employed children (5/1): \(1 - ((5/6)^2 + (1/6)^2) = 1 - 26/36 = 0.2778\) each. Weighted: \(0.2778\). Gain \(= 0.5 - 0.2778 = 0.2222\).
3
History: pure children 0, fair child \(1 - (0.5^2 + 0.5^2) = 0.5\). Weighted: \(\tfrac{4}{12}(0.5) = 0.1667\). Gain \(= 0.5 - 0.1667 = 0.3333\).
Gini gain prefers History (0.333) over Employed (0.222), the same ranking as entropy.

03Tree induction: the ID3 algorithm

ID3 (Iterative Dichotomiser 3) grows a tree top-down and greedily. At each node it picks the feature with the highest information gain, splits on it, and repeats on each child with that feature removed. It is recursive: building a subtree is the same problem as building the whole tree, on fewer instances and features.

ID3(\(\mathbf{d}\), \(\mathcal{D}\)), where \(\mathbf{d}\) is the set of remaining descriptive features and \(\mathcal{D}\) the instances at this node:

  1. Base case 1, no impurity: if every instance in \(\mathcal{D}\) has the same target level, return a leaf with that level.
  2. Base case 2, no features left: if \(\mathbf{d}\) is empty, return a leaf with the majority target level of \(\mathcal{D}\).
  3. Base case 3, no instances: if \(\mathcal{D}\) is empty, return a leaf with the majority level of the parent's instances.
  4. Recursive case: find \(d[\text{best}] = \arg\max_{d \in \mathbf{d}} IG(d, \mathcal{D})\). Make a node that tests \(d[\text{best}]\). For each level \(l\) of \(d[\text{best}]\), add a branch whose child is ID3(\(\mathbf{d} - \{d[\text{best}]\}\), \(\mathcal{D}_{d[\text{best}]=l}\)).

A categorical feature is removed once used: every instance below that node already has the same value, so testing it again gains nothing.

Intuition

ID3's inductive bias is a preference for shallow trees, put into practice greedily: it takes the locally best test and never reconsiders. That is fast, but the tree is not guaranteed to be the smallest possible. A standard tree tests one feature per node, so its decision boundaries are axis-parallel (lines like \(x_1 = c\)).

Worked example 3.1 Finishing the tree

Continue worked example 2.3 with History at the root. The good child (4 Approve) and the poor child (4 Reject) are pure. The fair child has 2 Approve, 2 Reject; within it, Employed = yes gives 2 Approve and Employed = no gives 2 Reject. Grow the rest with ID3.

1
History = good: base case 1 (pure), leaf Approve. History = poor: leaf Reject.
2
History = fair: \(H = 1\) bit. Splitting on Employed makes both children pure: \(\text{rem} = 0\), \(IG = 1\) bit, the maximum possible. Make an Employed node.
3
Both Employed children are pure: leaves Approve (yes) and Reject (no).
The tree is History at the root; good → Approve, poor → Reject, fair → Employed (yes → Approve, no → Reject). Depth 2, four leaves, every training instance classified correctly.

04Continuous features

Continuous descriptive features: thresholds

A categorical feature's partitions are its distinct levels. A continuous feature could be split in infinitely many places. Two ways to make it usable:

  • Binning (Week 3): turn it into a categorical feature with equal-width or equal-frequency bins, chosen before training and without looking at the target.
  • Thresholding (more common): make a binary test \(d \ge \theta\) and learn the best threshold \(\theta\) from the target.

To find candidate thresholds efficiently:

  1. Sort the instances by the continuous feature.
  2. Wherever two adjacent instances have different target levels, take the midpoint of their feature values as a candidate.
  3. Score each candidate split with information gain (or Gini), as if it were a binary feature. Keep the best; it then competes with the other features.

Midpoints between adjacent instances with the same target need not be tried. Moving the threshold within a run of one class only moves same-class instances from one side to the other, which cannot beat a threshold at the run's boundary.

Reusing a continuous feature

A categorical feature is used at most once on a path. A continuous feature can be tested again further down the same path with a different threshold: after Elevation ≥ 1 975, the branch can still ask Elevation ≥ 3 000 to separate two classes that both lie above 1 975.

Figure 4.1: The instances of worked example 4.1, sorted by temperature. Adjacent instances differ in class in only two places, so only two thresholds (dashed) need to be scored, out of seven possible midpoints.

Worked example 4.1 Choosing a threshold

Eight days, sorted by Temperature (°C), with target Comfort: 12 Cold, 15 Cold, 18 Mild, 21 Mild, 24 Mild, 27 Hot, 31 Hot, 35 Hot. Find the best threshold by information gain.

Continuous targets: regression trees

A tree whose leaves predict a number is a regression tree. Three changes to ID3:

  • Split criterion: entropy and Gini need class levels, so use variance (equivalently mean squared error). The best split minimises the size-weighted variance of the children.
  • Leaf prediction: the mean target of the training instances in the leaf, not the majority class. The mean minimises the squared error within the leaf.
  • Stopping: continuous targets are almost never "pure", so base case 1 is replaced by an early-stopping rule such as a minimum leaf size (for example 5 % of the data). Too small a leaf overfits; too large a leaf underfits.
Variance and the regression split (Kelleher Eqs 4.10, 4.11)\[ \text{var}(t, \mathcal{D}) = \frac{\sum_{i=1}^{n} (t_i - \bar{t})^2}{n - 1}, \qquad d[\text{best}] = \arg\min_{d \in \mathbf{d}} \sum_{l \in \text{levels}(d)} \frac{|\mathcal{D}_{d=l}|}{|\mathcal{D}|}\, \text{var}(t, \mathcal{D}_{d=l}) \]
\(\text{var}(t,\mathcal{D})\)
Sample variance of the target in node \(\mathcal{D}\) (target units squared).
\(t_i\)
Target value of instance \(i\).
\(\bar{t}\)
Mean target in the node; also the leaf's prediction.
\(n\)
Number of instances in the node.
\(d[\text{best}]\)
The feature whose split gives the lowest weighted child variance.
Worked example 4.2 A regression split

Six days of bicycle rentals: weekdays 810, 950, 880; weekend days 1 420, 1 510, 1 390. Of these, the days with 950 and 1 420 were rainy. Compare splitting on DayType with splitting on Rain.

1
DayType: weekday mean 880, variance \(\tfrac{(-70)^2 + 70^2 + 0^2}{2} = 4\,900\). Weekend mean 1 440, variance \(\tfrac{(-20)^2 + 70^2 + (-50)^2}{2} = 3\,900\). Weighted: \(0.5(4\,900) + 0.5(3\,900) = 4\,400\).
2
Rain: rainy {950, 1 420}, mean 1 185, variance 110 450. Dry {810, 880, 1 510, 1 390}, mean 1 147.5, variance 125 225. Weighted: \(\tfrac26(110\,450) + \tfrac46(125\,225) = 120\,300\).
Split on DayType (weighted variance 4 400 against 120 300). The leaves predict 880 rentals on weekdays and 1 440 at weekends.

Model trees and oblique trees

Because each leaf predicts a constant, a regression tree's prediction function is piecewise constant: a staircase. Deeper trees give more, narrower steps and follow the data more closely (slides 7.2 show depths 0 to 5 fitting a wavy curve). Two extensions address the limits of standard trees:

  • A model tree fits a regression function (linear or non-linear) to the instances in each leaf, instead of using their mean. Prediction inside a leaf then varies with the features, so a model tree can follow a trend with far fewer leaves.
  • An oblique tree tests a linear combination of numeric features at a node, such as \(0.6\,\text{Elevation} + 40\,\text{Slope} \ge 1\,800\), instead of one feature. Its boundaries can be slanted rather than axis-parallel, which suits classes separated by a diagonal. The cost: finding a good hyperplane at each node needs a search, which is much slower, and the tests are harder to interpret.

Figure 4.2: The dots are 21 noisy samples of a curve. The solid steps are a four-leaf regression tree grown greedily by minimising squared error; the grey verticals are its three thresholds. The dashed lines are a two-leaf model tree, split at the same root threshold, with a least-squares line in each leaf. With half the leaves, the model tree follows the trend more closely.

Reading Kelleher et al. (2020) Sections 4.4.2 and 4.4.3; slides 4.1, 4.2, 7.2 and 7.3

05Pruning

A deep tree with many partitions ends with many leaves that hold only a few instances each. Those leaves fit noise and sampling variance in the training data: the tree overfits, scoring well on training data and worse on new data.

Figure 5.1: Illustrative accuracies for trees of maximum depth 1 to 8 (practice problem 7.4 uses these numbers). Training accuracy (ink) climbs to 1.00. Validation accuracy (teal) peaks at 0.83 at depth 4 and then falls: beyond depth 4 the extra splits fit noise. Choose depth 4.

Two families of remedies:

  • Pre-pruning (early stopping) stops growth during induction: a maximum depth, a minimum number of instances per node, a minimum information gain, or a statistical test that the split is significant. It is cheap but can stop too early, before a split that only pays off one level further down.
  • Post-pruning grows the full tree, then removes weak branches bottom-up. In reduced-error pruning, a hold-out validation set is passed through the tree. For each subtree whose children are leaves, compare the error of the parent (as a leaf predicting its majority) with the size-weighted error of its children. If the parent's error is equal to or lower than the children's, prune the children.
Worked example 5.1 Reduced-error pruning decision

A node receives 20 validation instances. Used as a leaf it misclassifies 4. Its two leaf children receive 12 and 8 validation instances and misclassify 2 and 3. Prune?

1
Parent error rate: \(4/20 = 0.20\).
2
Children's weighted error: \(\tfrac{12}{20}\cdot\tfrac{2}{12} + \tfrac{8}{20}\cdot\tfrac{3}{8} = \tfrac{5}{20} = 0.25\).
0.20 ≤ 0.25, so prune: replace the subtree with a leaf. The split made validation error worse.

Pruning makes trees robust (slides 7.1): outliers and noisy patterns tend to be isolated in small leaves, and small leaves of minority classes caused by sampling variance are the first to be pruned.

Cost-complexity pruning

Cost-complexity (weakest-link) pruning (Mackey, 2015) trades fit against size with one parameter, \(\alpha \ge 0\). It minimises

Cost-complexity objective\[ C_\alpha(T) = \sum_{R_m \in T} \sum_{x_i \in R_m} \left(y_i - \hat{y}_{R_m}\right)^2 + \alpha\,|T| \]
\(T\)
A pruned version of the full tree \(T_0\).
\(R_m\)
The region (leaf) \(m\) of \(T\).
\(y_i\)
Target of training instance \(x_i\) in that leaf.
\(\hat{y}_{R_m}\)
The leaf's prediction (its mean).
\(\alpha\)
Complexity parameter: the penalty per leaf, in the units of the RSS.
\(|T|\)
Number of leaves of \(T\).

The double sum is the residual sum of squares (RSS). With \(\alpha = 0\) the full tree wins (it has the smallest RSS). As \(\alpha \to \infty\) the single-leaf tree wins. In between, larger \(\alpha\) favours smaller trees.

The procedure builds a nested sequence of trees:

  1. Start with the full tree \(T_0\). For every internal node, compute the cost of collapsing its subtree into one leaf, per leaf removed: \[ \frac{\text{RSS}(T_1) - \text{RSS}(T_0)}{|T_0| - |T_1|} \] Collapse the subtree where this is smallest (the weakest link): it buys the most simplicity for the least increase in error. This gives \(T_1\).
  2. Repeat to get \(T_0, T_1, \ldots, T_m\), where \(T_m\) is a single leaf.
  3. Choose \(\alpha\) by 10-fold cross-validation: for each fold, grow the sequence on the other nine folds, compute the RSS of each tree on the held-out fold, and pick the \(\alpha\) with the lowest average error.

For classification, it is typical to grow the tree with Gini or entropy but to prune using the misclassification rate.

Worked example 5.2 Weakest link and the effect of α

(a) A full tree has two prunable subtrees. Subtree A has 3 leaves with RSS 40; collapsed to a leaf, its RSS is 100. Subtree B has 2 leaves with RSS 55; collapsed, 70. Which is pruned first? (b) Three candidate trees: 6 leaves with RSS 120, 3 leaves with RSS 180, 1 leaf with RSS 400. Which minimises \(C_\alpha\) for \(\alpha = 10\) and \(\alpha = 30\)?

1
A: \((100 - 40)/(3 - 1) = 30\) per leaf removed. B: \((70 - 55)/(2 - 1) = 15\). B is the weakest link: prune B first.
2
\(\alpha = 10\): \(120 + 60 = 180\); \(180 + 30 = 210\); \(400 + 10 = 410\). Minimum: the 6-leaf tree.
3
\(\alpha = 30\): \(120 + 180 = 300\); \(180 + 90 = 270\); \(400 + 30 = 430\). Minimum: the 3-leaf tree.
Prune B first. At \(\alpha = 10\) keep 6 leaves; at \(\alpha = 30\) the 3-leaf tree is best. The two tie at \(\alpha = 20\) (both 240).

06Rule extraction

After a tree is induced and pruned, it can be rewritten as a set of IF–THEN production rules, one per root-to-leaf path:

  • each decision node on the path becomes a condition (clause) in the rule's antecedent;
  • the conditions are joined with AND, because an instance reaches the leaf only if it passes every test on the path;
  • the leaf's class is the rule's consequent (decision).

So the number of rules equals the number of leaves. The rules are mutually exclusive and exhaustive, because every instance follows exactly one path. Extract rules after pruning, otherwise the rule set contains the overfitted, over-specific rules of the full tree. The rules explain a prediction in plain words: the antecedent of the rule that fired is the reason.

Worked example 6.1 Rules from the loan tree

Extract rules from the tree of worked example 3.1.

1
IF History = good THEN Approve.
2
IF History = fair AND Employed = yes THEN Approve.
3
IF History = fair AND Employed = no THEN Reject.
4
IF History = poor THEN Reject.
Four leaves give four rules. In rule 2 the antecedent is "History = fair AND Employed = yes" and the consequent is "Approve".
Summary of the week

Decision trees are interpretable supervised models: decision nodes test descriptive features and leaves predict the target. They can predict and also yield production rules that explain predictions. Regression trees predict leaf means; model trees put a regression in each leaf. Standard trees have axis-parallel boundaries; oblique trees use linear combinations but need a hyperplane search. Pruning makes trees robust to outliers, noise and sampling variance.

07Practice problems

Problem 7.1 Entropy, Gini and gain

A parent node has 12 instances: 4 Faulty and 8 OK. Feature Sensor splits it into High (3 Faulty, 1 OK) and Low (1 Faulty, 7 OK). Find (a) the parent entropy and Gini index, (b) the information gain, (c) the gain ratio and (d) the Gini gain.

1
Parent: \(H = -(\tfrac13\log_2\tfrac13 + \tfrac23\log_2\tfrac23) = 0.9183\) bits. Gini \(= 1 - (\tfrac19 + \tfrac49) = 0.4444\).
2
High (3/1): \(H = 0.8113\). Low (1/7): \(H = 0.5436\). \(\text{rem} = \tfrac{4}{12}(0.8113) + \tfrac{8}{12}(0.5436) = 0.6328\). \(IG = 0.9183 - 0.6328 = 0.2855\) bits.
3
Split information for a 4/8 split: \(0.9183\) bits. \(GR = 0.2855/0.9183 = 0.3109\).
4
Gini High \(= 1 - (0.75^2 + 0.25^2) = 0.375\); Low \(= 1 - ((1/8)^2 + (7/8)^2) = 0.2188\). Weighted \(= \tfrac13(0.375) + \tfrac23(0.2188) = 0.2708\). Gain \(= 0.4444 - 0.2708 = 0.1736\).
(a) 0.918 bits, 0.444; (b) 0.286 bits; (c) 0.311; (d) 0.174.
Problem 7.2 Thresholds and reuse

Sorted by Depth (m): 2 Sand, 5 Sand, 9 Clay, 14 Clay, 20 Rock, 26 Rock, 33 Clay. (a) List the candidate thresholds. (b) Why is 7 m a candidate but 3.5 m is not? (c) Why might Depth appear twice on one path?

1
Class changes: 5→9 (Sand→Clay), 14→20 (Clay→Rock), 26→33 (Rock→Clay). Candidates: 7, 17 and 29.5 m.
2
2 and 5 m are both Sand. A threshold between them only separates Sand from Sand, so it is never better than the boundary at 7 m.
3
Clay appears in two separate depth ranges. After a test Depth ≥ 17, the ≥ 17 branch still mixes Rock and Clay, which a second test Depth ≥ 29.5 separates.
(a) 7, 17 and 29.5 m. (b) Same class on both sides. (c) Continuous features may be reused with a different threshold.
Problem 7.3 Regression leaf and model tree

A regression-tree leaf holds monthly water use (kL) of 620, 700, 740, 780 and 860. (a) What does it predict? (b) What shape is a one-feature regression tree's prediction? (c) How would a model tree differ in this leaf?

1
Mean: \((620 + 700 + 740 + 780 + 860)/5 = 3\,700/5 = 740\) kL.
2
Every query in the leaf gets 740 kL, so the prediction is a staircase: constant within each leaf, jumping between leaves.
3
A model tree fits, say, a linear regression on the leaf's five instances, so its prediction changes with the features inside the leaf.
(a) 740 kL. (b) Piecewise constant. (c) A fitted function per leaf instead of a constant.
Problem 7.4 Choosing depth

Use the accuracies of Figure 5.1. Training: 0.68, 0.77, 0.84, 0.90, 0.94, 0.97, 0.99, 1.00. Validation: 0.66, 0.74, 0.80, 0.83, 0.82, 0.79, 0.76, 0.74 for depths 1 to 8. Which depth do you choose, and where does overfitting start?

1
Training accuracy rises steadily: deeper trees always fit the training data better.
2
Validation accuracy rises to 0.83 at depth 4, then falls.
Choose depth 4. Overfitting starts beyond depth 4, where training accuracy still rises but validation accuracy drops.
Problem 7.5 Oblique versus axis-parallel

Two classes are separated by the line \(x_2 = x_1\). How does a standard tree model this boundary, and how does an oblique tree?

1
A standard tree can only test one feature at a time, so it approximates the diagonal with a staircase of many axis-parallel splits: a deep tree.
2
An oblique tree can test \(x_2 - x_1 \ge 0\) in one node.
Standard: many splits forming a staircase. Oblique: one split. Advantage of oblique: a smaller, more accurate tree. Limitation: a costly hyperplane search and harder-to-read tests.

08Formula sheet

Impurity

\(H(t,\mathcal{D}) = -\sum_l P(t=l)\log_2 P(t=l)\)

\(\text{Gini}(t,\mathcal{D}) = 1 - \sum_l P(t=l)^2\)

Two classes: max \(H = 1\) bit, max Gini \(= 0.5\).

Choosing a split

\(\text{rem}(d,\mathcal{D}) = \sum_l \frac{|\mathcal{D}_{d=l}|}{|\mathcal{D}|} H(t,\mathcal{D}_{d=l})\)

\(IG = H(t,\mathcal{D}) - \text{rem}(d,\mathcal{D})\)

\(GR = IG / \left(-\sum_l P(d=l)\log_2 P(d=l)\right)\)

Gini gain: same as IG with Gini in place of \(H\).

Regression trees

\(\text{var}(t,\mathcal{D}) = \sum_i (t_i - \bar t)^2/(n-1)\)

Best split: minimum weighted child variance. Leaf predicts the mean.

Pruning

Reduced error: prune if parent error ≤ weighted child error (validation set).

\(C_\alpha(T) = \text{RSS}(T) + \alpha|T|\)

Weakest link: minimise \(\frac{\text{RSS}(T_1)-\text{RSS}(T_0)}{|T_0|-|T_1|}\).

ID3 base cases

Pure node → leaf of that class. No features → majority leaf. No instances → parent's majority.

Key facts

Thresholds: midpoints where adjacent sorted targets differ. Continuous features can be reused on a path. Rules = leaves; conditions ANDed.
