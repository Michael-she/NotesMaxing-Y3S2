DATA ANALYTICS 344 · WEEK 6

Rule-Based Knowledge Discovery

Classification as IF–THEN rules: rule structure, ordering and evaluation; learning rules with OneR and PRISM; overfitting and pruning; association rule mining.

Week 6 at a glance

Core ideas

  • A classification model can be represented as a rule set R = {r1, …, rk}; each rule is IF condition THEN prediction, with the condition built from conjuncts (feature tests) ANDed together.
  • An instance triggers every rule whose antecedent it satisfies. Ordered rule sets: first matching rule wins. Unordered sets: vote. No rule triggered: use a default rule/prediction.
  • Rule quality has two sides: coverage (how many instances trigger the rule) and accuracy (fraction of covered instances in the predicted class). Adding conditions raises accuracy but reduces coverage.
  • OneR builds a one-feature classifier: per feature, majority class per value, count errors, keep the feature with the smallest total error. PRISM (sequential covering / separate-and-conquer) grows rules for one class at a time by greedily maximising accuracy p/t until each rule is perfect on the training data.
  • More and more specific rules keep improving training accuracy but eventually overfit: validation accuracy peaks and then falls. Control with pruning, stopping criteria, or validation-based model selection.
  • Association rules differ from classification rules: any attribute may appear on either side and the consequent may contain several attributes. They are mined via frequent itemsets (minimum support) and a minimum confidence.

Key definitions

  • Antecedent / consequent — the condition part of a rule / the predicted target value.
  • Conjunct — one feature test in the antecedent, e.g. ToolWear = High.
  • Triggered (fired) rule — a rule whose antecedent is fully satisfied by the instance.
  • Ordered rule set (decision list) — rules in priority order; first rule that triggers decides.
  • Default rule — fallback prediction when no rule triggers.
  • Mutually exclusive — no instance triggers more than one rule.
  • Exhaustive — every possible instance triggers at least one rule.
  • Coverage (support) — number/fraction of instances satisfying the antecedent.
  • Accuracy (confidence) — fraction of covered instances that belong to the predicted class, p/t.
  • Inductive bias — the algorithm’s built-in preferences for choosing among models consistent with the data.
  • Itemset — a set of attribute–value pairs (items) considered together in association mining.

Formulas

  • Rule accuracy: accuracy(r) = p/t = (covered instances of target class) ÷ (all instances covered).
  • Rule coverage: instances satisfying the antecedent (as a count, or as a fraction of all instances).
  • Support: support(X) = number of transactions/instances containing all items in X.
  • Confidence: confidence(X ⇒ Y) = support(X ∪ Y) ÷ support(X).

Exam traps

  • Selecting rules or conditions by accuracy alone — a 100%-accurate rule covering 2 instances is usually useless.
  • PRISM adds the condition that maximises p/t (accuracy), not the one covering the most instances; ties are broken by larger p.
  • OneR compares the total error of all rules for a feature — not the single best rule of each feature.
  • Non-exhaustive rule sets need a default rule; forgetting it leaves instances unpredicted.
  • “First match wins” applies only to ordered rule sets; unordered sets resolve conflicts by voting.
  • Choose the model at the validation accuracy peak — never the one with the highest training accuracy.
  • Adding a condition can never increase coverage (AND only restricts).

01Classification models as IF–THEN rule sets

A classification model does not have to be a black box. Any classifier can, in principle, be represented as a set of IF–THEN rules: a rule set R = {r1, r2, …, rk} in which each individual rule rj (also called a disjunct or classification rule) has the form

rj :   IF condition THEN prediction
rj
Rule number j in the rule set.
condition
The antecedent: one or more feature tests joined by AND.
prediction
The consequent: the class assigned when the condition holds.

The condition (the rule antecedent) consists of one or more descriptive-feature tests logically ANDed together; each individual test is called a conjunct. A conjunct has the form feature ∇ value where ∇ is a comparison operator (=, ≠, <, >, ≤, ≥). The consequent (rule consequent / prediction) contains the predicted value of the target feature. For example, from the lecture traffic domain:

r1: IF time < 10:00 am AND day = weekday THEN traffic = heavy
rk: IF day = weekend THEN traffic = light

Definition

A rule triggers (fires) for an instance if the instance’s feature values satisfy every conjunct in the antecedent. When a rule triggers, the classifier predicts the rule’s consequent for that instance. If any single conjunct is false, the rule does not trigger and makes no prediction for that instance.

The lecture animal-classification example illustrates this. With rules such as

r1: IF gives_birth = no AND aerial_creature = yes THEN bird
r3: IF gives_birth = yes AND body_temperature = warm THEN mammal

the instance lemur (gives_birth = yes, body_temperature = warm, …) satisfies both conjuncts of r3, so r3 is triggered and the predicted class is mammal.

Intuition

Because conjuncts are ANDed, every extra condition can only shrink the set of instances that trigger the rule. A rule with no conditions (an empty or default rule) covers everything; a rule with many very specific conditions covers only a handful of instances. This monotone “narrowing” behaviour is the engine behind both PRISM (Section 7) and the coverage–accuracy trade-off (Section 4).

02Rule ordering, conflict resolution and default rules

To classify an instance with a rule-based model, we identify which rules the instance triggers. Two complications arise naturally:

  • An instance can trigger several rules with conflicting predictions. In the lecture’s animal example, the instance turtle (gives_birth = no, aerial_creature = no, aquatic_creature = semi) triggers both r4 (reptile) and r5 (amphibian). The conflict must be resolved.
  • An instance can trigger no rule at all. The instance dogfish shark (gives_birth = yes, aerial_creature = no, aquatic_creature = yes, body_temperature = cold) triggers none of the five rules, yet the classifier must still give a reasonable prediction.
Definition

An ordered rule set (decision list) arranges rules in decreasing priority; the prediction is the consequent of the first rule that triggers, and later rules are ignored for that instance. An unordered rule set has no fixed order; all triggered rules vote and the majority consequent is predicted (ties are usually resolved at random). A default rule (or default prediction) supplies the prediction when no rule triggers.

In an ordered set, rule position is part of the model: a rule that appears earlier overrides later, overlapping rules. In an unordered set, rules act as independent “nuggets of knowledge”, which is modular and readable, but conflicts must then be settled by voting, and instances triggering no rule still need a default. Witten et al. note that rules generated for the same class may be applied in any order (they all predict the same class), while ordering matters once rules for different classes can fire on the same instance.

Common mistake

Assuming “first match wins” for every rule set. It only holds for ordered rule sets. If the question gives an unordered set, conflicting triggered rules are resolved by a voting scheme (ties usually at random), and a missing prediction requires a default rule or default class (e.g., the class with the most training examples).

Reading  Witten et al. (4e), §4.4 — the “Rules versus decision lists” discussion explains ordered interpretation, conflicting rules and default rules. See also the Week 6 lecture slides (turtle and dogfish shark examples).

03Mutually exclusive and exhaustive rule sets

Definition

A rule set is mutually exclusive if no instance can trigger more than one rule (the rules do not overlap). It is exhaustive if there is a rule for every possible combination of attribute values, i.e. every instance — even an unseen one — triggers at least one rule.

Consequences when these properties are violated:

  • Not mutually exclusive: an instance may trigger several rules with different consequents, producing conflicting predictions that must be resolved (priority ordering or voting, Section 2).
  • Not exhaustive: some instances trigger no rule and receive no prediction unless a default rule (or default class) is provided.

A rule set that is both mutually exclusive and exhaustive guarantees that every instance is covered by exactly one rule: no conflicts, no gaps. In practice this is a strong requirement, and it is usually easier to use an ordered rule set plus a default rule to cover all instances than to engineer a rule set that is mutually exclusive and exhaustive by construction.

Intuition

Think of the rules as regions laid over the instance space. Mutually exclusive means the regions never overlap; exhaustive means the regions tile the whole space. Ordered rule sets relax both requirements: overlaps are allowed (earlier regions win) and the default rule fills whatever space is left uncovered.

04Rule evaluation: coverage and accuracy

Given two rule-based models, which should we prefer? The lectures motivate two complementary measures. For a rule r evaluated on a dataset:

Definition

Coverage (support): the number (or fraction) of all instances that satisfy the antecedent of the rule — how many instances the rule applies to.
Accuracy (confidence): the fraction of the covered instances that the rule classifies correctly — of the instances that trigger the rule, how many belong to the class predicted by the consequent.

Writing t for the number of instances covered by the rule and p for the number of covered instances that belong to the target class:

Both quantities matter. The lectures contrast two rules: rule r1 has accuracy 95% and covers 40 instances (38 correct); rule r2 has accuracy 100% but covers only 2 instances. Accuracy alone is not a good measure — but neither is coverage alone: a rule that covers all instances (e.g., the empty rule) is rarely accurate. A “good” rule covers a reasonable number of instances and is accurate.

Effect of adding conditions. Each added conjunct restricts which instances trigger the rule, so coverage can only stay the same or fall. Among the instances that remain, the proportion of the target class typically rises — accuracy increases while coverage decreases. Pushed too far, this produces increasingly specific rules that describe only a handful of training instances: the route to overfitting (Section 8).

Worked example — coverage vs accuracy

Two rules constructed from a training dataset:

  • Rule A is triggered by 40 observations; 36 belong to the class predicted by the rule.
  • Rule B is triggered by 5 observations; all 5 belong to the class predicted by the rule.

Step 1 — accuracies.

accuracy(A) = 3640 = 0.90     accuracy(B) = 55 = 1.00
36 / 40
Rule A is triggered by 40 observations, 36 of them in the predicted class.
5 / 5
Rule B is triggered by 5 observations, all in the predicted class.

Step 2 — coverage. Rule A covers 40 observations, Rule B only 5, so Rule A has the greater coverage; Rule B has the greater accuracy.

Step 3 — interpretation. Selecting rules on accuracy alone would always prefer rules like B: trivially perfect rules that cover almost nothing. A classifier built from such rules makes confident predictions for very few instances and pushes most instances to the default rule, so overall performance is poor and the rules capture noise rather than structure. In general, adding conditions to a rule increases accuracy (on the data used to build it) while reducing the number of observations that trigger it — which is why coverage must always be reported alongside accuracy.

05Inductive bias of rule-induction algorithms

The lectures show why learning rules cannot be driven by training data alone. With four binary descriptive features there are 24 = 16 possible instances and a binary target, so 216 = 65 536 different prediction functions exist; even restricting attention to models that are consistent (make no training error) leaves hundreds of consistent models, which disagree on unseen instances. A consistent model can simply memorise the training data without learning anything generalisable. Machine learning is therefore an ill-defined problem: the data alone cannot pick a unique model, so every algorithm must bring its own preferences to the search.

Definition

The inductive bias of a learning algorithm is the set of assumptions or preferences — beyond the training data — that it uses to choose among the hypotheses (rule sets) consistent with the data. It determines which rule sets the algorithm can and prefers to learn.

Examples of inductive biases seen this week:

  • “A good rule covers several instances and is accurate” — the general bias stated in the lectures; it prefers broad, accurate rules over narrow ones.
  • OneR biases the search to rule sets that use a single descriptive feature: very simple, very fast, but it can underfit when the true concept needs several features.
  • PRISM biases toward rules that are perfect on the training data: it keeps adding conjuncts until accuracy reaches 100%, greedily choosing the condition that maximises p/t at each step.

Study guide Question 6 contrasts two algorithms: Algorithm A prefers short rules with as few conditions as possible (a simplicity bias), while Algorithm B keeps adding conditions whenever training accuracy improves (a training-fit bias). Given the same training data they produce different rule sets: Algorithm B yields more complex rules. But the more complex rule set is not necessarily the better classifier — extra conditions may fit noise, and generalisation must be checked on unseen data (Section 8).

Common mistake

Treating “consistent with the training data” as a sufficient goal. Many consistent models exist; the inductive bias decides which one you get, and consistency says nothing about performance on unseen data.

06OneR: one rule (one feature) to rule them all

OneR constructs a classifier from a single descriptive feature. For each candidate feature it builds one rule per feature value (predicting the majority class among training instances with that value), counts the resulting classification errors, and finally keeps the rules of the feature with the smallest total error.

Algorithm

For each descriptive feature d:
    For every unique value v of d:
        find the target value that appears most frequently when d = v
        create the rule:  IF d = v THEN target = (that majority value)
    calculate the total error of the rules created for feature d
Keep the rules for the feature with the smallest total error; discard the rest.

The error of a rule is the number of covered instances whose true class differs from the majority class predicted for that value; the feature’s total error is the sum over its values. OneR then reports that feature’s rule set as the classifier.

Step 4 — select the feature. Hair has the smallest total error (1 error, i.e. training accuracy 7/8 = 87.5%), so OneR selects Hair and discards the Height and Eyes rule sets.

Step 5 — the OneR rule set:

r1: IF Hair = Black THEN Class = Yes
r2: IF Hair = Blond THEN Class = No
r3: IF Hair = Brown THEN Class = Yes

Step 6 — mutually exclusive? exhaustive? The rule set is mutually exclusive: an instance has exactly one Hair value, so at most one rule can trigger and predictions can never conflict. It is exhaustive over the values seen in training: every Hair value present in the data (Black, Blond, Brown) has a rule, so every training instance is covered. Strictly, an unseen Hair value (say “Red”) would trigger no rule, so full exhaustiveness over the whole attribute space would additionally require a default rule.

Numerical features and missing values

  • Numerical features: OneR works on categorical values, so a continuous feature (e.g., Height measured in cm) must first be discretised: bin the measurements into a small number of intervals (e.g., short/medium/tall, or data-driven bins) and then run OneR on the bin labels exactly as above.
  • Missing values: OneR does not require imputation. Missing can be treated as its own distinct value with its own majority-class rule, or the instances with a missing value can be left out when computing that feature’s majority classes and error. Either way the algorithm proceeds without first filling in the missing entries.
Common mistake

Comparing features by their single best rule. OneR compares the total error summed over all value-rules of a feature. Also remember the “1” in OneR: the final classifier uses only one descriptive feature — simple and interpretable, but prone to underfitting when the target depends on several features jointly.

07Sequential covering and the PRISM algorithm

A OneR model can underfit because it may only use one feature. To learn more complex rules, the lectures introduce sequential covering: rules are learned one at a time, each rule “covers” some instances, the covered instances are removed, and the process repeats on what remains.

Sequential covering (separate-and-conquer)

let DT be the training data set; set DS = DT
create an empty rule set R
for each target class tc:
    while DS contains instances with the label tc:
        learn a rule ri for class tc and add it to R
        remove the instances from DS covered by ri

Key properties of this scheme:

  • One class at a time. Rules are built for a chosen target class tc, disregarding the structure of the other classes except as “not tc”. This contrasts with decision trees, whose splits consider all classes at once.
  • Multiple rules per class. A single rule rarely covers all instances of the class, so the while-loop keeps generating further rules for tc until every tc-instance in DS is covered.
  • Removing covered instances is essential. If the instances covered by r1 were kept, the next iteration would simply re-learn the same rule. Removing them forces each new rule to specialise on the instances the earlier rules missed.
  • Because each rule separates out the instances it handles, these methods are called separate-and-conquer algorithms (contrast: divide-and-conquer for trees). The instance set continually shrinks, which keeps the search efficient.

PRISM: learning one rule

Sequential covering says that rules are learned sequentially; PRISM specifies how each rule is learned. For the current target class tc: 

Create a rule r with an empty condition that predicts tc
    (the empty rule covers all instances; its accuracy is the fraction of tc).
Repeat:
    For each descriptive feature d not yet in the condition of r,
      and for every unique value v of d:
        temporarily add (d = v) to the condition of r
        compute the coverage t and accuracy p/t of r
        remove (d = v) again
    Permanently add the condition (d = v) that maximises p/t
        (break ties by choosing the condition with the largest p).
Until the rule covers only instances of class tc (accuracy = 100%)
    or no descriptive features remain.
Remove the instances covered by r; start again if tc-instances remain.

The rule starts empty (general) and is specialised one conjunct at a time (general-to-specific). At each step PRISM evaluates every feature–value condition not yet in the rule and keeps the one that maximises the proportion of the target class among the covered instances. Because a rule is finished only when it covers target-class instances exclusively, PRISM generates rules that are perfect (or near-perfect) on the training data — which makes it prone to overfitting when the training data contain noise (Section 8).

The lectures illustrate PRISM on the 24-instance contact-lens dataset with target class hard (4 of 24 instances). The empty rule covers 24 instances at accuracy 4/24 ≈ 17%. Among the nine possible first conjuncts, astigmatism = yes and tear production rate = normal both give the largest fraction 4/12, one is chosen (here arbitrarily), then tear production rate = normal (4/6) and finally spectacle prescription = myope (3/3 = 100%), giving the perfect rule

IF astigmatism = yes AND tear production rate = normal AND spectacle prescription = myope THEN recommended lenses = hard.

This rule covers only 3 of the 4 hard instances, so the covered instances are removed and PRISM learns a second rule for hard from the remaining 21 instances (IF age = young AND astigmatism = yes AND tear production rate = normal THEN hard). Only then does the algorithm move on to the next class (soft, then none) — unless a default rule is used, in which case explicit rules for the final class are unnecessary.

Worked example — PRISM condition selection (study guide Question 5)

PRISM is constructing a rule for the target class Quality = Reject. Candidate conditions and their target/non-target counts:

Candidate conditionReject (p)AcceptCovered (t)Reject proportion p/t
ToolWear = High1241612/16 = 0.750
CoolantFlow = Low82108/10 = 0.800
Vibration = High6396/9 ≈ 0.667
Pressure = Low4044/4 = 1.000

Step 1 — select the condition. PRISM maximises the Reject proportion p/t. The maximum is Pressure = Low with 4/4 = 1.000, so the rule becomes

IF Pressure = Low THEN Quality = Reject

Step 2 — why this condition? Every instance it covers belongs to the target class: the rule is already 100% accurate on the training data, which is exactly what PRISM strives for. Note that it wins on proportion, not on coverage: ToolWear = High covers more Reject instances (12) but also 4 Accept instances, giving a lower proportion.

Step 3 — what if non-target instances remained? Suppose instead the best condition had been CoolantFlow = Low (0.800), still covering 2 Accept instances. PRISM would then continue growing the rule: among the features not yet in the rule, it evaluates every further feature–value condition on the instances currently covered, permanently adds the one with the highest new p/t, and repeats until the rule covers only Reject instances (or no features remain). This is why a PRISM rule can accumulate several conditions: each added conjunct can only remove instances from the covered set, so it is possible to keep cutting away the remaining Accept instances while retaining (most of) the Reject instances, driving accuracy toward 100%.

Step 4 — after the rule is finished. The instances covered by the completed rule are removed from the working set. If Reject instances remain uncovered, PRISM learns another rule for Reject on the reduced set; otherwise it moves on to the next class (Accept). Multiple rules per class are needed because each rule is restricted to a perfect rectangular “patch” of the instance space, and one patch seldom covers an entire class.

Common mistake

Assuming PRISM must produce an exhaustive rule set: it does not. If rules are generated for every class there is a rule for every training instance, but unseen combinations may trigger nothing; and if a default rule is used, explicit rules for the last class are omitted entirely. Also remember PRISM’s rules are perfect on the training data — that is a memorisation guarantee, not a generalisation one.

08Model complexity, overfitting and pruning

The complexity of a rule-based classifier is driven by the number of rules and by how specific each rule is (how many conjuncts it contains). Simple models (few, general rules — think OneR) can underfit: they perform poorly even on the training data because they cannot capture the underlying relationship. Very complex models (many highly specific rules — think unpruned PRISM) can overfit: they fit the training data almost perfectly, including its noise, and then perform poorly on unseen data.

The lectures’ remedy is a hold-out split (e.g., 70% training / 15% validation / 15% test): train candidate models of increasing complexity, plot training and validation performance against complexity, and select the model with the best validation performance. Underfitting shows up as poor training and validation performance; overfitting as validation performance far below training performance (validation error >> training error). The test set is reserved for the final, single evaluation of the chosen model.

Worked example — detecting overfitting in rule sets (study guide Question 7)

A rule-induction algorithm is run with different limits on the maximum number of rules:

Pattern. Training accuracy rises monotonically with the number of rules (0.71 → 0.98): more rules always let the model fit the training data more closely. Validation accuracy rises only up to 7 rules (0.84) and then falls (0.81 at 9 rules, 0.77 at 11).

Model selection. Choose the 7-rule model: it has the highest validation accuracy. Selection must be based on validation performance, not training performance.

Where overfitting begins. Beyond 7 rules: from 9 rules onward, training accuracy keeps climbing while validation accuracy drops — the extra rules are memorising noise in the training set rather than learning general structure.

Why not the 11-rule model? Its 0.98 training accuracy is the highest, but its validation accuracy (0.77) is well below the 7-rule model’s — the classic overfitting signature. Selecting by training accuracy rewards memorisation.

Two controls against overfitting. (1) Stopping criterion / complexity limit: cap the number of rules (or conjuncts per rule), as done in this table. (2) Rule pruning: after learning a rule, remove conjuncts one at a time and keep the removal whenever the pruned rule performs better on validation data. A third, equivalent view is validation-based model selection, as used above.

The lectures describe pruning concretely via the RIPPER algorithm: rules are grown general-to-specific (selecting conjuncts with the FOIL information-gain measure rather than raw accuracy), then pruned by repeatedly removing the last-added conjunct and re-measuring accuracy on validation data, keeping the removal whenever accuracy improves, until accuracy stops improving. The FOIL measure itself rewards rules that cover many target instances while being accurate (lecture formulation, with c, i the correct/incorrect coverage of the old rule and c′, i′ those of the new rule):

In short, overfitting in rule-based models is controlled by (i) rule pruning, (ii) stopping criteria (limits on rules/conjuncts, or stop adding conditions unless they help on held-out data), or (iii) model selection using validation data.

Common mistake

Reporting the training accuracy of the final (largest) rule set as the model’s quality. Always compare training and validation curves: the gap between them is your evidence of overfitting, and the validation peak decides which model to deploy.

09Association rule mining

Scope note

The Week 6 learning outcomes emphasise classification rules. However, association rule mining is part of Topic 6 per the module framework (“Rule-Based Knowledge Discovery: association rule mining …”) and is prescribed via Witten et al. §4.5, so it is included here. The practical component of the module implements these methods in R; these notes stay conceptual.

Association rules vs classification rules

  • In a classification rule, the consequent is always the designated target feature; descriptive features appear only in the antecedent.
  • In an association rule, any attribute may appear on either side, and the consequent may contain several attributes, e.g. IF temperature = cool THEN humidity = normal or IF temperature = cool AND windy = false THEN humidity = normal AND play = yes.
  • There is no distinguished target: association mining searches for any regular co-occurrence among attribute values (the classic setting is market-basket analysis, where items are purchases).

Because any combination of attributes could be a consequent, brute-force rule induction for every possible right-hand side is infeasible. Instead the method exploits the fact that only rules with high coverage are interesting, and works in two stages: first find frequent combinations of attribute–value pairs (itemsets), then turn them into rules with sufficient accuracy. Terminology: in this setting coverage is usually called support and accuracy confidence.

Definition

An item is an attribute–value pair; an itemset is a set of items. The support of an itemset (or rule) is the number of instances/transactions containing all its items. The confidence of a rule is the support of the full itemset (antecedent + consequent) divided by the support of the antecedent alone — the proportion of antecedent instances for which the rule is correct.

support(X) = number of instances containing all items in X   (sometimes normalised by N)

Why minimum support thresholds?

The user prescribes a minimum support (minimum coverage). This serves two purposes: it focuses the output on patterns that occur often enough to be interesting, and it makes the search feasible. Itemsets are generated level by level — all frequent one-item sets, then candidate two-item sets formed from pairs of them, then three-item sets, and so on — with one pass over the data per level to count coverage and discard itemsets below the threshold. The crucial property used is: an itemset can only reach the minimum support if all of its subsets also reach it, so infrequent subsets need never be expanded. (Sets containing two different values of the same attribute, e.g. outlook = sunny and outlook = overcast, are never generated since they cannot occur.)

From itemsets to rules

Each frequent itemset is then split into antecedent and consequent in every possible way, keeping only rules whose confidence meets the minimum accuracy. Witten et al.’s weather data gives a concrete illustration: the three-itemset {humidity = normal, windy = false, play = yes} has support 4 and yields seven candidate rules, including

  • IF humidity = normal AND windy = false THEN play = yes — 4/4 = 100%
  • IF humidity = normal AND play = yes THEN windy = false — 4/6
  • IF humidity = normal THEN windy = false AND play = yes — 4/7
  • IF play = yes THEN humidity = normal AND windy = false — 4/9

(each fraction is the itemset’s support divided by the support of the rule’s antecedent). With a minimum accuracy of 100%, only the first survives. Multi-consequent rules are built efficiently from single-consequent ones: a double-consequent rule can hold only if both corresponding single-consequent rules hold, so candidates are grown one consequent at a time instead of enumerating all subsets.

Qualitatively, for the weather data with minimum coverage 2 and minimum accuracy 100%, the procedure returns 58 rules — 3 with coverage 4 (e.g. outlook = overcast ⇒ play = yes), 5 with coverage 3 (e.g. outlook = sunny AND humidity = high ⇒ play = no), and 50 with coverage 2. The point of the example is the mechanism (support filtering, then confidence filtering), not memorising the rules.

Intuition

Association mining reverses the usual modelling question. Instead of “given features, predict the target”, it asks “which attribute values tend to occur together?”. Support filters out coincidences that are too rare to matter; confidence checks that the co-occurrence is reliable enough when the antecedent holds.
