Deep Learning: Regularisation, CNNs and RNNs

Deep networks have huge numbers of parameters and overfit easily, so early stopping and dropout are used to keep them general. Convolutional networks exploit the local structure of images; recurrent networks carry a hidden state through time. This page covers how both are built, how to compute their outputs and sizes by hand, and how they are trained.

01Preventing overfitting

Deep learning models can have millions of parameters. That capacity lets them fit complex functions, and also memorise noise in the training data: they are prone to overfitting. The two methods in this module are early stopping and dropout. Both are forms of regularisation: they keep weights small, so that predictions are stable under small changes in the input and outliers are not amplified.

Early stopping

During training, the training loss keeps falling. The loss on a separate validation set falls at first, then starts to rise once the network begins fitting noise. Early stopping watches the validation loss and stops training around that point.

  • A patience parameter sets how many consecutive epochs the validation error may increase before training is stopped. Patience greater than 1 stops a single noisy uptick from ending training too soon.
  • After stopping, keep the version of the model with the lowest validation error, not the last one trained. In practice the weights are saved whenever a new best is reached.

Figure 1.1: The validation losses of worked example 1.1 (teal) and an illustrative training loss (ink). Validation loss reaches its minimum of 0.51 at epoch 7. With patience 2, the increases at epochs 8 and 9 stop training after epoch 9 (dashed), and the epoch-7 weights are restored. The single rise at epoch 6 did not trigger a stop because epoch 7 improved again.

Worked example 1.1 Early stopping with patience

Validation loss by epoch: 0.90, 0.72, 0.61, 0.55, 0.52, 0.53, 0.51, 0.54, 0.57, 0.60. Patience is 2 consecutive increases. When does training stop, and which model is kept? What would patience 1 do?

1

2

Dropout

In each feedforward phase, dropout picks a random set of neurons from the input and hidden layers and drops them: they are deleted from the network for that forward and backward pass and reinstated afterwards. Each training step therefore trains a smaller, randomly thinned network. No neuron can rely on particular others being present, so the network learns redundant, robust features, an effect similar to averaging many smaller networks.

Inverted dropout is how it is implemented:

  • For each layer, draw a dropmask: a vector of 0s and 1s where each entry is 1 (keep) with probability \(p\).
  • Multiply the activations by the mask: dropped neurons output 0.
  • Divide the kept activations by \(p\). On average only a fraction \(p\) of the neurons survive, so scaling up by \(1/p\) keeps the expected weighted sum into the next layer the same as without dropout. At prediction time no neurons are dropped and nothing is rescaled.
Inverted dropout\[ \tilde{\mathbf{a}} = \frac{\mathbf{m} \odot \mathbf{a}}{p}, \qquad m_i \sim \text{Bernoulli}(p) \]
\(\mathbf{a}\)
Activations of a layer in the forward pass.
\(\mathbf{m}\)
Dropmask: each entry 1 with probability \(p\), else 0.
\(\odot\)
Elementwise product.
\(p\)
Probability that a neuron is kept (not dropped).
\(\tilde{\mathbf{a}}\)
Activations passed to the next layer during training.
Worked example 1.2 Applying a dropmask

A hidden layer outputs \(\mathbf{a} = (2.0, 0.5, 3.0, 1.2)\). The keep probability is \(p = 0.75\) and the drawn mask is \((1, 0, 1, 1)\). Find the activations passed on.

1
Mask: \((2.0, 0, 3.0, 1.2)\).
2
Divide by 0.75: \((2.667, 0, 4.0, 1.6)\).
\((2.667, 0, 4.000, 1.600)\). Neuron 2 is dropped for this step; the others are scaled up by \(1/0.75 = 1.333\).

Contrastive loss trains a network so that pairs from the same class get a small output distance and pairs from different classes get a distance of at least a set margin.

A general fully connected DNN treats every input independently of its position. It does not know that neighbouring pixels belong together, or that one time step follows another. So it is not effective for tasks that need local visual features (use a CNN) or sequential/temporal features (use an RNN). It also needs a weight for every input–neuron pair, which explodes for images.

03CNN structure

A traditional convolutional neural network (CNN) is built as: input → convolution (+ ReLU) → pooling → … → flatten → fully connected → output. It takes an image and can produce, for example, softmax class probabilities or another image.

  • A grayscale image is a 2-D matrix of height × width, with values from 0 (black) to 255 (white): \(0 \le \text{Img}(i,j) \le 255\). A 28 × 28 grayscale image has shape 28 × 28 (or 28 × 28 × 1).
  • A colour image in RGB is a 3-D array, height × width × 3: three channels (red, green, blue). A 28 × 28 RGB image has shape 28 × 28 × 3.
  • Normalise the image (range or z-score) before convolution so that the learned features respond to patterns of relative intensity, such as edges, rather than to how bright the image happens to be.

Three ideas make convolutional layers work:

  • Local receptive field: each neuron in a convolutional layer looks only at a small patch of the input (say 3 × 3), not the whole image.
  • Weight sharing: all neurons in one feature map use the same filter weights, applied at different positions. A feature detector (a vertical-edge detector, say) useful in one part of the image is useful everywhere.
  • Feature map: the grid of outputs from one filter: the filtered image. Each filter gives one feature map; the maps are stacked like channels.

Because a shared weight is used at every position, backpropagation computes a separate weight update for each neuron that uses it. The effective update applied to the shared weight is the sum of those separate updates.

Channel or feature map?

A channel is one slice of the depth of a volume. For an input image the channels are colours (R, G, B). For a hidden layer the channels are the feature maps, one per filter. "Depth" means the number of channels.

04Convolution

Convolution slides a small filter (kernel) over the image like a window. At each position it multiplies the kernel elementwise with the image tile under it, sums the products and adds a bias; that number is one pixel of the output feature map. A ReLU is then applied to the feature map.

One convolution output\[ z_{r,c} = \sum_{u}\sum_{v} K_{u,v}\,X_{r+u,\,c+v} + b, \qquad a_{r,c} = \text{ReLU}(z_{r,c}) \]
\(X\)
Input image (or previous feature map).
\(K_{u,v}\)
Kernel weight at row \(u\), column \(v\) of the filter.
\(b\)
The filter's bias (one per filter).
\(z_{r,c}\)
Output pixel at row \(r\), column \(c\) of the feature map.
\(a_{r,c}\)
After ReLU.

Figure 4.1: The numbers of worked example 4.1. The highlighted tile produces the highlighted output: elementwise products summed, plus the bias 0.5, gives −1.5. Sliding the window one column right gives 0.5, and so on. Deep-learning "convolution" does not flip the kernel; mathematically it is cross-correlation, but the name stuck (Sefidian 1.1).

Output size, padding and stride

Output dimension\[ O = \frac{I - F + 2P}{S} + 1 \]
\(O\)
Output height (or width) in pixels.
\(I\)
Input height (or width).
\(F\)
Filter size (filters are square: height = width = \(F\)).
\(P\)
Padding: rows/columns of zeros added on each side.
\(S\)
Stride: the step size of the sliding window.

If the division is not exact, round down: the window cannot hang off the edge. Since \(F\) need not divide the image size, some border pixels may not be fully covered, and pixels at the edge are used by fewer windows than those in the middle: the border effect. Padding adds zeros around the image to fix this:

  • Valid padding: no padding, \(P = 0\). The output shrinks by \(F - 1\).
  • Same padding: just enough padding that the output size equals the input size. For \(S = 1\), \(P = (F-1)/2\), which is why filter sizes are usually odd (3, 5, 7).
Worked example 4.2 Output dimensions

A 64 × 64 image is convolved with a 5 × 5 filter. Find the output size for (a) \(P = 0, S = 1\), (b) \(P = 2, S = 1\), (c) \(P = 2, S = 2\).

1
(a) \((64 - 5 + 0)/1 + 1 = 60\): 60 × 60 (valid).
2
(b) \((64 - 5 + 4)/1 + 1 = 64\): 64 × 64 (same, since \(P = (5-1)/2 = 2\)).
3
(c) \((64 - 5 + 4)/2 + 1 = 32.5\), rounded down to 32: 32 × 32.
60 × 60, 64 × 64 and 32 × 32. A stride of 2 roughly halves each dimension.

Depth, filters and parameters

  • A filter's depth must equal the input's depth: on an RGB image, a "3 × 3" filter is really 3 × 3 × 3, and one output pixel sums all 27 products plus a bias. The filter has to cover every channel at that position.
  • The output depth equals the number of filters: each filter produces one feature map, and the maps are stacked.
  • Parameters of a convolutional layer: \((F \times F \times C_{\text{in}} + 1) \times N_{\text{filters}}\). This does not depend on the image size: sparsity of connections.
Watch out

Sefidian's notes say an RGB filter is "a cube \(f \times f \times f\)". That is a slip: the depth of the filter is the number of input channels, \(f \times f \times n_C\) (\(f \times f \times 3\) for RGB), as the same notes state later under "notation and volumes".

Worked example 4.3 Why convolution saves parameters

A 64 × 64 × 3 image goes into a layer of 10 filters of size 5 × 5 with valid padding. Find the filter depth, the output shape and the parameter count, and compare with a fully connected layer of 100 neurons on the same image.

1
Filter depth = input depth = 3, so each filter is 5 × 5 × 3.
2
Output: \((64 - 5)/1 + 1 = 60\), depth 10 (one per filter): 60 × 60 × 10.
3
Parameters: \((5 \cdot 5 \cdot 3 + 1) \times 10 = 76 \times 10 = 760\).
4
Fully connected: \(64 \cdot 64 \cdot 3 = 12\,288\) inputs × 100 neurons = 1 228 800 weights (plus 100 biases).
The convolutional layer has 760 parameters against about 1.23 million: weight sharing and local receptive fields cut the parameter count by a factor of over 1 600.

05Pooling and the full CNN

Pooling downsamples each feature map by aggregating a window of pixels into one value. It slides a window like convolution, with an operator such as max, mean, sum or median. A 2 × 2 window with stride 2 halves each spatial dimension (the windows do not overlap). Pooling acts on each channel separately, so the depth is unchanged.

  • Pooling has no weights to learn: only hyper-parameters (window size, stride, operator). In backpropagation its derivative is fixed by the operation (for max pooling, the gradient goes only to the position that was the maximum).
  • It shrinks the representation, which speeds up later layers, makes detected features a little robust to small shifts, and lets later convolutions see a larger region of the original image. Repeated convolution and pooling therefore extract progressively more abstract features: edges, then textures and parts, then objects.

Figure 5.1: The feature map of worked example 5.1. Each shaded 2 × 2 window becomes one output value. Max pooling keeps the strongest response in each window; mean pooling averages it.

After the last convolution and pooling stage, the 3-D volume is flattened into one long vector, because a fully connected layer expects a vector of inputs. The fully connected layers (usually ReLU, often with dropout) combine the extracted features, and the output layer (for example softmax) makes the prediction. Training learns the kernel weights and the fully connected weights by backpropagation. Most of a CNN's parameters sit in its fully connected layers.

06RNN structure

A recurrent neural network (RNN) models temporal (sequential) data: sensor readings, ECG traces, text. Temporal data has three dimensions:

  • Instances: the separate sequences (one patient's ECG trace).
  • Timestamps: the positions in each sequence (one per millisecond).
  • Features: what is measured at each timestamp (the voltage, or several leads).

Every timestamp has the same number of features, but instances can have different numbers of timestamps. Mini-batch training needs equal lengths, so sequences are padded: pre-padding adds filler (zeros) at the start, post-padding at the end.

At every timestamp the RNN receives a new input \(\mathbf{x}^{t}\) and keeps a hidden state \(\mathbf{h}^{t}\), a memory of important information from earlier inputs. The new hidden state combines the current input with the previous hidden state, and the output is computed from the hidden state:

Simple RNN (SRNN)\[ \mathbf{h}^{t} = \varphi\!\left(\mathbf{W}_{hh}\,\mathbf{h}^{t-1} + \mathbf{W}_{xh}\,\mathbf{x}^{t} + \mathbf{b}_h\right), \qquad \hat{\mathbf{y}}^{t} = \varphi_o\!\left(\mathbf{W}_{hy}\,\mathbf{h}^{t} + \mathbf{b}_y\right) \]
\(\mathbf{x}^{t}\)
Input at timestamp \(t\).
\(\mathbf{h}^{t-1}\)
Previous hidden state (\(\mathbf{h}^0\) is usually zero).
\(\mathbf{h}^{t}\)
Current hidden state, passed on to step \(t+1\).
\(\mathbf{W}_{xh}, \mathbf{W}_{hh}, \mathbf{W}_{hy}\)
Input-to-hidden, hidden-to-hidden (recurrent) and hidden-to-output weights; the same at every timestamp.
\(\varphi, \varphi_o\)
Hidden activation (e.g. ReLU or tanh) and output activation.
\(\hat{\mathbf{y}}^{t}\)
Output at timestamp \(t\).

The input \(\mathbf{x}^t\) is what is observed now. The hidden state \(\mathbf{h}^t\) is the network's summary of everything up to now: it depends on \(\mathbf{x}^t\), \(\mathbf{x}^{t-1}\), and so on through the recurrence. The weights are shared across time for the same reason a CNN shares filters across space: the same rule applies at every step, and the model handles sequences of any length with a fixed number of parameters.

08Backpropagation through time

RNN weights start random, so early predictions are poor. To train, roll the RNN out over the timestamps of a training sequence. The unrolled network is an ordinary deep feedforward network in which the same weight matrices appear once per timestamp. If every function in it is differentiable, the chain rule gives \(\partial L/\partial \mathbf{W}\) for each weight matrix: this is backpropagation through time (BPTT).

Because \(\mathbf{W}_{hh}\) (and \(\mathbf{W}_{xh}\)) is used at every step, it gets a gradient contribution from every step. The gradient for a repeated weight is the sum of its contributions across all timestamps: the same rule as for a shared CNN filter. The network then learns from every timestamp of the training instance.

Worked example 8.1 Summing gradients through time

A linear RNN \(h^t = w\,h^{t-1} + x^t\) with \(w = 0.5\), \(h^0 = 0\) and inputs (1, 1, 1). The loss is \(L = \tfrac12(2 - h^3)^2\). Find \(\partial L/\partial w\).

1
Forward: \(h^1 = 1\), \(h^2 = 1.5\), \(h^3 = 1.75\). \(\partial L/\partial h^3 = -(2 - 1.75) = -0.25\).
2
Step 3 uses \(w\) directly with input \(h^2\): contribution \(-0.25 \times 1.5 = -0.375\).
3
Step 2 uses \(w\) with input \(h^1\); its effect reaches \(h^3\) through one more factor \(w\): \(-0.25 \times 0.5 \times 1 = -0.125\).
4
Step 1 uses \(w\) with input \(h^0 = 0\): contribution 0.
\(\partial L/\partial w = -0.375 - 0.125 + 0 = -0.5\). Contributions from earlier steps carry extra factors of \(w\), which is where vanishing and exploding gradients come from.
  • Diminishing (vanishing) gradients: a contribution from \(k\) steps back carries roughly \(k\) factors of the recurrent weight times the activation slope. If these are below 1, it shrinks geometrically: \(0.5^{20} \approx 10^{-6}\). The network cannot learn long-range dependencies because distant timestamps barely affect the update.
  • Exploding gradients: if the factors are above 1, contributions grow geometrically (\(1.5^{20} \approx 3\,300\)). Updates become huge and training is unstable. (A common fix, beyond this module, is to clip the gradient's size; LSTM and GRU cells address vanishing gradients.)
Summary of the week

Deep networks model complex functions but overfit; early stopping and dropout regularise them. CNNs use local receptive fields, weight sharing and pooling (subsampling), loosely mimicking the visual system. RNNs process variable-length sequences and keep a hidden state, so predictions use current and past inputs. Both use padding to standardise input sizes. Both are trained by backpropagation; pooling has no weights, and in RNNs BPTT sums the gradients of shared weights over all timestamps.

10Formula sheet

Regularisation

Early stopping: stop after patience consecutive validation increases; keep the lowest-validation model.

Inverted dropout: \(\tilde{\mathbf a} = \mathbf m \odot \mathbf a / p\).

Output choices

Regression: linear + SSE. Similarity: sigmoid + contrastive. Classification: softmax + cross-entropy.

Convolution

\(z = \sum K \odot \text{tile} + b\), then ReLU.

\(O = \lfloor (I - F + 2P)/S \rfloor + 1\); same: \(P = (F-1)/2\).

Filter depth = input depth; output depth = number of filters.

Params: \((F^2 C_\text{in} + 1) N_\text{filters}\).

Pooling

Max, mean, sum or median per window; 2 × 2 stride 2 halves height and width; no weights; depth unchanged.

RNN

\(\mathbf h^t = \varphi(\mathbf W_{hh}\mathbf h^{t-1} + \mathbf W_{xh}\mathbf x^t + \mathbf b)\)
