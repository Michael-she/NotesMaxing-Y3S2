Similarity-Based Learning, k-NN and Linear Regression

Two ways to learn from labelled data. k-nearest neighbours stores the training set and predicts from the most similar instances, so it needs a good similarity measure and well-prepared features. Linear regression fits a few weights by minimising the sum of squared errors with batch gradient descent.

01Instance-based learning

Most models learn a generalised function from the training data and then discard the data. Instance-based learning skips that step: it stores the training instances and, when a query arrives, predicts from the stored instances most similar to it. It is also called lazy learning, because the work happens at prediction time.

The idea is "predict what worked in similar cases before". It suits problems where instances of the same class have a lot in common but a general rule is hard to write down, such as recommender systems ("customers like you bought…").

Definition

Similarity-based learning needs two ingredients: (1) a similarity or distance measure over the feature space and (2) a set of known input–target mappings (the labelled training set).

The slides note that such models have low variance error when enough neighbours are used, while the bias depends on how well the distance measure captures what "similar" means for the problem.

Reading Kelleher et al. (2020) Sections 5.1 and 5.2; slides 1 to 2.1

02Distance metrics

Each instance is a point in an \(m\)-dimensional feature space, one axis per descriptive feature. Close points are similar. A function \(\text{metric}(\mathbf{a}, \mathbf{b})\) is a proper distance metric if it satisfies four criteria:

CriterionRuleMeaning
Non-negativity\(\text{metric}(\mathbf{a},\mathbf{b}) \ge 0\)Distances are never negative.
Identity\(\text{metric}(\mathbf{a},\mathbf{b}) = 0 \iff \mathbf{a} = \mathbf{b}\)Zero distance only for identical points.
Symmetry\(\text{metric}(\mathbf{a},\mathbf{b}) = \text{metric}(\mathbf{b},\mathbf{a})\)Distance from a to b equals distance from b to a.
Triangle inequality\(\text{metric}(\mathbf{a},\mathbf{b}) \le \text{metric}(\mathbf{a},\mathbf{c}) + \text{metric}(\mathbf{b},\mathbf{c})\)A detour via c is never shorter.

Distance values should be easy to compare. Bounded measures (for example in \([0, 1]\)) are easier to read as "similar" or "dissimilar" than unbounded ones.

Minkowski distances

The Minkowski distance is a family of metrics for numeric features, one for each value of the parameter \(p\):

Minkowski, Manhattan and Euclidean (Kelleher Eqs 5.1–5.3)\[ \text{Minkowski}(\mathbf{a},\mathbf{b}) = \left(\sum_{i=1}^{m} |\mathbf{a}[i] - \mathbf{b}[i]|^{p}\right)^{1/p} \] \[ p = 1:\ \text{Manhattan} = \sum_{i=1}^{m} |\mathbf{a}[i]-\mathbf{b}[i]|, \qquad p = 2:\ \text{Euclidean} = \sqrt{\sum_{i=1}^{m} (\mathbf{a}[i]-\mathbf{b}[i])^2} \] \[ p = \infty:\ \text{Chebyshev} = \max_{i} |\mathbf{a}[i]-\mathbf{b}[i]| \]
\(\mathbf{a}, \mathbf{b}\)
The two instances being compared (feature vectors).
\(m\)
Number of descriptive features.
\(\mathbf{a}[i]\)
Value of feature \(i\) for instance \(\mathbf{a}\).
\(p\)
Minkowski parameter, \(p \ge 1\).

Manhattan (taxi-cab) distance adds up the moves along each axis. Euclidean distance is the straight line. Chebyshev (chessboard) distance is the largest single difference, like the number of moves a chess king needs.

Larger \(p\) is more sensitive to one large difference. Raising differences to a high power makes the largest term dominate the sum: with differences 3 and 4, \(p=1\) gives 7, where the 4 is 57 % of the total; \(p=2\) gives \(\sqrt{9+16}\), where it contributes 64 % of the sum of squares; \(p=\infty\) keeps only the 4. Manhattan treats many small differences and one big one more evenly.

Figure 2.1: Each outline is the set of points at distance exactly 1 from the centre. Manhattan (\(p = 1\)) gives a diamond, Euclidean (\(p = 2\)) a circle, \(p = 4\) a rounded square and Chebyshev (\(p = \infty\)) a square. As \(p\) grows, the outline grows toward the square: a point that differs a lot in only one feature counts as "close" for large \(p\) only if that single difference is small.

Worked example 2.1 Three distances, two different answers

Query \(\mathbf{q} = (1, 6)\). Training instances \(\mathbf{d}_1 = (4, 2)\) and \(\mathbf{d}_2 = (3, 8)\). Find the nearest under Manhattan, Euclidean and Chebyshev.

1
Differences: \(\mathbf{q}-\mathbf{d}_1\): \(|1-4| = 3\), \(|6-2| = 4\). \(\mathbf{q}-\mathbf{d}_2\): \(|1-3| = 2\), \(|6-8| = 2\).
2
Manhattan: \(3 + 4 = 7\) and \(2 + 2 = 4\).
3
Euclidean: \(\sqrt{9+16} = 5\) and \(\sqrt{4+4} = 2.828\).
4
Chebyshev: \(\max(3,4) = 4\) and \(\max(2,2) = 2\).
\(\mathbf{d}_2\) is nearest under all three (4, 2.83 and 2 against 7, 5 and 4). As \(p\) rises, the distance to \(\mathbf{d}_1\) shrinks from 7 to 5 to 4 because only its largest difference counts in the end.

03Other measures of similarity

A similarity model can use a measure that is not a proper metric. Two common cases are binary features and cosine similarity. Note the direction: these are similarity indices (bigger means more alike), not distances.

Binary features

For binary (true/false) features, compare the query \(\mathbf{q}\) and an instance \(\mathbf{d}\) feature by feature and count four cases:

\(\mathbf{d}\) true\(\mathbf{d}\) false
\(\mathbf{q}\) trueCP co-presencePA presence–absence
\(\mathbf{q}\) falseAP absence–presenceCA co-absence
Binary similarity indices (Kelleher Eqs 5.9–5.11)\[ \text{sim}_{RR}(\mathbf{q},\mathbf{d}) = \frac{CP}{|\mathbf{q}|}, \qquad \text{sim}_{SM}(\mathbf{q},\mathbf{d}) = \frac{CP + CA}{|\mathbf{q}|}, \qquad \text{sim}_{J}(\mathbf{q},\mathbf{d}) = \frac{CP}{CP + PA + AP} \]
\(\text{sim}_{RR}\)
Russell–Rao index: share of features that are true in both.
\(\text{sim}_{SM}\)
Sokal–Michener index: share of features on which they agree (both true or both false).
\(\text{sim}_{J}\)
Jaccard index: co-presences as a share of features that are true in at least one.
\(CP, CA, PA, AP\)
Counts of co-presence, co-absence, presence–absence and absence–presence.
\(|\mathbf{q}|\)
Total number of binary features, \(CP + CA + PA + AP\).

Jaccard ignores co-absences. In sparse data (shopping baskets, documents, symptoms) most features are false for everyone. Two customers who both did not buy 9 990 of 10 000 products are not similar for that reason. Counting co-absences, as Sokal–Michener does, would make almost everyone look identical. Categorical features can be turned into binary ones with one-hot encoding (one 0/1 feature per level) before using these indices.

Worked example 3.1 Binary similarity

Over eight binary features, \(\mathbf{q} = (1,0,1,1,0,0,0,1)\) and \(\mathbf{d} = (1,0,0,1,0,1,0,0)\). Find the three indices.

1
Count: CP (both 1) at features 1 and 4: 2. CA (both 0) at 2, 5 and 7: 3. PA (q 1, d 0) at 3 and 8: 2. AP (q 0, d 1) at 6: 1. Check: \(2+3+2+1 = 8\).
2
Russell–Rao: \(2/8 = 0.25\). Sokal–Michener: \((2+3)/8 = 0.625\).
3
Jaccard: \(2/(2+2+1) = 0.4\).
RR = 0.25, SM = 0.625, J = 0.4. SM is the highest because it rewards the three shared absences.

Cosine similarity

Cosine similarity compares the direction of two numeric vectors, ignoring their length: it is the cosine of the angle between them.

Cosine similarity (Kelleher Eq 5.14)\[ \text{sim}_{COS}(\mathbf{a},\mathbf{b}) = \frac{\mathbf{a}\cdot\mathbf{b}}{\sqrt{\sum_{i=1}^{m}\mathbf{a}[i]^2}\,\times\,\sqrt{\sum_{i=1}^{m}\mathbf{b}[i]^2}} = \cos\theta \]
\(\mathbf{a}\cdot\mathbf{b}\)
Dot product, \(\sum_i \mathbf{a}[i]\,\mathbf{b}[i]\).
\(\sqrt{\sum_i \mathbf{a}[i]^2}\)
Length (Euclidean norm) of \(\mathbf{a}\).
\(\theta\)
Angle between the two vectors.

Two vectors pointing the same way have \(\theta = 0\) and similarity 1, however different their sizes: a customer who sends 20 SMS and makes 40 calls has the same pattern as one who sends 200 and makes 400. With non-negative features the value lies in \([0, 1]\), where 0 means perpendicular (maximally dissimilar). Negative feature values could give negative similarity, so the slides recommend range normalisation to \([0,1]\) first.

Worked example 3.2 Cosine similarity

Find the cosine similarity of \(\mathbf{a} = (3, 4)\) with \(\mathbf{b} = (6, 8)\) and with \(\mathbf{c} = (4, 3)\).

1
\(\mathbf{a}\cdot\mathbf{b} = 18 + 32 = 50\); \(|\mathbf{a}| = 5\), \(|\mathbf{b}| = 10\). Similarity \(= 50/50 = 1\).
2
\(\mathbf{a}\cdot\mathbf{c} = 12 + 12 = 24\); \(|\mathbf{c}| = 5\). Similarity \(= 24/25 = 0.96\).
\(\mathbf{b}\) is maximally similar (1.00) although it is twice as long. \(\mathbf{c}\) has the same length as \(\mathbf{a}\) but points slightly differently (0.96). Euclidean distance would rank them the other way: \(|\mathbf{a}-\mathbf{c}| = 1.41\) against \(|\mathbf{a}-\mathbf{b}| = 5\).

04The k-nearest neighbour algorithm

The nearest neighbour algorithm (Kelleher Algorithm 2):

  1. Compute the distance from the query to every instance in memory and find the instance with the shortest distance.
  2. Predict the target level of that nearest neighbour.

With Euclidean distance and \(k = 1\), the feature space is partitioned into a Voronoi tessellation: every training instance owns a Voronoi region, the set of points closer to it than to any other instance. A query is labelled by the region it falls in. Merging neighbouring regions that predict the same level gives the model's decision boundaries. The model is a collection of local models, one per neighbourhood, rather than one global function.

One neighbour makes the prediction sensitive to noise: a single mislabelled instance owns a region and mislabels every query in it. k-NN takes the majority target level among the \(k\) nearest neighbours instead.

Figure 4.1: The data of worked example 4.1. Teal dots are class A, amber squares class B, and the ringed point is the query (4, 4). The circle passes through the k-th nearest neighbour. Slide k from 1 to 7: the plain majority flips from A to B at k = 5, because the larger class takes over. Switch weighting on: each vote counts \(1/\text{dist}^2\), and A wins for every k because its members are closest.

Worked example 4.1 k-NN classification

Training set (\(x_1, x_2\), class): 1 (1, 2) A; 2 (2, 4) A; 3 (3, 3) A; 4 (5, 6) B; 5 (6, 3.5) B; 6 (4, 6.5) B; 7 (6, 5) B. Classify the query \(\mathbf{q} = (4, 4)\) with Euclidean distance for \(k = 1, 3, 5\).

1
Distances: ID 3: \(\sqrt{1+1} = 1.414\); ID 2: \(\sqrt{4+0} = 2.000\); ID 5: \(\sqrt{4+0.25} = 2.062\); ID 4: \(\sqrt{1+4} = 2.236\); ID 7: \(\sqrt{4+1} = 2.236\); ID 6: \(\sqrt{0+6.25} = 2.500\); ID 1: \(\sqrt{9+4} = 3.606\).
2
\(k = 1\): nearest is ID 3 (A). Prediction A.
3
\(k = 3\): IDs 3, 2, 5 = A, A, B. Majority A.
4
\(k = 5\): IDs 3, 2, 5, 4, 7 = A, A, B, B, B. Majority B.
A for \(k = 1\) and \(k = 3\), B for \(k = 5\). The answer changes because each extra neighbour adds a vote, and the extra votes here come from class B.

Choosing k

  • Small k (for example 1): low bias, high variance. The boundary is jagged and follows individual instances, so noise and outliers change predictions (overfitting). Advantage: it captures fine local structure.
  • Large k: smoother boundaries and robustness to noise, but higher bias. Small or minority regions are swallowed by the majority (underfitting). In the extreme, \(k = n\) predicts the majority class of the whole dataset for every query. Large k is also sensitive to class imbalance.

Choose k by validation performance, and use an odd k for two classes to avoid ties.

Weighted voting and k-NN regression

To stop distant neighbours, and a dominant class, from swamping the vote, weight each neighbour's vote by the reciprocal of its squared distance to the query:

Distance-weighted k-NN (Kelleher Eq 5.6)\[ \mathbb{M}_k(\mathbf{q}) = \arg\max_{l \in \text{levels}(t)} \sum_{i=1}^{k} \frac{1}{\text{dist}(\mathbf{q},\mathbf{d}_i)^2} \times \delta(t_i, l) \]
\(\mathbb{M}_k(\mathbf{q})\)
Predicted level for query \(\mathbf{q}\).
\(\mathbf{d}_i\)
The \(i\)-th nearest neighbour.
\(\text{dist}(\mathbf{q},\mathbf{d}_i)\)
Its distance to the query.
\(\delta(t_i, l)\)
1 if the neighbour's target \(t_i\) equals level \(l\), else 0.
Worked example 4.2 Weighted vote

Repeat \(k = 5\) from worked example 4.1 with distance-weighted voting.

1
A votes: ID 3 \(1/1.414^2 = 0.5\); ID 2 \(1/4 = 0.25\). Total 0.75.
2
B votes: ID 5 \(1/4.25 = 0.2353\); IDs 4 and 7 \(1/5 = 0.2\) each. Total 0.6353.
A wins, 0.750 against 0.635: the two A neighbours are closer, so they outweigh three more distant B neighbours.

For a continuous target, k-NN returns the average (or the median) of the k neighbours' targets, or a distance-weighted average \(\sum w_i t_i / \sum w_i\) with \(w_i = 1/\text{dist}_i^2\). The median is more robust when one neighbour has an extreme target value.

Worked example 4.3 k-NN regression

A query's nearest neighbours (distance, target in kWh): (0.4, 210), (0.6, 230), (1.0, 260), (1.6, 330), (2.5, 420). Predict with \(k = 3\) using the mean, the median and the weighted mean.

1
Mean: \((210 + 230 + 260)/3 = 233.3\) kWh. Median of 210, 230, 260: 230 kWh.
2
Weights: \(1/0.4^2 = 6.25\), \(1/0.6^2 = 2.778\), \(1/1.0^2 = 1\). Weighted mean \(= (6.25 \cdot 210 + 2.778 \cdot 230 + 1 \cdot 260)/(6.25 + 2.778 + 1) = 2\,211.4/10.028 = 220.5\) kWh.
233.3 kWh (mean), 230 kWh (median), 220.5 kWh (weighted mean). Weighting pulls the prediction toward the closest neighbour's 210 kWh.

05k-d trees: faster neighbour search

Plain k-NN compares the query with every stored instance: \(n\) distance calculations per prediction. A k-d tree (k-dimensional tree) indexes the instances so that most of them can be ruled out without computing their distances.

Construction: pick a feature (cycling through the features level by level), find its median value, make the instance at the median the node, and split the remaining instances into the two partitions below and above it. Repeat on each partition, stopping when a partition has fewer than two instances.

Search: descend from the root to the leaf region containing the query, taking that leaf as the best guess. Then back up the tree. At each node, check whether the node itself is closer, and whether the distance from the query to the node's splitting line is less than the current best distance. Only if it is can the other side hold a closer point; otherwise that whole branch is skipped.

Figure 5.1: Left: the six points of worked example 5.1 with the splitting lines. The first split is vertical (x = 7), the second-level splits horizontal (y = 4 on the left, y = 6 on the right). Right: the same tree. The query (9, 2), marked ×, falls in the region of (8, 1).

Nearest neighbour (8, 1) at distance 1.414, found with 3 distance calculations instead of 6.

06Preparing data for k-NN

Distance-based models are only as good as the feature space they measure in.

  • Normalise numeric features. Distance adds up raw differences, so a feature with a large range dominates. Age (18 to 80 years) and AnnualIncome (R120 000 to R1 500 000) cannot be compared directly: a difference of R1 000 in income outweighs a 60-year age gap. Range normalisation \(a' = (a - \min)/(\max - \min)\) maps each feature to \([0, 1]\), so each contributes in proportion to its relative difference.
  • Noise and outliers. Distance measures are sensitive to outliers. For small k, an outlier is unlikely to be a neighbour of anything. For large k it can be, but the majority vote limits its effect. Outliers can be in the descriptive features or the target.
  • Missing values. A distance cannot be computed for a missing feature. Options: impute it (mean, median or mode of the feature, Week 3), or compute the distance over the features both instances have and rescale.
  • Class imbalance. As k grows, the majority class dominates. Use distance weighting, or oversample the minority class or undersample the majority.
Worked example 6.1 Range normalisation

Normalise Age = 35 (range 18 to 80) and AnnualIncome = R400 000 (range R120 000 to R1 500 000).

1
Age: \((35 - 18)/(80 - 18) = 17/62 = 0.274\).
2
Income: \((400\,000 - 120\,000)/1\,380\,000 = 0.203\).
(0.274, 0.203): both now on \([0, 1]\), so a unit change in either means "the whole range".

The curse of dimensionality. As the number of features grows, the volume of the feature space grows exponentially, so a fixed training set covers it ever more thinly. Neighbours end up far away, and the distances to the nearest and farthest instances become similar, so "nearest" means little. Irrelevant features add noise to every distance. Hence feature selection: keep the predictive and interacting features, drop the irrelevant and redundant ones.

ApproachHow it worksExamples

07Error-based learning

A parameterised model is defined by a set of parameters (weights). Error-based learning searches for the parameter values that minimise an error function measuring how far the model's predictions are from the true targets in the training set. Training has converged when the error approaches its lower limit (ideally zero).

Parameters and hyper-parameters

Parameters are learned from the training data during training: the weights of a regression model. Hyper-parameters are set before training starts and control how learning happens: the learning rate, the number of epochs, k in k-NN, the maximum depth of a tree.

The sum of squared errors

For a candidate model \(\mathbb{M}_\mathbf{w}\), the residual of instance \(i\) is its actual target minus the prediction. The sum of squared errors (the \(L_2\) loss) adds the squared residuals:

Sum of squared errors (Kelleher Eq 7.4)\[ L_2(\mathbb{M}_\mathbf{w}, \mathcal{D}) = \frac{1}{2}\sum_{i=1}^{n} \left(t_i - \mathbb{M}_\mathbf{w}(\mathbf{d}_i)\right)^2 \]
\(\mathbb{M}_\mathbf{w}\)
The model with weight vector \(\mathbf{w}\).
\(\mathcal{D}\)
Training set of \(n\) instances.
\(t_i\)
Actual target of instance \(i\).
\(\mathbb{M}_\mathbf{w}(\mathbf{d}_i)\)
Predicted target for descriptive features \(\mathbf{d}_i\).
\(\tfrac12\)
Convenience factor that cancels the 2 when differentiating; it does not change which weights are best.

Why square? Residuals can be positive or negative. Summing them raw lets them cancel: a model that is 50 too high on one instance and 50 too low on another has a residual sum of 0. Squaring makes every error count positively, punishes large errors more than small ones, and gives a smooth, differentiable function to minimise. Other losses exist, such as the cross-entropy loss used for classification (Weeks 9 and 10).

Worked example 7.1 Residuals and SSE

Office sizes 400, 550 and 700 m² rent for R230k, R290k and R365k a year. Compare models A: \(\hat{y} = 60 + 0.4x\) and B: \(\hat{y} = 40 + 0.45x\) (in R thousands).

1
A predicts 220, 280, 340. Residuals \(y - \hat{y}\): 10, 10, 25. Squares: 100, 100, 625. Sum: 825.
2
B predicts 220, 287.5, 355. Residuals: 10, 2.5, 10. Squares: 100, 6.25, 100. Sum: 206.25.
SSE: 825 for A, 206.25 for B (in (R thousand)²; halved, \(L_2\) = 412.5 and 103.1). B fits the training data better.

08Batch gradient descent

Every combination of weights gives one value of the error. Plotting error against the weights gives the error surface: for a model with two weights, the two horizontal axes are \(w[0]\) and \(w[1]\), and the height is the SSE. The best model sits at the lowest point.

If the model is a linear combination of the descriptive features and both the model and the error function are differentiable, the SSE error surface is convex: a single bowl with one global minimum and no local minima. At the minimum, the partial derivatives of the error with respect to every weight are zero.

Batch gradient descent finds the minimum iteratively, like walking downhill in fog by always stepping in the steepest downhill direction:

  1. Initialise the weights to a random point in weight space.
  2. For each weight, compute the error delta: the gradient of the error with respect to that weight, summed over all training instances.
  3. Update every weight a small step against the gradient, scaled by the learning rate \(\alpha\). One such pass through the whole dataset is an epoch.
  4. Repeat until convergence: the error stops decreasing meaningfully, or a maximum number of epochs is reached.

"Batch" means the gradient uses the full training set before any update. Each step therefore moves in the true steepest-descent direction of the total error, so the descent is smooth and the update is the same whatever order the instances are in. Week 10 contrasts this with stochastic and mini-batch updates.

Gradient descent update for linear regression (Kelleher Eq 7.14)\[ \mathbf{w}[j] \leftarrow \mathbf{w}[j] + \alpha \underbrace{\sum_{i=1}^{n}\left(t_i - \mathbb{M}_\mathbf{w}(\mathbf{d}_i)\right)\times \mathbf{d}_i[j]}_{\text{errorDelta}(\mathcal{D},\,\mathbf{w}[j])} \]
\(\mathbf{w}[j]\)
Weight \(j\); \(\mathbf{w}[0]\) is the intercept.
\(\alpha\)
Learning rate: the step size (hyper-parameter).
\(t_i - \mathbb{M}_\mathbf{w}(\mathbf{d}_i)\)
Residual of instance \(i\) under the current weights.
\(\mathbf{d}_i[j]\)
Feature \(j\) of instance \(i\); \(\mathbf{d}_i[0] = 1\) (dummy feature for the intercept).
errorDelta
\(-\partial L_2/\partial \mathbf{w}[j]\): the downhill direction for that weight.

The sign is a plus because errorDelta is already the negative gradient. Intuition: if the model under-predicts (positive residual) on instances with a large positive \(\mathbf{d}[j]\), increase \(\mathbf{w}[j]\).

Worked example 8.1 One epoch of batch gradient descent

Data \((x, t)\): (1, 3), (2, 5), (3, 6), (4, 9). Model \(\hat{t} = w_0 + w_1x\), initial \(w_0 = 0.5\), \(w_1 = 1.0\), learning rate \(\alpha = 0.02\). Do one epoch.

1
Predictions: 1.5, 2.5, 3.5, 4.5. Residuals: 1.5, 2.5, 2.5, 4.5. \(L_2 = \tfrac12(2.25 + 6.25 + 6.25 + 20.25) = 17.5\).
2
errorDelta for \(w_0\) (feature 1): \(1.5 + 2.5 + 2.5 + 4.5 = 11\). For \(w_1\): \(1.5(1) + 2.5(2) + 2.5(3) + 4.5(4) = 32\).
3
Update: \(w_0 = 0.5 + 0.02(11) = 0.72\); \(w_1 = 1.0 + 0.02(32) = 1.64\).
4
New predictions 2.36, 4.00, 5.64, 7.28 give \(L_2 = 2.249\).
After one epoch \(w_0 = 0.72\), \(w_1 = 1.64\); the error fell from 17.5 to 2.25. Repeating converges to the least-squares line \(\hat{t} = 1.0 + 1.9x\) with \(L_2 = 0.35\).

The learning rate

  • Too small: tiny steps, so convergence takes very many epochs. Small rates may be needed when features are not normalised, because a large-valued feature makes its gradient huge.
  • Too large: the steps overshoot, jumping from one side of the bowl to the other. The error can oscillate, or grow without limit (diverge), and the minimum is missed.
  • Learning-rate decay starts large, for fast early progress, and shrinks over time, for a stable finish:
Learning-rate decay (Kelleher Eq 7.16)\[ \alpha_\tau = \alpha_0\,\frac{c}{c + \tau} \]
\(\alpha_\tau\)
Learning rate at iteration \(\tau\).
\(\alpha_0\)
Initial learning rate (for example 1).
\(c\)
Constant that controls how fast the rate decays.
\(\tau\)
Current iteration of gradient descent.

With \(\alpha_0 = 1\) and \(c = 20\): \(\alpha = 1\) at \(\tau = 0\), \(0.667\) at \(\tau = 10\), \(0.286\) at \(\tau = 50\) and \(0.167\) at \(\tau = 100\).

09Linear regression

Linear regression predicts a continuous target as a weighted sum of the descriptive features. With one feature it is the equation of a line, with an intercept \(w[0]\) and a gradient \(w[1]\). With several features (multivariable linear regression) each feature gets its own weight, and the model is a plane or hyperplane:

Multivariable linear regression (Kelleher Eq 7.9)\[ \mathbb{M}_\mathbf{w}(\mathbf{d}) = \mathbf{w}[0] + \mathbf{w}[1]\,\mathbf{d}[1] + \cdots + \mathbf{w}[m]\,\mathbf{d}[m] = \sum_{j=0}^{m} \mathbf{w}[j]\,\mathbf{d}[j] = \mathbf{w}\cdot\mathbf{d} \]
\(\mathbf{w}[0]\)
Intercept: the prediction when every feature is zero.
\(\mathbf{w}[j]\)
Weight of feature \(j\): the change in prediction per unit increase in \(\mathbf{d}[j]\), other features held fixed.
\(\mathbf{d}[j]\)
Value of descriptive feature \(j\); \(\mathbf{d}[0] = 1\).
\(m\)
Number of descriptive features.

Each feature needs its own weight because each has its own units and its own effect. One shared weight would force floor number and floor area to change rent by the same amount per unit, which is meaningless. Gradient descent fits all weights at once, with the update of Section 8 applied to every \(j\). The slide example (Kelleher's office rentals: Size, Floor and BroadbandRate) starts from random weights such as \(w[0] = -0.146\), \(w[1] = 0.185\), \(w[2] = -0.044\), \(w[3] = 0.119\) and repeats epochs until the SSE stops falling.

Normalising the features speeds up gradient descent but makes the weights harder to interpret, because they are then "per unit of normalised feature" rather than per m² or per floor.

Categorical descriptive features

Linear regression multiplies features by weights, so features must be numbers. Do not code a categorical feature as arbitrary numbers (A = 1, B = 2, C = 3): that would claim C is "three times" A and that the steps A→B and B→C have equal effects. Instead use one-hot encoding: one binary feature per level, exactly one of which is 1. Each level then gets its own weight.

Key idea

Linear regression is a parametric model whose few weights describe a line or plane. Batch gradient descent is a least-squares optimiser: on the convex SSE surface it reaches the same weights that the closed-form least-squares solution gives.

Problem 10.5 Concepts

(a) Why is the SSE surface of linear regression convex? (b) Why use the full dataset per update in batch gradient descent? (c) What does a learning curve that falls fast and then flattens tell you?

1
(a) The model is linear in the weights, so each residual is linear in the weights and its square is a convex quadratic. A sum of convex functions is convex: one bowl, one global minimum.
2
(b) The full-data gradient is the exact direction of steepest descent of the total error, so each step reliably reduces the error for a suitable \(\alpha\).
3
(c) Big early gains, then convergence. Stop when the improvement per epoch drops below a tolerance.
(a) Linear model plus squared loss gives a convex quadratic. (b) An exact gradient. (c) The model has converged; stop on a small-improvement criterion.

11Formula sheet

Distances

Minkowski: \(\left(\sum_i |a_i - b_i|^p\right)^{1/p}\)

\(p=1\) Manhattan, \(p=2\) Euclidean, \(p=\infty\) Chebyshev \(= \max_i|a_i-b_i|\).

Metric: non-negativity, identity, symmetry, triangle inequality.

Similarity indices

RR \(= CP/|\mathbf{q}|\), SM \(= (CP+CA)/|\mathbf{q}|\)

J \(= CP/(CP+PA+AP)\)

Cosine \(= \mathbf{a}\cdot\mathbf{b}/(|\mathbf{a}||\mathbf{b}|)\)

k-NN

Classification: majority of k nearest. Weighted vote: \(1/\text{dist}^2\).

Regression: mean or median of k targets.

Range normalisation: \((a - \min)/(\max - \min)\).

Error and gradient descent

\(L_2 = \tfrac12\sum_i (t_i - \mathbb{M}_\mathbf{w}(\mathbf{d}_i))^2\)

\(\mathbf{w}[j] \leftarrow \mathbf{w}[j] + \alpha\sum_i (t_i - \mathbb{M}_\mathbf{w}(\mathbf{d}_i))\,\mathbf{d}_i[j]\)

Decay: \(\alpha_\tau = \alpha_0\, c/(c+\tau)\)

Linear regression

\(\mathbb{M}_\mathbf{w}(\mathbf{d}) = \mathbf{w}\cdot\mathbf{d} = \sum_{j=0}^m \mathbf{w}[j]\mathbf{d}[j]\), with \(\mathbf{d}[0] = 1\).

Categorical features: one-hot encode.
