# Instructions for AI contributors

You are working on **notesmaxing**: a static study-notes site for one student's third-year, second-semester
engineering modules. These instructions are everything you need. Read them before changing anything, and
read [NOTES_GUIDE.md](NOTES_GUIDE.md) as well before writing or editing a notes page.

## What the site is

- Plain HTML, CSS and JavaScript. There is no framework, no bundler and no `npm install`.
- `index.html` lists the modules. `module.html?m=<id>` lists one module's notes by week and its past
  papers. Each notes page is a standalone HTML file inside its module's folder.
- `problems.html?m=<id>` is the problem generator. It sends the ticked notes and papers to the AI model,
  shows a staged progress bar, and saves the problems in the browser.
- Every notes page has a chat panel (`assets/ask-gemini.js`). Its AI tutor is called **The Lovely Lady**
  in all visible text. Google Gemini is only named in code and comments.
- Hosting: GitHub `Michael-she/NotesMaxing-Y3S2`, branch `main`. Every push to `main` deploys to Vercel
  (https://notesmaxing-y3s2.vercel.app). `api/chat.js` and `api/health.js` are Vercel edge functions that
  forward requests to Gemini. They read `GEMINI_API_KEY`, `GEMINI_MODEL` and `GEMINI_API_BASE` from
  the environment.

## Layout

```
index.html, module.html, problems.html   the three app pages
modules.json          the modules: id, folder, code, display name
manifest.js           GENERATED by build_manifest.py; never edit by hand
build_manifest.py     scans the module folders and writes manifest.js
ingest.py             files correctly named notes and papers from inbox/ into place
serve_notes.py        local server (pages + the chat API); run_notes.bat launches it on Windows
api/                  Vercel edge functions for the chat panel and the problem generator
assets/site.css       the ONLY stylesheet; every page's look comes from it
assets/site.js        theme, side menu, formula annotations, figure toggles, MathJax settings
assets/ask-gemini.js  the chat panel
NOTES_GUIDE.md        the full spec for writing a notes page (hand it to a model with the slides)
<Module folder>/      notes pages, either directly or in week folders; papers/ holds past papers;
                      exam-prep/ holds practice exam papers with memos (listed as "Exam questions")
```

Modules (from `modules.json`):

How `build_manifest.py` reads the folders:

- **Week:** the first `week<N>` in the path, for example `Week8-Control-Law/` or `week3.html`.
- **Title:** the page's `<h1>`.
- **Track:** a first-level subfolder that is not a week folder.
- **Papers:** PDFs in `papers/`. A four-digit year in the name is used for sorting. `memo`,
  `solution` or `answer` in the name marks a memo.
- **Ignored:** folders starting with `_` or `.`, and files named `index.html`.

## Standing rules

These are the owner's decisions. Do not undo them.

1. **One stylesheet.** No `<style>` blocks, no `style=""` attributes and no colour values in pages. If
   a page needs a new look, add a class to `assets/site.css` that works in both light and dark themes.
   Use the existing tokens (`--genoa`, `--ink`, `--rule`, ...) and SVG classes (`c1`–`c4`, `ln`, `thin`,
   `dash`, `stable`, ...).
2. **No branding and no top menu bar.** Pages link through their own back links. The only shared
   control is the light/dark button that `site.js` adds. Light is the default, whatever the system
   setting; dark only when the reader picks it.
3. **Figure captions are one short sentence.** The longer explanation goes in a `<p class="fignote">`
   directly after the `</figure>`.
4. **Animations play by default** while on screen. They stop for readers who ask for reduced motion.
5. **Formula annotation checkboxes start unticked.**
6. **Ctrl+Enter sends** in every text box that submits something.
7. **Maths** uses MathJax with `\( ... \)` inline and `\[ ... \]` for display. Do not use `$...$`.
8. **Every number in the notes must be correct.** Check worked examples and figure data by calculation,
   for example with Python. Interactive figures compute what they draw from the formulas.
9. **Plain writing:** short sentences, no filler, no marketing tone, units on every answer.

## Common tasks

### Add a notes page or past paper

1. Name the file by the convention in NOTES_GUIDE.md section A2. Examples:
   `CS354_Week08_Notes_Control-Law.html` and `CS354_2026_A1_Memo.pdf`.
2. Put the file in `inbox/`.
3. Run `python ingest.py`. Use `--dry-run` first to preview.

`ingest.py` files each page by its name and fixes the `../` link depth, the back link and the
`data-store` key. It then rebuilds `manifest.js`. Commit the new files together with `manifest.js`.

A page can also be filed by hand, like the existing CS354 pages (`CS354-Control-Systems/WeekN-Topic/`).
Use `../../` paths at that depth, then run `python build_manifest.py`.

### Change an existing page

- Don't change a page's `data-store` value: it is the browser key for that page's saved chat.
- Renaming or moving a page changes its URL, which breaks bookmarks. Rebuild the manifest after any
  rename, and update any text that still names the old week.
- Optional lines on a figure use `.fig-toggles`. Animated figures use `.anim` with `.anim-controls`.
  Interactive figures use `.fig-ctl` sliders, a `.fig-read` readout and `<circle class="hit">` drag
  handles. NOTES_GUIDE.md section A9 has templates for all three. CS354 Week 1, Figures 5.1 to 6.2, is
  a worked example of interactive figures.

### Add an exam paper

Practice exam papers live in `<Module folder>/exam-prep/`, one HTML page per paper, laid out like a notes
page. Give the page `<meta name="exam-scope" content="A1">` (or A2) and
`<meta name="exam-marks" content="80">`; the module page lists it under "Exam questions". Each
question is a `<section>` with its marks in `<span class="mk">[26]</span>` inside the `<h2>`, each part
a `<div class="qp"><b>(a)</b><div>…</div><span class="mk">[6]</span></div>`, and the worked answer
in `<details class="memo">` after the question. Mark formulas that are not on the module's formula
sheet with `<span class="derive">derive</span>`. Verify every number by calculation before adding it.

Memos show the full working, laid out the same way everywhere (see the CS354 pages):

- `<p class="plan"><b>Approach.</b> …</p>`: one or two sentences on the method.
- One `<div class="mp">` per part: `<h4><span class="pt">(a)</span>Title<span class="mk">[6]</span></h4>`,
  then `<ol class="steps">` with one `<li><div>…</div><span class="mt">2</span></li>` per step. The
  `mt` number is the marks that step earns; leave it empty for none. The step marks must add up to
  the part's marks, and the parts to the question's.
- `<div class="ans">` for the boxed result and `<p class="chk"><b>Check.</b> …</p>` for a check
  against simulation. A sketch answer goes in a `<figure>` computed from the transfer function.

In the question bank, add `data-sketch` to a question's `<section>` when it asks for a sketch; the
Type filter then lists it under "sketching".

### Add a module

1. Add a line to `modules.json`.
2. Create the module folder with a `papers/` subfolder.
3. Run `python build_manifest.py`.

### Problem generator

- **Storage:** problems are saved in the browser's `localStorage` under the key `notes-problems`.
- **Record fields:** `id, module, request, level, title, problem, solution, sources, weeks, tokens, created`.
- **Old records:** problems saved before a field existed won't have it. Keep reading such records
  safely; don't break them.
- **Difficulty:** the levels are Fundamental, Basic, Exam and Final boss. Exam is the default.
- **Topic:** optional. When none is given, the model chooses one.

### Usage ledger

The site records who uses it and what the AI costs them, at 750 000 tokens a beer. `usage.html`
shows the reader only their own beer, token and message totals, nothing else. `api/ledger?user=<name>` returns one person's figures. Only for the admin name (`LEDGER_ADMIN`,
default "Michael Shepstone", compared without case or punctuation) does it also return everyone's,
which `usage.html` shows in an "Everyone" section. The full ledger is also on amavadata.

- **Names:** `assets/ledger.js`, loaded by `site.js` on every page, asks a new device for its name the
  first time any page loads. The first attempt to send something to The Lovely Lady shows, once, a notice
  that chatting with her costs beer. Both are remembered in `localStorage` (`notes-user-name`,
  `notes-beer-ok`). Every request to `api/chat` carries the name as
  `user`; it is never forwarded to Gemini.
- **Storage:** the amavadata reporting platform (`https://amavadata.com`), one gateway, two aliases per
  person. After each answer, `api/chat.js` posts the tokens used to `tokens_<name>`. Each page open
  sends a beacon to `api/visit` after the page has loaded and gone idle, which posts 1 to
  `opens_<name>`. `api/ledger` sums one person's readings. All of it is in `api/_ledger.js`, mirrored in
  `serve_notes.py` for local use.
- **Setup:** `AMAVA_BASE` and `AMAVA_GATEWAY` are set in the Vercel project; put them in `.env` to count
  local use too. A failed post never breaks a page or the chat. Show amounts as beers first, tokens in
  brackets (`notesLedger.fmt`).

### Chat API

Don't put the API key, or any other secret, in a file that is committed. `.env` holds it locally and
is git-ignored.

On Vercel, a response must start within about 25 seconds. So `api/chat.js` starts streaming at once,
sends keep-alive comments while it waits, and reports errors as `data: {"error": ...}` events. Keep
that shape if you change it.

## Checking your work

1. Run `python serve_notes.py`, which serves http://localhost:8765. Then open the pages you changed in a
   browser. Without a `.env` key the chat and the generator won't answer, but everything else works.
2. Check the browser console for errors, and check that MathJax rendered: there should be no
   `mjx-merror` elements.
3. Check both themes and a narrow phone-width window. The page must not scroll sideways, except inside
   a figure.
4. After adding or moving notes, open `module.html?m=<id>` and check the weeks are listed in order.
   Reload without the cache if `manifest.js` looks stale.

## Git

- Commit with a plain, specific message that says what changed for the reader, for example
  `CS354 Week 1: Figures 5.1 to 6.2 are interactive`. Push to `main` only if the owner has allowed it
  for your session.
- Never commit course material other than past papers. `.gitignore` already blocks other PDFs, plus
  `.mp4` and `.pptx` files.
- Never commit `inbox/`, `.env` or generated scratch files.
- The repo is edited on Windows. Git's "LF will be replaced by CRLF" warnings are expected and harmless.

## Privacy

Don't put the owner's email address, or any other personal details, in a page, a commit or a request to
an outside service.
