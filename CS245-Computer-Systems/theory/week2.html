Development Board & Memory Architecture

CS245 · Lectures 4–6 · Board hardware, physical memory technologies, memory map

L4STM32F4DISCOVERY Board

  • Target microcontroller: STM32F407VGT6 (LQFP100 package), manufactured by ST Microelectronics.
  • Core: ARM 32-bit Cortex-M4 with a hardware single-precision FPU, running up to 168 MHz.
  • On-chip memory: 1 MB Flash (program memory), 192 KB SRAM (data memory).
  • On-board peripherals:
    • Embedded ST-LINK/V2-A debugger/programmer via Mini-USB (the CN3 jumpers must remain fitted for on-board MCU programming — do not remove them).
    • 3-axis digital MEMS accelerometer (LIS302DL).
    • Omnidirectional digital MEMS microphone (MP45DT02).
    • Audio DAC with integrated Class-D speaker driver (CS43L22).
    • Push-buttons: B1 (blue, User button on PA0), B2 (black, Reset on NRST).
    • Eight LEDs: LD1 (USB comms), LD2 (3.3 V power), LD3 (orange, PD13), LD4 (green, PD12), LD5 (red, PD14), LD6 (blue, PD15), LD7 (VBUS, green), LD8 (over-current, red).
    • Dual 50-pin extension headers exposing all 100 LQFP I/O lines, for prototyping and probing.
    • Flexible power supply: via ST-LINK USB, a second USB port, or an external source (3 V / 5 V application supply options).

Programming happens over USB: the binary program is placed into Flash memory, and the processor begins executing instructions from address 0x0000 0000 (aliased to the start of Flash, 0x0800 0000).

L5Physical Memory Technologies

RAM vs. ROM

  • RAM (Random Access Memory): read/written a byte at a time at roughly equal speed; used for program data (variables); volatile — loses its contents when power is removed.
  • ROM (Read Only Memory): read-only from the program's point of view (reprogramming requires a higher supply voltage or a special procedure); used for program instructions; non-volatile — retains data indefinitely without power.

SRAM vs. DRAM

  • SRAM (Static RAM): stores each bit on a pair of cross-coupled inverters — a bistable flip-flop. "Static" because it needs no refreshing. Fast, low latency, but uses more transistors per bit (6T), so it is lower density than DRAM. Used for embedded MCU internal RAM and CPU caches.
  • DRAM (Dynamic RAM): stores a bit as charge on a capacitor (1 transistor + 1 capacitor per cell). Reading destroys the stored value, so it must be rewritten after every read; the charge also leaks away over time, so the whole array must be refreshed every few milliseconds. Higher density, lower cost — used for "bulk" system memory in PCs.

Historic core memory

Magnetic-core memory used 32 × 32 planar grids of tiny ferrite rings threaded with write/sense wires. Because the cores retain their magnetic state without power, core memory is non-volatile.

ROM family: PROM, EPROM, EEPROM, Flash

  • Mask ROM: contents fixed during chip manufacture — presence or absence of a transistor per bit cell.
  • PROM (Programmable ROM): a transistor is placed in every cell, connected to ground through a fuse; programming blows selected fuses. One-time programmable, since a blown fuse cannot be repaired.
  • EPROM (Erasable PROM): replaces the fuse with a floating-gate transistor whose gate is not physically wired to anything. A sufficiently high voltage tunnels electrons onto the floating gate, turning the transistor on. Erased only by exposing the die to intense ultraviolet light through a quartz window.
  • EEPROM (Electrically Erasable PROM): erased and written electrically, at byte or word granularity, using on-chip charge pumps to generate the higher programming voltage — no UV light needed. Higher endurance, but slower write speeds than Flash.
  • Flash memory: erased in large blocks or sectors at once (erasing resets all bits to 1); write-erase cycles are otherwise similar to EEPROM.

Programmer's summaryA memory cell always stores one bit, whose physical form depends on the technology: SRAM → flip-flop state, DRAM → capacitor charge, Flash → floating-gate transistor charge. Bits are grouped into bytes; computer memory is organised, addressed, and sized in bytes. The system bus lets the CPU access memory (and memory-mapped peripherals) directly; some memory (hard disks, SD cards) is not directly CPU-addressable at all.

L5C Memory Segments & Layout

In the embedded ARM system used in this module, memory is split across Flash (non-volatile, base 0x0800 0000, aliased to 0x0000 0000) and SRAM (volatile, base 0x2000 0000). Program (instruction) memory is normally only read, never written to at run time; data memory is altered by the running program and holds variables.

How does code end up in the 0x0000 0000–0x1FFF FFFF range and data end up at 0x2000 0000 onward? The linker combines all object files into the executable and places each section at the address the linker script specifies; the debugger/programmer then copies the resulting binary image into non-volatile Flash memory. See the Programming notes for this week for the linker-script mechanics.

L6The Stack (Concept)

  • The stack is a region of volatile memory (RAM) used to pass parameters and save state across function calls and interrupts, managed by the Stack Pointer (SP) register.
  • It is a last-in-first-out (LIFO) structure — like a stack of dishes, the most recently added item is the first one removed. The "top of stack" is the most recently allocated location.
  • ARM Cortex-M uses a Full Descending (FD) stack:
    • Full: SP points at the last occupied address (not the next free slot).
    • Descending: the stack grows from high addresses toward low addresses as items are pushed.
  • What ends up on the stack: function arguments that don't fit in R0–R3; the callee-saved registers R4–R8, R10, R11 (and SP) if a function needs to reuse them as scratch space; local variables that don't fit in available registers; and the processor state (e.g. LR) that must be preserved across a nested function call or interrupt.

The exact push/pop mechanics and the ARM instructions that manipulate the stack (PUSH/POP, STM/LDM, and the AAPCS calling convention) are covered in this week's Programming notes, since they are primarily assembly-programming knowledge.
