Serial communication: UART and I2C

Why devices talk one bit at a time, how synchronisation and direction are handled, and how the two most common links work: the asynchronous point-to-point UART and the synchronous two-wire I2C bus. Includes the STM32F407 USART flags and baud rate register, and the I2C transaction sequence bit by bit.

01Serial communication

Reading Lecture 16, slides 5 to 20

Serial communication sends data one bit at a time over one channel, usually a wire or a PCB track. The voltage on the line changes over time to carry the bits. At its simplest one device, the transmitter (TX), drives the line and another, the receiver (RX), senses it.

Start from GPIO: a pin set as an output on device 1 drives a 0 or 1, a pin set as an input on device 2 (through its Schmitt trigger) senses it. Wire the two together and one bit passes. Change the output over time and many bits pass. Two questions follow: how does device 2 know when the next bit is valid (synchronisation), and how does it reply (direction)?

ParallelSerial
LinesMany, several bits at one instantOne, bits one after another
Speed for the same clockFasterSlower
CostMore wires, pins and cableFewer

Synchronous and asynchronous

Synchronisation is how the receiver finds where each bit starts and ends in the stream.

  • Synchronous: a separate clock line tells the receiver when to read the next bit. Simple and fast, but needs one more wire.
  • Asynchronous: no clock. The receiver works it out from the agreed bit rate, the transitions in the data and special markers (start and stop bits). Only one signal, but more complex hardware and lower speeds.

Figure 1.1: Top: the receiver samples data (teal) on each clock edge (dashed amber lines), so the bit rate can change freely. Bottom: there is no clock, so the line idles high, a low start bit marks the beginning and the receiver times each bit from the agreed rate until the high stop bit.

Direction, buses and contention

TermMeaning
SimplexOne direction only.
Half-duplexBoth directions, one at a time.
Full-duplexBoth directions at the same time.
Point-to-pointTwo devices on a dedicated channel.
BusOne channel shared by several devices.

Option 1 uses two signals, one each way: a full-duplex point-to-point link. Signals are labelled TX and RX, but relative to which device? Check the datasheet. A common ground is also needed as the voltage reference.

Figure 1.2: Each device's TX goes to the other's RX, so both can send at once. Without the ground wire the two devices have no shared 0 V and the levels mean nothing.

Option 2 uses one wire and swaps each device between input and output whenever the direction changes. This extends to a bus with many devices. One device, the master, controls synchronisation and the slaves only talk when the master allows it.

Watch out: bus contention

Bus contention is two devices using the bus at the same time. If both pins are push-pull outputs and one drives 3.3 V while the other drives 0 V, the only resistance between the rails is the on-resistance of the output MOSFETs (\(R \approx 0\)), so \(I = V/R\) is very large and the GPIO port is damaged. A bus scheme must make this impossible (I2C does it with open-drain outputs, section 5).

Dedicated hardware

Doing serial communication in software with GPIO means constant writes to port registers, timers and interrupts. At 1 Mbps that is one million interrupts per second; with a 10 MHz clock and one instruction per cycle the ISR has only 10 instructions. So microcontrollers have dedicated hardware that handles the low-level work (synchronisation, timing, data format, signal levels) and interrupts the CPU only at a higher level, for example when a byte has arrived or a transmission has ended. DMA (Week 8) can remove the CPU from the transfer completely.

Both ends must follow the same rules, which is why interfaces are standardised: UART, I2C, SPI, CAN, Ethernet, SATA, USB. The first three are built into most microcontrollers.

Exam

02UART

Reading Lecture 17, slides 3 to 5

A UART is asynchronous (no clock) and connects exactly two devices in a full-duplex point-to-point link. It uses three signals: TX, RX and ground. Microcontroller levels are 0 V for logic 0 and 3.3 V or 5 V for logic 1.

Both ends must use the same bit rate, the baud rate, within a tolerance given in the datasheet. Standard rates include 1200, 9600, 19 200 and 115 200 bps.

The UART frame

The line idles high. Each byte is sent as a frame:

  1. a start bit (low), whose falling edge tells the receiver a frame has begun;
  2. the data bits, usually 8 (configurable), least significant bit first;
  3. an optional parity bit, even or odd;
  4. one or two stop bits (high).

The settings are written as data bits, parity, stop bits: 8N1 is 8 data bits, no parity, 1 stop bit, the common configuration. With even parity the parity bit makes the total number of 1s (data plus parity) even; with odd parity, odd.

Figure 2.1: 0x43 is 0100 0011 in binary. Sent LSB first the data bits are b0 to b7 = 1, 1, 0, 0, 0, 0, 1, 0. The byte has three 1s, so even parity adds a 1 to make four. The stop bit returns the line to idle.

Frame length and data rate\[ n_{frame} = 1 + n_{data} + n_{parity} + n_{stop} \qquad \text{byte rate} = \frac{\text{baud rate}}{n_{frame}} \]
\(n_{frame}\)

\(n_{data}\)
Data bits per frame (usually 8).

8N1 sends 10 bits to carry 8, so 115 200 bps gives 11 520 bytes per second, an efficiency of 80 %.

Worked example 2.1 a GPS sentence

A GNSS receiver outputs a 70-character NMEA sentence at its default 9600 baud, 8N1. How long does it take to arrive? How many bytes per second would 8E1 give?

1
8N1: \(n_{frame} = 1 + 8 + 0 + 1 = 10\) bits per character.
2
\(t = 70 \times 10 / 9600 = 72.9\) ms.
3
8E1: \(n_{frame} = 11\), byte rate \(= 9600/11 = 872.7\) B/s (73 % efficient), against 960 B/s for 8N1.
72.9 ms per sentence. At a 10 Hz update rate (ten sentences a second) 9600 baud is not enough, which is why receivers are reconfigured to higher baud rates.

Hardware flow control adds two signals from the modem interface: CTS (Clear To Send) blocks transmission at the end of the current frame, and RTS (Request To Send) says the UART is ready to receive. A USART (Universal Synchronous Asynchronous Receiver/Transmitter) can also output a clock, if wanted.

03USART on the STM32F407

Reading Lecture 17, slides 6 to 13

As with every peripheral, the USART is used through memory-mapped registers. Transmit and receive each use a shift register behind the data register.

RegisterPurpose
USART_SRStatus register: the flags TXE, TC, RXNE, ORE and others.
USART_DRData register: write to send, read to receive.
USART_BRRBaud rate register: holds USARTDIV.
USART_CRxConfiguration registers: word length, parity, stop bits, enables, interrupt enables.

Transmission: TXE and TC

  1. Software writes a frame to DR.
  2. The hardware moves it into the transmit shift register and sets TXE (Transmit data register Empty): DR may now take the next frame, even though the first is still being shifted out.
  3. Software writes the next frame to DR, which clears TXE. That frame waits in DR until the shift register is empty, then moves across and TXE goes high again.
  4. When the last frame has fully left the shift register and nothing is waiting in DR (TXE still set), TC (Transmission Complete) goes high.

Figure 3.1: TXE (amber) drops when a frame is written and rises as soon as DR is copied into the shift register, so the next write can happen while the current frame is on the line. TC (ink) only rises after the final stop bit. Wait for TXE before writing more data; wait for TC before switching off the USART or turning an RS-485 driver round.

Watch out

Slide 8 says to "clear the TXE flag in software". On the STM32F407 TXE is cleared by the write to USART_DR itself; there is no separate clear step. The effect is the same: writing the next frame is what clears it.

Reception: oversampling and RXNE

The receiver oversamples the line at 8× or 16× the baud rate. This rejects noise and tolerates a small mismatch between the two clocks. The start bit is detected from the oversampled signal, then the following bits are clocked into the receive shift register.

  • When a whole frame is in, it is copied to DR and RXNE (Receive data register Not Empty) goes high.
  • Software reading DR clears RXNE.
  • If another frame finishes while RXNE is still high, the old one has not been read: an overrun error sets ORE.

Baud rate register

The same baud rate is used for transmit and receive, set by USARTDIV in USART_BRR. The clock \(f_{ck}\) for USART1 and USART6 comes from APB2; for USART2 it comes from APB1.

USART baud rate\[ \text{Baud rate} = \frac{f_{ck}}{8 \times \text{USARTDIV}} \;(8\times \text{ oversampling}) \qquad \text{Baud rate} = \frac{f_{ck}}{16 \times \text{USARTDIV}} \;(16\times) \]
Baud rate
Bits per second on the line (bps).
\(f_{ck}\)
Peripheral clock of the USART, from APB1 or APB2 (Hz).
USARTDIV
Unsigned fixed-point divider in USART_BRR. With 16× oversampling: a 12-bit integer part (mantissa) and a 4-bit fraction in sixteenths.
Worked example 3.1 BRR for 115 200 baud

USART1 runs from APB2 at \(f_{ck} = 84\) MHz with 16× oversampling. Find BRR for 115 200 baud and the error.

1
\(\text{USARTDIV} = 84 \times 10^6 / (16 \times 115\,200) = 45.573\).
2
Mantissa 45 = 0x2D. Fraction \(0.573 \times 16 = 9.17\), rounded to 9.
3
BRR = (45 << 4) | 9 = 0x2D9, so USARTDIV = 45 + 9/16 = 45.5625.
4
Actual rate \(= 84 \times 10^6 / (16 \times 45.5625) = 115\,226\) bps, an error of +0.02 %.
BRR = 0x2D9, giving 115 226 bps (+0.02 %), well inside UART tolerance.

04UART applications and standards

Reading Lecture 17, slides 14 to 21

GNSS (GPS) receivers do the whole job of receiving satellites and computing position, velocity and time, and send periodic NMEA messages over UART (the Adafruit v3 module: 9600 baud by default, 1 to 10 Hz update). The microcontroller can also reconfigure the receiver. GSM (cellular) modems send data or SMSs over the cellular network for IoT applications, with a complicated command protocol over UART.

StandardSignallingCable lengthNotes
RS-232Single-ended, ±12 V for noise immunity15 m1960s, DTE (terminal) to DCE (modem). Needs a driver IC. DB9 or DB25 connectors.
RS-422Differential: Tx+, Tx− and Rx+, Rx−1200 mDriver IC; two twisted pairs.
RS-485Differential, one data channelnot given on the slideDriver IC; many devices on one twisted pair because transmitters can be tri-stated. You write your own addressing protocol.

RS-232 was a standard PC port (a COM port in Windows, a TTY device in Linux) and was replaced by USB, so USB-to-RS-232 cables exist for legacy hardware. Development kits now either route a UART through the embedded ST-Link programmer (STM32 Nucleo) or use a USB-UART bridge IC (FTDI FT23x, Silicon Labs CP210x). The STM32F407 Discovery board instead runs a USB stack and appears as a Virtual COM Port, but only once its firmware is running. On the PC side the port is used through a terminal emulator; the course uses Termite and Tera Term.

05I2C

Reading Lecture 18

I2C (Inter-Integrated Circuit) is a bidirectional two-wire bus for control between ICs, developed by Philips (now NXP) and used in over 1000 ICs. The wires are the serial clock SCL and serial data SDA. It is half-duplex, a bus, and synchronous.

ModeUp to
Standard-mode100 kbit/s
Fast-mode400 kbit/s
Fast-mode Plus1 Mbit/s
High-speed mode3.4 Mbit/s

Several masters are allowed, but normally there is one. Only the master drives SCL. Any device may change the level of the bus lines, so contention must be prevented.

Open-drain bus

SCL and SDA use open-drain outputs: the p-MOS of the output stage is never switched on. Writing 0 turns the n-MOS on and pulls the pin to 0 V; writing 1 turns it off and leaves the pin floating. A pull-up resistor on each line pulls it high when nobody is pulling it low.

Figure 5.1: Each device can only connect the line to ground. If one device "outputs 1" (transistor off) while another outputs 0, the line is simply low and the current is limited by \(R_p\): no short circuit is possible. The line is a wired-AND: it is high only if every device releases it. Choosing \(R_p\) is a trade-off covered in Week 11.

Start, stop, address and ACK

Data goes in bytes (8 bits per frame), most significant bit first, and any number of bytes may follow. SDA may only change while SCL is low; a change while SCL is high is a control condition:

  • START: SDA goes high to low while SCL is high.
  • STOP: SDA goes low to high while SCL is high.

Only the controller (master) generates START and STOP. The bus is busy after a START and free again a short time after a STOP.

Figure 5.2: In the shaded windows SCL (ink) is high and SDA (teal) changes, which never happens during normal data bits. That is how every slave recognises the start and end of a transaction.

Addressing: every slave has a unique address, usually 7 bits (\(2^7 = 128\) addresses), sometimes 10 bits (\(2^{10} = 1024\)). After START the master sends the address and one R/W bit: 0 for a master write (send to the slave), 1 for a master read (the slave returns data).

Acknowledge: after every byte comes a ninth clock pulse, generated by the master. The transmitter releases SDA and the receiver pulls it low and holds it low while SCL is high: that is an ACK (byte received, send another). If SDA stays high on the ninth pulse, that is a NACK.

Watch out

UART sends LSB first; I2C sends MSB first. And on I2C the address byte is the 7-bit address shifted left with R/W in bit 0: address 0x68 gives 0xD0 for a write and 0xD1 for a read. The STM32 HAL functions expect this shifted form (0x68 << 1).

Master write and master read

StepMaster write: masterSlave
1Keep SCL high, pull SDA low: STARTAll slaves detect START
2Send 7 clocks with the slave address on SDAAll slaves read the address
3Output the write bit (0)All slaves read R/W
4Release SDA and sense ACKMatching slave pulls SDA low (ACK)
5Send 8 clocks with 8 data bitsMatching slave reads the data
6Release SDA and sense ACKMatching slave ACKs
7Release SCL, then SDA: STOPAll slaves detect STOP

A master read starts the same way but with R/W = 1. In step 5 the master still clocks, but the slave drives the 8 data bits and the master senses them. In step 6 the master answers: ACK to ask for another byte, NACK when it is done. Then STOP.

Figure 5.3: The address 0x68 = 110 1000 goes out MSB first, then W = 0. The slave answers ACK (low) on the ninth clock. The data byte 0x6B = 0110 1011 follows, then a second ACK and the STOP. One byte of payload costs 18 clock periods plus START and STOP.

Repeated start and clock stretching

  • Repeated START: the master issues a new START without a STOP, to run several transactions (read or write) without releasing the bus. Typical use: write a register address, then repeated START and read from it.
  • Clock stretching: after an address or data byte the master releases SCL, and a slave that needs time (to answer a read, or to service an internal interrupt) holds SCL low. The master must wait until SCL is released.

The hardware handles START and STOP detection, address matching, read and write transfers and ACK/NACK. What the bytes mean is up to software and the IC maker: high-level commands, reading or writing a register at an internal address, or bulk reads and writes of consecutive registers. In STM32CubeMX the pins and mode are configured graphically, and the HAL driver offers blocking, interrupt and DMA versions of each transfer. A logic analyser that decodes I2C is the most useful debugging tool.

Worked example 5.1 reading six sensor registers

A master at 400 kHz reads 6 bytes starting at register 0x3B of the slave at address 0x68: START, address+W, register address, repeated START, address+R, 6 data bytes, STOP. Find the address bytes and the number of clock pulses, and estimate the time.

1
Address bytes: write \(0x68 \ll 1 = \) 0xD0; read 0xD1.
2
Bytes on the bus: address+W, 0x3B, address+R and 6 data: 9 bytes, each 8 bits plus an ACK/NACK: \(9 \times 9 = 81\) clocks.
3
\(t \approx 81 / 400\,000 = 202.5\) µs, plus the START, repeated START and STOP.
0xD0 and 0xD1, 81 clock pulses, about 203 µs. The master ACKs the first five data bytes and NACKs the sixth.

06Practice problems

Problem 6.1 an exact baud rate

USART2 is clocked from APB1 at 42 MHz with 16× oversampling. Find BRR for 9600 baud and the error.

1
USARTDIV \(= 42 \times 10^6/(16 \times 9600) = 273.4375\).
2
Mantissa 273 = 0x111; fraction \(0.4375 \times 16 = 7\) exactly.
BRR = 0x1117, exactly 9600 bps (0 % error).
Problem 6.2 a coarser divider

Same USART2 (42 MHz, 16×), now at 115 200 baud.

1
USARTDIV \(= 42 \times 10^6/(16 \times 115\,200) = 22.786\); fraction \(0.786 \times 16 = 12.58 \to 13\).
2
BRR = (22 << 4) | 13 = 0x16D; actual \(42 \times 10^6/(16 \times 22.8125) = 115\,068\) bps.
0x16D, 115 068 bps, −0.11 %. Smaller USARTDIV values give coarser steps and bigger errors.
Problem 6.3 decoding a frame

A UART in 8E1 receives, after the start bit: 1, 1, 0, 0, 0, 0, 1, 0, then 1, then 1. What byte arrived and is the parity correct?

1
The first eight are b0 to b7 (LSB first): b7…b0 = 0100 0011 = 0x43, the ASCII letter 'C'.
2
Data has three 1s; with the parity bit (1) there are four: even, so correct. The last 1 is the stop bit.
0x43 ('C'), parity good.
Problem 6.4 bit-banging versus hardware

A 168 MHz core bit-bangs a 115 200 bps UART with one timer interrupt per bit. How many clock cycles are available per bit, and what is the byte rate in 8N1?

1
\(168 \times 10^6/115\,200 = 1458\) cycles per bit, all spent waiting for or servicing interrupts.
2
Byte rate \(= 115\,200/10 = 11\,520\) B/s.
About 1458 cycles per bit and 11 520 B/s; the USART hardware gives the same rate with one interrupt per byte (RXNE or TXE) instead of ten per byte.
Problem 6.5 I2C register write

At 400 kHz, write the value 0x00 to register 0x6B of slave 0x68. List the bytes and estimate the time.

1
START, 0xD0 (ACK), 0x6B (ACK), 0x00 (ACK), STOP.
2
\(3 \times 9 = 27\) clocks: \(27/400\,000 = 67.5\) µs plus START and STOP.
0xD0, 0x6B, 0x00; about 67.5 µs.
