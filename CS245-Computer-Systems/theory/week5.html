COMPUTER SYSTEMS 245 · THEORY · WEEK 5

Timers, Counters & Clocks

CS245 · Lectures 12–14 · Timer/counter principles, PWM, SysTick, watchdogs, RTC, clock sources & PLLs

01Timer/Counter Operating Principles

Embedded systems routinely need to measure elapsed time and count the occurrence of events — a microwave oven, for instance, needs one timer to track time-of-day, another to time the cook cycle, another to pulse the turntable motor, and a fourth to control power level by switching the magnetron on for only a fraction of each second.

  • Hardware counter: a register (TIMx_CNT) that increments or decrements on every transition of an input signal.
  • Timer mode: the input is an internal, periodic clock of known frequency — used to measure elapsed time or trigger actions with controlled timing.
  • Counter mode: the input is an external, asynchronous signal (e.g. an optical encoder or flow meter) — used to count the number of physical events.

Key registers: TIMx_CNT (current count, 16- or 32-bit — wider registers give a greater counting range before wraparound), TIMx_PSC (16-bit prescaler, dividing the input clock by any factor from 1 to 65536), TIMx_ARR (auto-reload register, defining the counting ceiling), and up to four TIMx_CCRx capture/compare registers per timer. Most timers have 4 independent channels, usable for output compare, input capture, PWM generation, or one-pulse output. Interrupts can be generated on update (overflow/underflow/reset), trigger, output-compare, input-capture, and break-input events.

02Counter Modes

  • Upcounting: counts 0 → TIMx_ARR, then resets to 0, generating an Update Event (UEV) and setting the Update Interrupt Flag (UIF).
  • Downcounting: counts TIMx_ARR → 0, then reloads TIMx_ARR and generates a UEV.
  • Center-aligned (up/down): counts 0 → ARR−1 (overflow UEV), then ARR → 1 (underflow UEV), then restarts from 0. Effective period = 2 × ARR × clock period.

03Output Compare & Input Capture

  • Output compare: the counter is continuously compared against TIMx_CCRx; on a match, an output pin's logic level changes (set, clear, or toggle) — without requiring the CPU to be interrupted at all. Used to generate output waveforms, or simply to mark that a period of time has elapsed. Can also raise an interrupt if enabled.
  • Input capture: the timer free-runs on a known clock; when a configured edge is detected on the corresponding input-capture (ICx) signal, the current counter value is latched into TIMx_CCRx. This measures the time between edges of an external signal, without CPU polling. Extra features include programmable edge sensitivity (rising/falling/both), an event prescaler (capture every 1/2/4/8 events, reducing CPU load for high-frequency signals), and a 4-bit digital noise/debounce filter (able to reject glitches up to 15 sampling periods after the active edge).

Typical uses of counter mode: an LMT01 temperature sensor outputs a number of pulses within a fixed time window that varies with temperature; an optical encoder outputs pulses at a rate proportional to rotation speed. Both are read by feeding the pulse train into a timer/counter's external input.

04Pulse-Width Modulation (PWM)

PWM generates a square wave with a programmable pulse width (duty cycle), which — after low-pass filtering, or simply as perceived by an LED/motor — behaves like a varying average DC voltage. Frequency is set by TIMx_ARR; duty cycle is set by TIMx_CCRx. The generated signal is called OCxREF.

Upcounting (CNT < CCR)Downcounting (CNT > CCR)
PWM Mode 1OCxREF = 1OCxREF = 0
PWM Mode 2OCxREF = 0OCxREF = 1

In edge-aligned Mode 1, OCxREF is high as long as TIMx_CNT < TIMx_CCRx; if the compare value exceeds the auto-reload value, OCxREF is simply held at 1 (100% duty). PWM can also be generated in center-aligned mode, active whenever the CMS bits in TIMx_CR1 are non-zero.

One-pulse mode

Generates a single pulse of programmable length in response to an external trigger event. CCR1 defines when the pulse starts (optionally after a delay from the trigger), and ARR defines when it ends — the effective pulse width is ARR − CCR1.

05SysTick, Watchdogs & RTC

SysTick timer

A 24-bit downcounter built into the Cortex-M4 core itself (dedicated primarily to RTOS use, but usable as a plain downcounter), with autoreload and maskable interrupt-on-zero. It is normally configured (in HAL_Init()) as a 1 ms tick that simply increments a counter variable on every interrupt; HAL_Delay() spins in a loop waiting for that counter to advance by the requested amount.

Critical ruleNever call HAL_Delay() from inside an interrupt handler unless SysTick has been given a strictly higher preemption priority than that handler — otherwise SysTick can never fire to advance the count, and the system deadlocks.

Watchdog timers

A watchdog timer (WDT) automatically resets the system if the main program fails to periodically "kick" (service) it — typically used to recover an embedded device that has hung due to a software or hardware fault. It counts down from a reload value; reaching zero triggers a reset. As long as the software is healthy and keeps kicking the watchdog on schedule, the counter never reaches zero.

Real-Time Clock (RTC)

An independent BCD (binary-coded decimal) calendar timer/counter, tracking seconds, minutes, hours (12/24-hour), weekday, date, month, and year — with automatic leap-year and month-length compensation. Provides a programmable alarm and periodic interrupts, and can wake the device from Stop/Standby low-power modes. Normally clocked by an external 32.768 kHz crystal (LSE), though it can fall back to the internal RC oscillator (less accurate) or the HSE divided by 128. It defaults to generating a 1-second time base from the 32.768 kHz source, and continues running across Run mode, low-power modes, and reset, as long as supply voltage stays in range.

06Clock Sources

Every microcontroller needs a clock input, used by the CPU, memory, bus, and peripherals — it governs instruction execution rate, serial communication rate, and analog-to-digital sampling rate. Microcontrollers implement sequential logic (their output depends on input history, not just present inputs), and every logic gate has a finite propagation delay; the time between clock pulses must be long enough for all gate outputs to settle before the next pulse, or the circuit's behaviour becomes unreliable.

SourceTypical frequencyTrade-off
HSI — High-Speed Internal RC oscillator16 MHzFactory-trimmed to ±1% at 25 °C. Low cost, instant startup, but drifts with temperature and has manufacturing-tolerance imprecision.
LSI — Low-Speed Internal RC oscillator≈32 kHzDrives the watchdog and basic sleep timing; same drift/imprecision trade-off as HSI.

LSE — Low-Speed External crystal32.768 kHzFeeds the RTC; same stability advantage as HSE.

An RC oscillator's imprecision comes from manufacturing tolerance in the resistor/capacitor values (which directly set the resonant frequency) and thermal drift in those same values. A crystal oscillator instead uses the mechanical (piezoelectric) resonance of a vibrating quartz crystal — deformed by an applied electric field (electrostriction), and generating its own field as it springs back — which is far more stable, though it still needs external circuitry to amplify and feed back the crystal's output.

Frequency error (ppm)

Oscillator accuracy is specified in parts-per-million (ppm):

Δf = f₀ × (ppm / 10⁶)
Δf
Frequency error in Hz.
f₀
Nominal frequency of the clock source.
ppm
Tolerance in parts per million.
10⁶

Example: a 32.768 kHz crystal rated ±20 ppm gives Δf = 32,768 × 20 / 1,000,000 ≈ ±0.65536 Hz — the clock may drift by up to ≈20 seconds per million seconds, roughly 52 seconds over a month.

07Phase-Locked Loop (PLL) & Clock Distribution

Quartz crystals cannot physically resonate at hundreds of MHz, so a Phase-Locked Loop (PLL) multiplies a lower crystal (or RC) frequency up to the CPU's operating frequency (168 MHz on this board). A PLL consists of a phase-frequency detector, a charge pump, a low-pass loop filter, a voltage-controlled oscillator (VCO), and feedback frequency dividers (÷M, ×N, ÷P, ÷Q). The VCO output is fed back to the phase detector, forming a negative-feedback loop: if the output phase drifts, the resulting error signal drives the VCO in the opposite direction, locking the output phase to a fixed relationship with the input.

Adding a frequency divider (successive divide-by-2 counters, using D flip-flops) in the feedback path makes the PLL lock to a frequency N times higher than the reference input — one flip-flop divides by 2, two flip-flops divide by 4, and so on.

Clock distribution ("clock tree")

Clock signals fan out to the CPU, memory, and every peripheral, typically through multiplexers that select the source and dividers/multipliers that scale it. The primary clock is the system clock (SYSCLK), sourced from HSI, HSE, or the main PLL (itself driven by HSI or HSE). Secondary clocks — LSI and LSE — independently drive the watchdog and RTC. Each clock source can be independently switched off when unused, to save power. On reset, the 16 MHz HSI is always selected by default; software can then switch to HSE or the PLL, with automatic fallback to HSI (plus an optional interrupt) if the selected external clock fails.

Prescalers configure the two AHB buses and the two APB domains independently: APB2 is the high-speed peripheral bus, APB1 the low-speed one. On this board, SYSCLK/AHB can reach 168 MHz, APB2 up to 84 MHz, and APB1 up to 42 MHz (see the AMBA bus diagram in Week 4).

Higher clock speed means faster transistor switching, which means higher power consumption and higher operating temperature — this is why modern microcontrollers allow individual peripheral clocks to be gated off, and support various low-power sleep states with wake-up capability.
