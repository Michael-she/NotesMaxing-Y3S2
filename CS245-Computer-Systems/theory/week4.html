COMPUTER SYSTEMS 245 · THEORY · WEEK 4

Interrupts, Exceptions & the System Bus

CS245 · Lectures 9–11 · Exception model, NVIC, bus architecture, Von Neumann vs. Harvard

01Interrupts vs. Exceptions

  • Polling: continuously checking a peripheral status register in a software loop. Simple, but wastes CPU cycles and risks missing a short-lived event entirely if the CPU happens to be busy elsewhere when it occurs.
  • Interrupts (asynchronous, external events): raised by hardware peripherals — a GPIO edge, a timer overflow, a UART byte arriving — to divert CPU execution immediately to an Interrupt Service Routine (ISR). Interrupts and exceptions generally behave like an unscheduled function call that branches to a new address, used to respond to an event as quickly as possible; they can be triggered by hardware or software.
  • Exceptions (synchronous, internal events): triggered by the CPU itself, due to an error or a software service call — an undefined instruction, an out-of-bounds memory access (data/prefetch abort), a divide by zero, an SVC call.
Polling Approach (Inefficient):
[ Main Task Execution ] ---> [ Check Pin ] ---> [ Main Task Execution ] (Event missed if short!)

Interrupt Approach (Efficient & Instant):
[ Main Task Execution ] ======================> [ Main Task Continues ]
         |                                             ^
         +---> (Hardware Trigger) ---> [ Execute ISR ]-+

Four questions any interrupt-driven design must answer: how does the processor know which handler to run, and where to find it; how is the interrupted program protected from having its registers/flags disturbed; which interrupt wins if several occur simultaneously; and how do you prevent an interrupt firing during a critical section of code? (These map directly onto the vector table, automatic register stacking, NVIC priorities, and interrupt masking, respectively — covered below.)

02The Vector Table & EXTI

When an exception occurs, the processor does not execute an explicit branch instruction — it automatically loads a new value into the PC, looked up from the vector table: a table of 32-bit handler start addresses placed at the very beginning of Flash (addresses 0x0000–0x03FC). On reset, the CPU reads two values from it — the initial Main Stack Pointer at 0x0000 0000, and the Reset handler's address at 0x0000 0004. Selected entries:

  • 0x0000 0000: initial MSP value.
  • 0x0000 0004: Reset handler entry point.
  • 0x0000 0008: Non-Maskable Interrupt (NMI) handler.
  • 0x0000 000C: HardFault handler.
  • 0x0000 0058: EXTI Line 0 handler (the User Button on PA0, in this module's examples).

At the end of the handler, execution must return to the instruction after the one interrupted, so the program resumes as if the exception were just a momentary "glitch".

External Interrupt/event Controller (EXTI)

The STM32F407 provides up to 23 EXTI edge detectors, which generate an interrupt or event request on an external asynchronous signal. Each line is independently configurable for interrupt vs. event, and for rising/falling/both-edge triggering.

Because many GPIO pins can share one EXTI line number, a multiplexer (controlled by the SYSCFG_EXTICR1–4 registers) selects which port feeds each EXTI line — e.g. EXTI0 can be routed from PA0, PB0, PC0, or PD0. (For the User Button on PA0: SYSCFG_EXTICR1 bits 3:0 = 0000, selecting Port A.)

03Cortex-M4 Exception Entry & Return

When the processor accepts an exception:

  1. Automatic stacking: the hardware pushes eight data words — the stack frame (32 bytes) — onto the stack currently in use.
  2. Vector fetch: in parallel, the CPU fetches the handler's start address from the vector table.
  3. EXC_RETURN generation: a special "magic" value (e.g. 0xFFFFFFF9 or 0xFFFFFFFD) is written into LR, encoding which stack was in use and what mode the CPU was in.
  4. Mode switch: execution moves to Handler mode — always privileged, and always using the Main Stack Pointer (MSP).

Cortex-M4 has two execution modes — Thread mode (normal program execution, returns to after a handler finishes) and Handler mode (exception handler execution) — and two privilege levels: Unprivileged/User (restricted access to certain instructions and resources) and Privileged (full access; always used for interrupts). There are also two stack pointers, MSP and PSP, both accessed as R13 — relevant mainly when running an RTOS.

Returning from an exception

Exception return happens when, in Handler mode, the CPU executes LDM, POP, or LDR with PC as the destination, or BX, with one of the EXC_RETURN values loaded into PC — this is exactly what BX LR does inside the handler, since LR was set to EXC_RETURN on entry (LR does not hold a literal return address; the real return address was saved in the stack frame). The processor then automatically restores the pre-exception mode, pops the stack frame back into the original registers — including PC, which resumes the interrupted code exactly where it left off — and program execution continues.

Aside — how a single core "multitasks"A single-core processor executes small slices of each task in turn (time-slicing), switching context when a timer expires or the running task blocks waiting on something. Saving/restoring registers and memory-map state during this context switch is computationally expensive, which is a major reason OS design spends so much effort minimising and optimising it.

04The NVIC

Older microcontrollers OR every interrupt line together onto a single request line, forcing the CPU to poll each peripheral to find the source. A modern interrupt controller combines multiple sources, lets priorities be assigned so the CPU always switches to the most appropriate ISR, and reports the interrupt source directly. A Vectored Interrupt Controller (VIC) goes further and supplies the handler address itself. On the Cortex-M4 this is tightly integrated into the core as the Nested Vectored Interrupt Controller (NVIC), connected via a dedicated bus, so the processor can select and dispatch the correct handler with no software polling required.

For the STM32F407, the NVIC supports:

  • 52 maskable interrupt channels.
  • A programmable priority level of 0–15 per interrupt — a lower number means higher priority (level 0 is highest).
  • Level and pulse detection of interrupt signals, and dynamic reprioritisation.
  • Grouping of priority values into group-priority and subpriority fields.
  • Tail-chaining: if another exception is already pending when a handler finishes, the stack pop/push pair between them is skipped entirely and control passes straight to the next handler — taking only ~6 clock cycles.
  • An external Non-Maskable Interrupt (NMI) — the highest-priority exception other than reset, with a fixed priority of −2. It is permanently enabled and cannot be masked or pre-empted by anything else.

05Bus Concepts & Address Decoding

A bus is a communication system transferring data between components inside a computer (or between computers) — a generic term covering both serial communication (a single line, varied over time to carry multiple bits) and parallel communication (several lines, each carrying a bit at the same instant).

The system bus — connecting the CPU, memory, and peripherals — is a parallel bus carrying:

  • Address bus — unidirectional, driven by the bus master, selecting a memory address or I/O register.
  • Data bus — bidirectional, carrying the actual data words.
  • Control bus — read/write strobes, byte enables, clock, and interrupt signals.

A tri-state buffer is a digital buffer whose output can be electronically disconnected (high-impedance, Hi-Z) as well as driven high or low. This lets several devices share the same physical wires without contention — a binary decoder enables only one device's buffer at a time.

A binary address decoder (e.g. 3-to-8) examines the most-significant address bits to assert exactly one chip-select/enable signal at a time (e.g. Flash-enable, SRAM-enable, Peripheral-enable), so only the addressed device's tri-state buffer ever drives the shared data bus.

06Von Neumann vs. Harvard Architecture

  • Von Neumann: a single, unified bus serves both instruction fetches and data transfers, so the two must be scheduled — they cannot both happen in the same cycle. This creates a memory-access bottleneck.
  • Harvard: physically separate instruction and data buses (with independent address spaces) allow simultaneous instruction fetch and data load/store. A bridge is needed between the two buses if the program itself needs to be modified programmatically.

The ARM Cortex-M4 is a Harvard architecture, with three separate AHB interfaces: an I-Code bus (instruction fetch from code memory), a D-Code bus (data/literal access to code memory), and a System bus (access to RAM and peripherals) — plus a Private Peripheral Bus (PPB) for the core's own configuration registers.

07AMBA: AHB & APB

The Advanced Microcontroller Bus Architecture (AMBA), introduced by ARM in 1996, is an open standard for connecting on-chip components and has become the de facto standard for embedded microcontrollers.

  • AHB (Advanced High-performance Bus): a high-throughput, synchronous, pipelined 32-bit bus. AHB-Lite is a simplified single-master version. Unlike older shared-databus architectures where every slave drives the bus through its own tri-state driver, AHB uses point-to-point links from each slave into a read multiplexer — this lets the bus run faster and avoids the power waste of one slave's driver turning on before another's has turned off. The master issues an address in one cycle, and the data phase completes in the next, allowing transfers to pipeline (address of the next transfer can be sent while the current one is still completing).
  • APB (Advanced Peripheral Bus): a lower-speed, lower-power bus for standard peripherals, connected to AHB via AHB-to-APB bridge(s).

GPIO is connected via the AHB1 bus.
