Q1receive_byte[6]

Build a calculator on the emulator UART. Input is an ASCII string (-)<num1>[+,-,x,/]<num2>=: an optional minus for num1, two whole numbers 0 to 9999, one operator and a final =. On = the program replies with the integer result and \n; divide by zero\n for division by 0; invalid input\n for anything else. It must repeat for every =. Examples: -123+456= → 333, 12+34= → 46, 15/16= → 0, 123/0= → divide by zero, 1234567x9876543= → invalid input.

process_input(buffer, &num1, &num2, &opcode) is given (opcode 1 +, 2 −, 3 ×, 4 ÷; returns 1 if the input is valid). The main loop calls receive_byte for each character and, on =, process_input and then calc_result. The two functions may not use globals or HAL calls.

Implement uint8_t receive_byte(uint8_t* inputbuffer, uint8_t* ptr_writepos, uint8_t rxbyte): if the write position is below 11, store the byte there and increment the position; return 1 if the byte is '=', else 0.

Memo for question 1

Approach. The write position lives in the caller, so it is changed through the pointer. The limit check protects the 11-byte buffer.

Code[6]

  1. uint8_t receive_byte(uint8_t* inputbuffer, uint8_t* ptr_writepos, uint8_t rxbyte)
{
    if (*ptr_writepos < 11)
    {
        inputbuffer[*ptr_writepos] = rxbyte;
        (*ptr_writepos)++;          /* brackets: increment the value, not the pointer */
    }
    if (rxbyte == '=')
        return 1;
    return 0;
}
    6
Watch out

*ptr_writepos++ without brackets increments the pointer and leaves the position unchanged. The attempt left the template empty and scored 0.

Q2calc_result[5]

Implement int32_t calc_result(int16_t num1, int16_t num2, uint8_t opcode): 1 add, 2 subtract, 3 multiply, 4 divide; any other opcode returns 0.

Memo for question 2

Approach. A switch on the opcode. Cast to 32 bits before the arithmetic so 9999 × 9999 fits.

Code[5]

  1. int32_t calc_result(int16_t num1, int16_t num2, uint8_t opcode)
{
    switch (opcode)
    {
        case 1: return (int32_t)num1 + num2;
        case 2: return (int32_t)num1 - num2;
        case 3: return (int32_t)num1 * num2;
        case 4: if (num2 == 0) return 0;      /* main replies 'divide by zero' */
                return (int32_t)num1 / num2;  /* C truncates towards zero */
        default: return 0;
    }
}
    5
Run with the given process_input: -123+456= gives 333, 15/16= gives 0, -1234x9876= gives -12186984
Watch out

The paper's example -1234*9876= uses *, but the operator set and process_input only accept x. With the given code that input gives invalid input; the product −12 186 984 needs -1234x9876=.

Q58 MHz crystal, 100 MHz chip[3]

The STM32F411 Discovery has only an 8 MHz oscillator, but the packaging says it runs at 100 MHz. Is this a mistake? Explain.

Memo for question 5

Approach. The system clock is generated on chip from the crystal.

Answer[3]

  1. Not a mistake.

    1

  2. The 8 MHz HSE crystal is the reference for the on-chip phase-locked loop (PLL).

    1

  3. The PLL divides it by M and multiplies it by N, then divides by P, to make SYSCLK up to 100 MHz (for example 8 / 8 × 400 / 4 = 100 MHz).

    1
Not a mistake: the PLL multiplies the 8 MHz clock up to 100 MHz

Q6Why both SRAM and Flash[4]

SRAM is much faster than Flash. If cost were no factor, why does the STM32F411 still have both, and what is mainly stored in each?

Memo for question 6

Approach. Volatility, not speed, decides.

Answer[4]

  1. SRAM is volatile: it loses its contents when power is removed.

    1

  2. The program must survive power-off, so it needs non-volatile Flash.

    1

  3. Flash holds the program code, the vector table and constant data.

    1

  4. SRAM holds what changes at run time: variables, the stack and the heap.

    1

Q8Recovering from an infinite loop[3]

An ISR accidentally enters an infinite loop. Which STM32F411 feature can recover, and how does it work?

Memo for question 8

Approach. Name it, then describe the counter and the refresh.

Answer[3]

  1. The watchdog timer (independent IWDG or window WWDG).

    1

  2. It is a down-counter running from its own clock; the program must refresh ("kick") it regularly, which reloads the count.

    1

  3. If the code hangs, the refresh stops, the counter reaches zero and the watchdog resets the microcontroller.

    1
Watchdog timer
Watch out

The attempt also wrote NVIC. The NVIC manages interrupts; it cannot recover from a hung ISR.

Q9Lighthouse PWM[8]

A lighthouse flashes for 0.5 s every 4 s (off 3.5 s, on 0.5 s). Use TIM2 in PWM mode 1, centre-aligned. In each case find the missing value.

(a)
PSC = 999, ARR = 32000, CCR = 4000. Clock frequency (MHz)?
(2)
(b)
Clock = 90 MHz, ARR = 36000, CCR = 4500. PSC?
(2)
(c)
Clock = 55 MHz, PSC = 4999, CCR = 2750. ARR?
(2)
(d)
Clock = 68 MHz, PSC = 4999, ARR = 27200. CCR?
(2)
Centre-aligned PWM, mode 1\[ T = \frac{2\,ARR\,(PSC + 1)}{f_{clk}}, \qquad D = \frac{CCR}{ARR} \]
\(T\)
PWM period; the counter runs up to ARR and back down (s).
\(ARR\)
Auto-reload value.
\(PSC\)
Prescaler value.
\(f_{clk}\)
Timer input clock (Hz).
\(D\)
Duty cycle: OCxREF is active while CNT is below CCR.
\(CCR\)
Compare value.
Memo for question 9

Approach. T = 4 s and D = 0.5 / 4 = 0.125 in every case.

(a)Clock[2]

  1. \(f_{clk} = 2 \times 32\,000 \times 1000 / 4 = 16 \times 10^6\) Hz.

    1

  2. Check: 4000 / 32 000 = 0.125.

    1
16 MHz

(b)PSC[2]

  1. \(PSC + 1 = 4 \times 90 \times 10^6 / (2 \times 36\,000) = 5000\).

    1

  2. Subtract one.

    1
TIM2_PSC = 4999

(c)ARR[2]

  1. \(ARR = 4 \times 55 \times 10^6 / (2 \times 5000) = 22\,000\).

    1

  2. Check: 2750 / 22 000 = 0.125.

    1
TIM2_ARR = 22000

(d)CCR[2]

  1. Period check: \(2 \times 27\,200 \times 5000 / (68 \times 10^6) = 4\) s.

    1

  2. \(CCR = 0.125 \times 27\,200 = 3400\).

    1
TIM2_CCR = 3400
Watch out

The attempt entered 0.016 MHz, PSC = 2498.9 (or 5000) and ARR = 10999. The notes beside it have the right idea: centre-aligned counting doubles the period, and PSC and the +1 must be handled exactly.

Q10Reading a UART waveform[6]

A UART signal (no parity, 8 data bits, 1 stop bit) is plotted with a grid; one grid division is marked 7.81 µs. Reading the plot, the line is high (idle) for two divisions, then: low 1, high 2, low 4, high 1, low 1, high 1, low 3, high 1, low 3, high 1, low 1, then high.

(a)
Determine the closest standard baud rate.
(2)
(b)
Which two ASCII characters are sent?
(4)
Memo for question 10

Approach. One division is one bit. Each frame is a low start bit, 8 data bits LSB first, and a high stop bit.

(a)Baud rate[2]

  1. \(1 / 7.81\ \mu\text{s} = 128\,041\) bit/s.

    1

  2. The closest standard rate is 115 200 baud.

    1
115 200 baud

(b)Characters[4]

  1. Frame 1 after the start bit: 1 1 0 0 0 0 1 0, then stop. LSB first, so the byte is 0100 0011 = 0x43.

    2

  2. Frame 2: 0 0 1 0 0 0 1 0, then stop: 0100 0100 = 0x44.

    2
"C" then "D"
Watch out

The attempt gave 4800 baud and "A", "Z". 4800 baud would be a bit time of 208 µs, far from 7.81 µs.
