2021 Assessment 3, with a memo

The 2021 A3 SunLearn quiz (80 marks), retyped from attempt reviews: the IDE and toolchain, an assembly function with planted errors, an empty descending stack, BSRR and ODR, where things live in memory, peripherals, centre-aligned PWM, an emulator program built from GPIO, DMA and timer pieces, and the smart meter block diagram. Answer each question before you open its memo.

Q3Empty descending stack[6]

Drag the snippets into place to implement an empty descending stack with a global stackPointer.

void push( int dataValue )
{
    [ ]
    [ ]
}

void pop( int *dataLocation )
{
    [ ]
    [ ]
}
Memo for question 3

Approach. Descending: the stack grows towards lower addresses. Empty: the pointer points at the next free slot, so push writes first and then moves; pop moves back first and then reads.

Push[3]

  1. void push( int dataValue )
{
    *stackPointer = dataValue;
    stackPointer--;
}
    3

Pop[3]

  1. void pop( int *dataLocation )
{
    stackPointer++;
    *dataLocation = *stackPointer;
}
    3
Watch out

Decrement first and then write is a full descending stack (the ARM stack, where SP points at the last item). The attempt and its notes used that order and were marked wrong for this empty stack.

Q5Flash or SRAM[7]

For the STM32F411, is each of these placed in Flash or SRAM? (negative marking)

  1. Vector table
  2. Stack
  3. Interrupt handler function
  4. static const int array1[2] = {1,2};
  5. int array1[2] = {1,2};
  6. The constant PI in #define PI 3.14159 … float angle = i*PI/10.0f;
  7. A global variable
Memo for question 5

Approach. Code and anything read-only goes to Flash (non-volatile). Anything the program changes at run time must be in SRAM.

Placement[7]

  1. Vector table: Flash, at address 0 so the core finds it at reset.

    1

  2. Stack: SRAM; it is written all the time.

    1

  3. Interrupt handler: Flash; it is code.

    1

  4. static const array: Flash; it can never change.

    1

  5. int array1[2] = {1,2};: SRAM. The initial values are stored in Flash and copied to SRAM by the start-up code.

    1

  6. PI: Flash. The preprocessor pastes the number into the code, so it ends up as a constant in the instruction stream or literal pool.

    1

  7. Global variable: SRAM.

    1
Flash, SRAM, Flash, Flash, SRAM, Flash, SRAM

Q6Lighthouse PWM[8]

A lighthouse flashes for 1 s every 4 s (off 3 s, on 1 s). Use TIM2 in PWM mode 2, centre-aligned. In each case three of the clock frequency, TIM2_PSC, TIM2_ARR and TIM2_CCR are given; find the fourth.

(a)
PSC = 9999, ARR = 3000, CCR = 2250. Clock frequency (MHz)?
(2)
(b)
Clock = 90 MHz, ARR = 36000, CCR = 27000. PSC?
(2)
(c)
Clock = 55 MHz, PSC = 4999, CCR = 16500. ARR?
(2)
(d)
Clock = 68 MHz, PSC = 4999, ARR = 27200. CCR?
(2)
Memo for question 6

Approach. Centre-aligned period \(T = 2\,ARR\,(PSC + 1)/f_{clk} = 4\) s. Mode 2 is active while CNT > CCR, so the on fraction is \((ARR - CCR)/ARR = 0.25\) and \(CCR = 0.75\,ARR\).

(a)Clock[2]

  1. \(f_{clk} = 2 \times 3000 \times 10\,000 / 4\).

    1

  2. = 15 000 000 Hz. Check: 2250 = 0.75 × 3000.

    1
15 MHz

(b)PSC[2]

  1. \(PSC + 1 = 4 \times 90 \times 10^6 / (2 \times 36\,000) = 5000\).

    1

  2. Subtract one.

    1
TIM2_PSC = 4999

(c)ARR[2]

  1. \(ARR = 4 \times 55 \times 10^6 / (2 \times 5000) = 22\,000\).

    1

  2. Check: 16 500 = 0.75 × 22 000.

    1
TIM2_ARR = 22000

(d)CCR[2]

  1. Period check: \(2 \times 27\,200 \times 5000 / (68 \times 10^6) = 4\) s.

    1

  2. \(CCR = 0.75 \times 27\,200 = 20\,400\).

    1
TIM2_CCR = 20400
Watch out

The attempt gave PSC = 9999 for (b): it left out the factor 2 of centre-aligned counting. In mode 1 the light would be on while CNT < CCR and CCR would be 0.25 ARR instead.

Q8Emulator program and register values[2]

Questions 8 to 16 build a program on the STM32F4 emulator from a template. Buttons 1 to 4 (PA0 to PA3, EXTI on the rising edge) turn on the matching LED (PD12 to PD15) and fill the screen with a colour; after a time the LED turns off and the screen goes black. A new press restarts the timer.

ButtonLEDColour indexTime active
11 (green, PD12)2500 ms
22 (orange, PD13)421 s
33 (red, PD14)42 s
44 (blue, PD15)14 s

Template set-up: PD12 to PD15 GPIO outputs; PA0 to PA3 EXTI inputs; TIM2 on the 16 MHz internal clock with prescaler 15999 and its interrupt on; DMA2 stream 0 memory-to-memory, word transfers, destination incrementing, source fixed. setstate calls setleds, fillscreen and the timer start/stop functions, which you write.

()
Given this set-up (other pins at reset), give all eight hex digits of GPIOA_MODER and GPIOD_MODER.
(2)
Memo for question 8

Approach. MODER has two bits per pin: 00 input, 01 output, 10 alternate function, 11 analog. Start from the reset value and change only the configured pins.

MODER values[2]

  1. GPIOA: PA0 to PA3 as EXTI are inputs (00), the same as their reset value, so GPIOA_MODER keeps its reset value. RM0383 (STM32F411) gives 0x0C00 0000 for port A.

    1

  2. GPIOD: PD12 to PD15 are outputs, 01 in bit pairs 24 to 31: 0101 0101 in the top byte.

    1
GPIOA_MODER = 0x0C000000, GPIOD_MODER = 0x55000000
Watch out

The A2 attempt changed its first answer (0x0C000000) to 0x00000000, and the A3 attempt entered the port base addresses. The STM32F407 manual (RM0090) gives 0xA800 0000 for port A, because PA13 to PA15 start as debug pins. Either way, bits 7 to 0 are 0.

Q9Register #define[3]

Complete #define GPIOD_ODR *( (uint32_t*) 0x________ ) so that uint32_t ledstate = GPIOD_ODR; and GPIOD_ODR = 0x1000; work.

Memo for question 9

Approach. Port D base plus the ODR offset; the leading * dereferences the cast pointer so the name reads and writes the register.

Address[3]

  1. GPIOD base = 0x4002 0C00.

    1

  2. ODR offset = 0x14.

    1

  3. 0x4002 0C00 + 0x14 = 0x4002 0C14.

    1
#define GPIOD_ODR *((uint32_t*) 0x40020C14)
Watch out

0x40020C00 (the A3 attempt) is MODER, not ODR. In real code add volatile: *((volatile uint32_t*)0x40020C14).

Q10setleds[4]

Write void setleds(int state): state 0 turns all LEDs off; state 1 to 4 turns on only that LED. Use GPIOD_ODR; no HAL, no BSRR and no ODR in the struct. Keep the other port D pins unchanged.

Memo for question 10

Approach. Clear the four LED bits with a mask, then set the one bit for the state, in one read-modify-write.

Code[4]

  1. void setleds(int state)
{
    uint32_t v = GPIOD_ODR & ~(0xFu << 12);   /* PD12..PD15 off, others kept */
    if (state >= 1 && state <= 4)
        v |= 1u << (11 + state);               /* LED1 = PD12 ... LED4 = PD15 */
    GPIOD_ODR = v;
}
    4
Watch out

The attempt read the buttons (GPIOA->IDR) inside setleds and used if (state = 1), which assigns instead of comparing. setleds must depend only on state.

Q11fillscreen with DMA[5]

Write void fillscreen(int state): put the colour for the state into the global src_fill and start the memory-to-memory DMA (hdma_memtomem_dma2_stream0) with HAL_DMA_Start_IT. The destination is the start of the screen and the number of transfers is the number of pixels divided by four.

Memo for question 11

Approach. Each transfer is one 32-bit word = four 8-bit pixels, so put the colour index in all four bytes of src_fill. The source address stays fixed and the destination increments.

Code[5]

  1. Colour per state: 0 → 0 (black), 1 → 2, 2 → 42, 3 → 4, 4 → 1. Multiplying by 0x01010101 copies the byte into all four bytes.

    2
  2. void fillscreen(int state)
{
    static const uint8_t colour[5] = {0, 2, 42, 4, 1};
    if (state < 0 || state > 4) state = 0;
    src_fill = colour[state] * 0x01010101u;
    HAL_DMA_Start_IT(&hdma_memtomem_dma2_stream0,
                     (uint32_t)&src_fill,          /* source: fixed */
                     SCREEN_ADDR,                  /* destination: screen start */
                     SCREEN_PIXELS / 4);           /* 64000 / 4 = 16000 words */
}
    3
Watch out

The screen's start address comes from the emulator template, which is not in the sources, so it is written SCREEN_ADDR here. The 64 000 pixels (320 × 200, one byte each) follow from the transfer lengths in Question 12.

Q15starttimer and stoptimer[5]

Write void starttimer(int state), which sets htim2.Instance->ARR for the state's time and starts TIM2 with its interrupt (HAL_TIM_Base_Start_IT), and void stoptimer(), which stops it (HAL_TIM_Base_Stop_IT).

Memo for question 15

Approach. One count is 1 ms, and the interrupt comes ARR + 1 counts after the counter starts at 0, so ARR = time in ms − 1.

Reload values[2]

  1. 500 ms → 499, 1 s → 999, 2 s → 1999, 4 s → 3999.

    2

Code[3]

  1. void starttimer(int state)
{
    static const uint32_t ms[5] = {0, 500, 1000, 2000, 4000};
    if (state < 1 || state > 4) return;
    HAL_TIM_Base_Stop_IT(&htim2);              /* a new press restarts the time */
    htim2.Instance->ARR = ms[state] - 1;
    htim2.Instance->CNT = 0;
    __HAL_TIM_CLEAR_FLAG(&htim2, TIM_FLAG_UPDATE);  /* no stale interrupt */
    HAL_TIM_Base_Start_IT(&htim2);
}

void stoptimer()
{
    HAL_TIM_Base_Stop_IT(&htim2);
}
    3
