00Instructions

  1. A SunLearn quiz: 3 hours, 90 marks. True/false items carry negative marks.
  2. Questions 1 to 3 are missing from the source copy; the 2025 paper's Questions 1 to 3 (board facts, a bit-pattern function, BSRR and ODR) show the likely style.

Q4Timer auto-reload

The timer input clock is 10 MHz and TIMx_PSC = 999. What must TIMx_ARR be for an interrupt every 0.5 s?

Timer period (revision lecture)\[ f_{timer} = \frac{f_{clk}}{PSC + 1}, \qquad T = \frac{ARR + 1}{f_{timer}} \]
\(f_{timer}\)
Counter clock after the prescaler (Hz).
\(f_{clk}\)
Timer input clock (Hz).
\(PSC\)
Value in TIMx_PSC.
\(T\)
Interrupt interval when counting up from 0 to ARR (s).
\(ARR\)
Value in TIMx_ARR.
Memo for question 4

Approach. Counter clock, then counts per interval, minus one.

ARR

  1. \(f_{timer} = 10\ \text{MHz} / 1000 = 10\ \text{kHz}\).

  2. Counts in 0.5 s: \(0.5 \times 10\,000 = 5000\), so \(ARR = 5000 - 1\).

TIMx_ARR = 4999
Watch out

The student memo also lists ARR = 2500 from \(T = 2\,ARR / f_{timer}\). That formula is for centre-aligned mode, where the counter goes up and back down. The question describes a plain up-counting interrupt, so 4999 is the answer.

Q8Speed ranking

Arrange the serial standards (SPI, I2C, UART) from fastest to slowest possible throughput.

Memo for question 8

Approach. Compare typical maximum rates.

Ranking

  1. SPI: push-pull lines, no address or ACK overhead, tens of Mbit/s.

  2. I2C: up to 3.4 Mbit/s (high-speed mode), usually 100 or 400 kbit/s.

  3. UART: standard rates up to 115 200 bit/s here, with framing bits on every byte.

SPI → I2C → UART

Q9UART 4800-8-N-2

A UART COM port is set to 4800-8-N-2.

(a)
What is the baud rate?
(b)
How many parity bits are in a frame?
(c)
How many start bits are in a frame?
(d)
How many stop bits are in a frame?
(e)
What is the data throughput in bytes per second?
Memo for question 9

Approach. The notation is baud-data bits-parity-stop bits. Every frame also has one start bit.

(a)Baud rate

  1. The first number.

4800 baud

(b)Parity bits

  1. N means no parity.

0

(c)Start bits

  1. A UART frame always has one start bit.

1

(d)Stop bits

  1. The last number.

2

(e)Throughput

  1. Bits per frame: 1 + 8 + 0 + 2 = 11.

  2. \(4800 / 11 = 436.36\) bytes/s.

436.36 bytes/s

Q11SD card over SPI

A microcontroller must read and write an SD card over SPI. Which SPI controller signal goes to each SD pin?

SD pins: CS (pin 1, shown as SC), CMD, VSS1, VDD, CLK, VSS2, DAT0, DAT1, DAT2. Options: GPIO, MOSI, MISO, SCLK.

Memo for question 11

Approach. In SPI mode the card's CMD pin is its data input, DAT0 its data output and pin 1 its chip select.

Connections

  1. CS (pin 1) ← GPIO: the master drives chip select from an ordinary output pin.

  2. CMD ← MOSI.

  3. DAT0 → MISO.

  4. CLK ← SCLK.

  5. VSS1, VSS2 and VDD are power; DAT1 and DAT2 are unused in SPI mode.

GPIO → CS, MOSI → CMD, MISO → DAT0, SCLK → CLK

Q12LIS3DSH driver

Fix LIS3DSH_Init and LIS3DSH_ReadXYZ; the symptom is that it does not work. The chip select is PE3.

void LIS3DSH_Init(void)
{
    HAL_StatusTypeDef res;
    uint8_t TxBuf[10] = {0};
    TxBuf[0] = 0x20 | 0x80;
    TxBuf[1] = 0x13;
    res = HAL_SPI_Transmit(&hspi1, TxBuf, 2, 100);
}

void LIS3DSH_ReadXYZ(int16_t *pData){
    HAL_StatusTypeDef res;
    uint8_t TxBuf[10] = {0};
    uint8_t RxBuf[10] = {0};
    TxBuf[0] = 0x18 ;
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_SET);
    res = HAL_SPI_Transmit(&hspi1, RxBuf, 1, 100);
    res = HAL_SPI_Receive(&hspi1, TxBuf, 3, 100);
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_RESET);
    pData[0] = RxBuf[0];
    pData[1] = RxBuf[2];
    pData[2] = RxBuf[4];
}
Memo for question 12

Approach. Same driver as 2025 Question 13. First byte = register address, bit 7 = 1 to read. CS (PE3) is active low for the whole transfer. CTRL_REG4 (0x20) = ODR[3:0] BDU Zen Yen Xen. Outputs: OUT_X_L at 0x28 to OUT_Z_H at 0x2D, low byte first.

Errors

  1. Init: 0x20 | 0x80 is a read; write with 0x20.

  2. Init: 0x13 sets ODR = 3.125 Hz with Z disabled. Use ODR for the rate asked plus 0x07 for all three axes (50 Hz → 0x57, 100 Hz → 0x67).

  3. Init: CS is never pulled low.

  4. Read: register 0x18 is wrong and the read bit is missing; use 0x28 | 0x80.

  5. Read: CS levels are swapped, the Tx and Rx buffers are swapped, and 3 bytes are read where 6 are needed.

  6. Read: each axis is two bytes, low byte first; combine them into a 16-bit value.

Corrected code

  1. void LIS3DSH_Init(void)
{
    HAL_StatusTypeDef res;
    uint8_t TxBuf[10] = {0};
    TxBuf[0] = 0x20;              /* CTRL_REG4, write */
    TxBuf[1] = 0x67;              /* ODR 100 Hz, X Y Z enabled (0x57 for 50 Hz) */
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_RESET);
    res = HAL_SPI_Transmit(&hspi1, TxBuf, 2, 100);
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_SET);
}

void LIS3DSH_ReadXYZ(int16_t *pData){
    HAL_StatusTypeDef res;
    uint8_t TxBuf[10] = {0};
    uint8_t RxBuf[10] = {0};
    TxBuf[0] = 0x28 | 0x80;       /* OUT_X_L, read */
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_RESET);
    res = HAL_SPI_Transmit(&hspi1, TxBuf, 1, 100);
    res = HAL_SPI_Receive(&hspi1, RxBuf, 6, 100);
    HAL_GPIO_WritePin(GPIOE, GPIO_PIN_3, GPIO_PIN_SET);
    pData[0] = (int16_t)((RxBuf[1] << 8) | RxBuf[0]);
    pData[1] = (int16_t)((RxBuf[3] << 8) | RxBuf[2]);
    pData[2] = (int16_t)((RxBuf[5] << 8) | RxBuf[4]);
}
Watch out

The retyped 2024 paper leaves out the required output data rate. The student memo uses 0x67 (100 Hz); the 2025 version of the question asks for 50 Hz (0x57). Use the rate your paper states. The student memo's *((int16_t*)(RxBuf+2)) casts give the same values on the little-endian Cortex-M4; the shifts above do not depend on byte order or alignment.

Q13I2C facts

(a)
Pull-up resistors are required on which signals?
(b)
I2C is a full-duplex bus. (True/False)
(c)
Clock stretching speeds up transaction throughput. (True/False)
(d)
Which of 10 Ω, 100 Ω, 10 kΩ or 100 kΩ is a good first choice for the pull-ups?
Memo for question 13

Approach. I2C uses two open-drain lines shared by every device.

Answers

  1. (a) SDA and SCL: open-drain outputs can only pull low, so each line needs a pull-up.

  2. (b) False. One data line, so it is half-duplex.

  3. (c) False. A slave holds SCL low to make the master wait; it slows the transfer down.

  4. (d) 10 kΩ. 10 Ω and 100 Ω draw more than an I/O pin can sink; 100 kΩ makes the rise time too slow.

SDA and SCL; False; False; 10 kΩ

Q14Minimum pull-up

For an I/O drive strength of 6 mA and \(V_{DD}\) = 3.3 V, calculate the minimum pull-up resistor (Ω) for an I2C bus.

Minimum pull-up\[ R_{P(min)} = \frac{V_{DD} - V_{OL(max)}}{I_{OL}} \]
\(R_{P(min)}\)
Smallest allowed pull-up (Ω).
\(V_{DD}\)
Supply (V).
\(V_{OL(max)}\)
Guaranteed low output level at that current (V).
\(I_{OL}\)
Sink current of the pin (A).
Memo for question 14

Approach. The pin must sink the full pull-up current while holding the line at or below \(V_{OL(max)}\).

Rp(min)

  1. \(V_{OL(max)}\) = 0.4 V from the STM32F407 datasheet output table.

  2. \(R_{P(min)} = (3.3 - 0.4) / 0.006 = 483.3\ \Omega\).

483.33 Ω
Watch out

The second set of handwritten answers took \(V_{OL} = 0\) ("not specified, assume zero") and got 550 Ω. The student memo, ticked, uses 0.4 V and gets 483.33 Ω, which matches the formula and the datasheet.

Q15ADC resolution

For a 0 to 10 V ADC, choose the minimum resolution for a quantisation error of less than 1 mV.

Memo for question 15

Approach. A rounding ADC has a maximum quantisation error of half an LSB.

Resolution

  1. \(\tfrac{1}{2}\,\text{LSB} = \dfrac{10}{2 \cdot 2^N} \lt 0.001\) gives \(2^N \gt 5000\).

  2. \(N \gt \log_2 5000 = 12.29\), so N = 13.

13 bits
Watch out

The two student answers disagree. The memo sets the error equal to a full LSB (\(10 / (2^N - 1) \lt 0.001\), N = 13.29) and gets 14 bits; the other set uses half an LSB and gets 13 bits. Quantisation error is ±½ LSB for a converter that rounds, so 13 bits. If your lecturer defines it as one full LSB (a truncating converter), the answer becomes 14 bits.

Q16ADC conversion result

For a 0 to 10 V 16-bit ADC, calculate the conversion result for a 1.1011 V DC input.

Ideal ADC (revision lecture)\[ R = (2^N - 1)\,\frac{V_{IN} - V_{REF-}}{V_{REF+} - V_{REF-}} \]
\(R\)
Digital result.
\(N\)
Resolution (bits).
\(V_{IN}\)
Input voltage (V).
\(V_{REF-}\)
Lower reference (V).
\(V_{REF+}\)
Upper reference (V).
Memo for question 16

Approach. Use the ideal ADC line and round to a whole code.

Result

  1. \(R = 65\,535 \times 1.1011 / 10 = 7216.06\).

  2. Round to the nearest code.

7216

Q188-bit conversion time

In the STM32F407 ADC, how many clock cycles are needed for an 8-bit conversion?

Memo for question 18

Approach. The reference manual gives total conversion time = sampling time + one cycle per bit.

Cycles

  1. Minimum sampling time: 3 ADCCLK cycles.

  2. 8-bit successive approximation: 8 cycles.

  3. \(3 + 8 = 11\) cycles (12-bit takes 15, 10-bit 13, 6-bit 9).

11 cycles

True or False: for a SAR ADC, the conversion result is decoded instantly.

Memo for question 19

Approach. How a SAR works.

Answer

  1. A SAR finds one bit per clock with a binary search; only a Flash ADC decodes in one step.

False

Q20DAC output

For a 0 to 5 V 12-bit DAC, calculate the analog output for the digital value 0xF7. Round to 4 decimal places.

Memo for question 20

Approach. Hex to decimal, then the ideal DAC line \(V_{OUT} = R\,V_{REF} / (2^N - 1)\).

Output

  1. 0xF7 = 247.

  2. \(V_{OUT} = 247 \times 5 / 4095 = 0.30159\) V.

0.3016 V

Q24Assembly: read PA0

Write the assembly function readUserPin to read PA0 on the STM32F4DISCOVERY. C prototype: uint32_t readUserPin(); Use only the input data register; initialisation is done.

Memo for question 24

Approach. GPIOA_IDR is at 0x4002 0000 + 0x10. Return in R0.

Code

  1. readUserPin:
    ldr  r1, =0x40020010    @ GPIOA_IDR
    ldr  r2, [r1]
    and  r0, r2, #1         @ PA0 only
    bx   lr
