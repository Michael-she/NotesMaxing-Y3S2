01C Standard Types, Strings & sizeof

Fixed-width types & booleans

  • Fixed-width types (<stdint.h>): portable type definitions that guarantee a platform-independent size — uint8_t, int16_t, uint32_t, etc. Prefer these over plain int/char in embedded code, since the width of built-in types is not guaranteed across compilers/platforms.
#include <stdint.h>

uint32_t variable = 5;   // guaranteed to be exactly a 32-bit unsigned int
  • Boolean types (<stdbool.h>): C89 has no built-in boolean type. <stdbool.h> defines bool, true (1) and false (0), implemented (in C99+) in terms of the compiler's _Bool type.

C-strings

Strings in C are character arrays terminated by a null byte, '\0'. There is no separate string type or built-in length field — the terminator is what tells library functions where the string ends.

char greeting[10] = "Hello!";
// bytes: 'H' 'e' 'l' 'l' 'o' '!' '\0' (unused) (unused) (unused)

char string1[] = "abc";
unsigned char string2[] = {97, 98, 99, 0};
// string1 and string2 occupy identical memory contents

sizeof("Hello!") is 7 bytes — 6 visible characters plus the null terminator.

The sizeof(...) operator

Importantsizeof is not a function — it is a compile-time operator. There is no runtime code that counts array elements; the compiler simply substitutes the known storage size at compile time.
sizeof(unsigned char)   // 1
sizeof(uint32_t)        // 4
sizeof(_Bool)           // implementation-specific
sizeof(int)             // implementation-specific

char  data[40];
char* ddata = data;
sizeof(data)             // 40  (size of the whole array)
sizeof(ddata)            // size of a pointer, e.g. 4 bytes on a 32-bit ARM target

02A First ARM Assembly Loop

A simple loop that stores incrementing byte values into memory, shown in C and the equivalent hand-written ARM assembly:

// C equivalent:
uint8_t data1[10];
int i;
for (i = 0; i < 10; i = i + 1)
    data1[i] = (uint8_t)i;
// R0 = base address of data1, R1 = loop index i
    mov  R0, #0x5000     // R0 = base address of array data1
    mov  R1, #0          // R1 = i = 0
LOOP:
    cmp  R1, #10          // compare i with 10
    bge  END              // if i >= 10, branch out of loop
    strb R1, [R0, R1]     // data1[i] = i  (store lowest byte of R1)
    add  R1, R1, #1       // i = i + 1
    b    LOOP              // repeat
END:

Resulting memory contents (byte-addressed, starting at 0x5000):

Addr    0    1    2    3
0x5000: 0x00 0x01 0x02 0x03
0x5004: 0x04 0x05 0x06 0x07
0x5008: 0x08 0x09 0x00 0x00
0x500C: 0x00 0x00 0x00 0x00

Two points worth noting from this example:

  • R1 holds the loop variable i directly in a register — it is never stored to memory. A variable does not have to live in memory at all if it can be kept in a register for its entire lifetime; whether it does depends on register pressure and compiler optimisation settings.
  • R0 is used purely to hold an address temporarily (the base address being written to) — registers are frequently reused as scratch space for addresses, not just for "values".
