STM32F4 GPIO Registers

Five 16-bit-wide ports — GPIOA…GPIOE — each with pins 0–15 (e.g. PA0…PA15). Base addresses (on the AHB1 bus):

PortBase address
GPIOA0x4002 0000
GPIOB0x4002 0400
GPIOC0x4002 0800
GPIOD0x4002 0C00
GPIOE0x4002 1000

Each port has 10 memory-mapped 32-bit registers, at these offsets from the port base:

RegisterOffsetBits/pinMeaning
GPIOx_MODER0x00200=Input (reset state), 01=General-purpose output, 10=Alternate function, 11=Analog
GPIOx_OTYPER0x0410=Push-pull, 1=Open-drain
GPIOx_OSPEEDR0x08200=Low (2 MHz), 01=Medium (25 MHz), 10=Fast (50 MHz), 11=High (100 MHz)
GPIOx_PUPDR0x0C200=None, 01=Pull-up, 10=Pull-down, 11=Reserved
GPIOx_IDR0x101 (RO)Bits 0–15 reflect the current input level on pins 0–15
GPIOx_ODR0x141 (RW)Bits 0–15 set the output pin states
GPIOx_BSRR0x182 (WO)Bits 0–15 (BSy): write 1 to set pin y. Bits 16–31 (BRy): write 1 to reset pin y. Writing 0 has no effect either way; if both bits are written 1, set wins. This gives atomic, single-instruction bit manipulation of ODR.
GPIOx_LCKR0x1C—A specific write sequence freezes MODER/OTYPER/OSPEEDR/PUPDR/AFRL/AFRH until the next reset
GPIOx_AFRL0x204Alternate-function mux select, pins 0–7 (AF0–AF15)
GPIOx_AFRH0x244Alternate-function mux select, pins 8–15 (AF0–AF15)

Pointers in C

A pointer is a variable that contains an address — nothing more. Pointer == Address. A pointer has a type, which tells the compiler the size/type of the data stored at that address; the pointer variable itself is always a fixed size (32 bits on this platform), regardless of what it points to.

int* my_ptr;      // my_ptr will hold the address of an int

Two operators are central to working with pointers:

  • & (address-of): obtains the address of a variable.
  • * (dereference): accesses the data stored at the address a pointer contains.
int my_var = 5;
int* my_ptr = &my_var;   // my_ptr now contains the address of my_var

*my_ptr = *my_ptr + 1;   // read the value at that address, add 1,
                          // and write the result back to the same address

Pointers are the mechanism behind three very common tasks in embedded C:

  • Accessing (reading/writing) a specific memory location, e.g. a memory-mapped peripheral register.
  • Accessing data stored in arrays.
  • Passing data/variables by reference into a function.

Accessing a fixed memory address

The compiler needs to know the size of the data at a raw address before it can read or write it correctly, so a numeric address must be cast to a pointer of the right type before it is dereferenced:

*(0x40020000) = 5;                 // wrong — compiler doesn't know the size

*((uint32_t*)0x40020000) = 5;      // correct — cast to a uint32_t pointer first

#define GPIOA_MODER *((uint32_t*)0x40020000)   // no spaces, no trailing ';'

GPIOA_MODER = 5;                    // now reads cleanly, thanks to the #define

Arrays are (almost) pointers

uint8_t data1[10];   // an array — the compiler allocates 10 bytes
uint8_t* p = data1;   // array name decays to a pointer to its first element

An array's size is fixed at compile time. There is a subtle but important difference between an array name and a pointer variable: the array name is not itself a variable (you cannot reassign it to point elsewhere), whereas a pointer variable can be reassigned to point anywhere.

Bitwise Operators & Bit Manipulation

These three operations — AND, OR, and BIC (bit-clear, i.e. AND-NOT) — are the standard toolkit for checking or modifying individual bits inside a register without disturbing the others.

AND — masking / checking bits

ANDing a bit with 0 always produces 0; ANDing with 1 passes the original bit through unchanged. This makes AND useful as a mask, to isolate specific bits for inspection.

input:  1100 1010
 mask:  0110 0110
result: 0100 0010
// Check that bit 0 is 1 and bit 3 is 0:
if ((input & 0b00001001) == 0b00000001)
    return 1;

OR — forcing bits to 1

ORing a bit with 1 always produces 1; ORing with 0 passes the original bit through. Used to force specific bits high without touching the rest of the register.

0x12345678 | 0x0000FFFF == 0x1234FFFF;
// high-order 16 bits untouched, low-order 16 bits forced to 1

BIC (AND-NOT) — forcing bits to 0

BICing a bit with 1 clears it to 0; BICing with 0 leaves the original bit untouched. In C there is no dedicated BIC operator — it is written as AND with the complement.

0x12345678 & ~0x0000FFFF == 0x12340000;
// high-order 16 bits untouched, low-order 16 bits forced to 0

REG &= ~(1 << n);   // clear bit n     — C
BIC r1, r1, #(1 << n) ; clear bit n     — assembly

REG |= (1 << n);    // set bit n       — C
ORR r1, r1, #(1 << n) ; set bit n       — assembly

Shifting to target one bit

For an 8-bit example value 1010 1010:

OperationResultEquivalent mathAssemblyC
Shift left by n(1) 0101 0100× 2nLSL r1, r0, #na = b << n
Shift right by n1101 0101÷ 2nASR r1, r0, #na = b >> n
 
// Set bit 6 of b (make it 1), leaving all other bits unchanged:
a = b | (1 << 6);

// Clear bit 5 of b (make it 0), leaving all other bits unchanged:
a = b & ~(1 << 5);

This is exactly the pattern used to configure a single pin's field inside a shared register such as GPIOx_MODER without disturbing the other 15 pins' configuration.

Direct Register Access Examples

Configure PD13 as a general-purpose output

GPIOD base is 0x4002 0C00; MODER offset is 0x00. Pin 13 occupies bits 27:26 of MODER — clear those two bits, then set them to 01:

#define GPIOD_MODER (*((volatile uint32_t *)0x40020C00))

// Clear bits 27:26, then set bit 26 (mode = 01, general-purpose output)
GPIOD_MODER = (GPIOD_MODER & ~(0x3 << (13 * 2))) | (0x1 << (13 * 2));

// Equivalently, written with the literal mask:
uint32_t * GPIOD_MODER_p = (uint32_t *) 0x40020C00;
*GPIOD_MODER_p = (*GPIOD_MODER_p & 0xF3FFFFFF) | 0x04000000;

Read pin state from PE4

GPIOE base is 0x4002 1000; IDR offset is 0x10, so GPIOE_IDR is at 0x4002 1010:

#define GPIOE_IDR (*((volatile uint32_t *)0x40021010))

uint8_t pin_state = (GPIOE_IDR >> 4) & 0x1;   // isolate bit 4

STM32 HAL GPIO Functions

STMicroelectronics provides a Hardware Abstraction Layer (HAL) and low-level drivers to improve productivity and portability across the STM32 family; STM32CubeIDE bundles STM32CubeMX to auto-generate initialisation code from a graphical configuration. Under the hood, the HAL functions simply read/write the same memory-mapped registers shown above — with added parameter validation.

void HAL_GPIO_Init(GPIO_TypeDef *GPIOx, GPIO_InitTypeDef *GPIO_Init);
void HAL_GPIO_DeInit(GPIO_TypeDef *GPIOx, uint32_t GPIO_Pin);

void HAL_GPIO_WritePin(GPIO_TypeDef* GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState);
// PinState: GPIO_PIN_SET or GPIO_PIN_RESET

GPIO_PinState HAL_GPIO_ReadPin(GPIO_TypeDef* GPIOx, uint16_t GPIO_Pin);

void HAL_GPIO_TogglePin(GPIO_TypeDef* GPIOx, uint16_t GPIO_Pin);
// Example
HAL_GPIO_WritePin(GPIOB, GPIO_PIN_2, GPIO_PIN_SET);

In STM32CubeIDE, typing a function/constant name and pressing Ctrl+Space shows "Template Proposals" with the valid values — but this is only a list of what compiles, not what is functionally correct for your circuit; you still need to know which value is actually right.

Software Debouncing

It is generally best to solve a hardware problem in hardware, but a few software approaches exist. The simplest (and most limited) is to 'pause' the microcontroller after the first edge and wait for bouncing to settle before reading the pin again.

CautionAvoid calling HAL_Delay() inside an interrupt handler — it depends on the SysTick interrupt to advance, and if SysTick cannot preempt the handler you are currently in, the system will hang waiting on a timer that can never fire.
