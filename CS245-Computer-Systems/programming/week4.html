Writing Interrupt Handlers

CS245 · Lectures 9–10 · volatile, EXTI setup, NVIC control, ISR wiring

01The C volatile Qualifier

The C compiler aggressively optimises: it may cache a variable's value in a core register instead of re-reading memory every time, and will remove code it believes has no observable effect. This breaks two common embedded patterns, because the compiler cannot see that the value can change for reasons outside the visible code flow:

  1. Memory-mapped peripheral registers — hardware can change the value independently of anything the CPU writes.
  2. Global variables modified inside an ISR — from the optimiser's point of view, if the ISR function is never explicitly called from the code it's analysing, it may assume the variable never changes, and either cache a stale copy in a register or optimise away a polling loop entirely (while(!flag); can become an infinite loop).

Fix: declare the variable volatile. This forces every read and write of that variable to go all the way to physical memory, with no caching or reordering by the optimiser.

volatile uint8_t button_pressed = 0;      // ISR-shared flag
volatile int x;   // equivalent to:
int volatile x;    // (before or after the type — both are the same)

// Pointers to volatile data are common for peripheral registers, and
// these two declarations are equivalent:
volatile uint32_t *p;
uint32_t volatile *p;
Rule of thumbDeclare a variable volatile whenever its value can change unexpectedly — i.e. memory-mapped peripheral registers, and any global variable an ISR writes that is also read from the main loop or another handler.

02Configuring EXTI by Register

To route the User Button (PA0) interrupt through to your ISR, several registers need to be set up (STM32CubeIDE's HAL/graphical configuration does this for you, but you should be able to do it by hand from the reference/programming manual):

  • EXTI_IMR bit 0 = 1 — unmask (enable) the interrupt.
  • EXTI_RTSR bit 0 = 1 — enable the rising-edge trigger.
  • EXTI_FTSR bit 0 = 0 — disable the falling-edge trigger.
  • NVIC_IPR0 bit 6 = 0 — set the priority of the EXTI0 interrupt.
  • NVIC_ISER0 bit 6 = 1 — enable the EXTI0 interrupt in the NVIC.
  • EXTI_PR — the pending-flag register; a pending interrupt's bit is cleared by writing a 1 to it (not by writing 0).

03NVIC Control: Masking & Priority

  • NVIC_ISERx / NVIC_ICERx — Interrupt Set-Enable / Clear-Enable registers, to enable or disable individual interrupt lines.
  • NVIC_IPRx — Interrupt Priority registers. Each is byte-accessible and holds four 8-bit priority fields, mapping onto the priority array IP[0]…IP[67].
  • BASEPRI — masks all exceptions below a chosen priority level; useful for disabling only lower-priority interrupts during a critical section, while still allowing higher-priority ones through.
  • PRIMASK — a single bit that disables all exceptions with configurable priority. Controlled from C with __disable_irq() and __enable_irq().

The NVIC driver functions provided by CMSIS/HAL simply write to these same registers, with additional argument validation layered on top — useful, but it helps to know what they resolve to underneath.

04Writing & Wiring an Exception Handler

  • The startup assembly file (a .S file, e.g. startup_stm32f407vgtx.s) sets up the vector table.
  • A handler function's name must exactly match the name expected in the vector table, and it takes no arguments and returns nothing — STM32CubeMX-generated projects already provide empty (weak) handlers for the standard exceptions in stm32f4xx_it.c, ready to be filled in.
  • In STM32CubeIDE, interrupts are usually configured through the graphical .ioc editor, which regenerates main.c and places your handler's address correctly in the vector table automatically — you then write the handler body in stm32f4xx_it.c.

The vector table entry for EXTI0 (0x0000 0058) holds the address of the handler (0x0000 1100). On a button press, the processor automatically saves the current PC and other registers onto the stack, jumps to the handler, which sets the flag at 0x1000 0000 to 1, and returns to the main program with BX LR — exactly like an ordinary function return.
