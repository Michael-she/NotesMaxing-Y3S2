Reference tracking and estimator design

Adding a command to full-state feedback with the reference gain N̄, and the full-order estimator that rebuilds the state from the measured output. Built from the Week 09 folder: the HTML lecture deck, the 2020 Ch 7.5 and 7.7 slides and Tutorial 7.

01Two assumptions to remove

Week 8's control law \(u = -\mathbf{K}\mathbf{x}\) rests on two unrealistic assumptions:

  • It is a regulator: it drives \(\mathbf{x}\) to zero and has no reference input.
  • Every state is measured.

This week removes both: the reference gain \(\bar N\) lets the output follow a command (FPE 7.5.2), and the estimator reconstructs the whole state vector from the one measured output (FPE 7.7). The running example continues, with \(\mathbf{K} = [3\;\;-0.5]\) placing the control poles at \(-3.5 \pm 3.43j\) (\(\alpha_c = s^2 + 7s + 24\)).

02Reference tracking with full-state feedback

The obvious way to add a command is \(u = -\mathbf{K}\mathbf{x} + r\). It almost always leaves a steady-state error. In steady state \(\dot{\mathbf{x}} = \mathbf{0}\), so \(\mathbf{x}_{ss} = -(\mathbf{A} - \mathbf{B}\mathbf{K})^{-1}\mathbf{B}r\) and \(y_{ss} = -\mathbf{C}(\mathbf{A} - \mathbf{B}\mathbf{K})^{-1}\mathbf{B}\,r\). Nothing in the design made that coefficient 1: \(\mathbf{K}\) was chosen to place poles, not to set a gain. The fix is to scale the command:

Reference gain (FPE 7.99)\[ u = -\mathbf{K}\mathbf{x} + \bar Nr, \qquad \bar N = \frac{-1}{\mathbf{C}(\mathbf{A} - \mathbf{B}\mathbf{K})^{-1}\mathbf{B}} = \frac{\alpha_c(0)}{b(0)} \quad (D = 0) \]
\(\bar N\)
Reference (feedforward) gain, a scalar.
\(\mathbf{C}(\mathbf{A}-\mathbf{B}\mathbf{K})^{-1}\mathbf{B}\)
Minus the closed-loop DC gain before scaling: (1 × n)(n × n)(n × 1), a scalar.
\(\alpha_c(0)\)
Constant term of the desired characteristic polynomial.
\(b(0)\)
Constant term of the plant numerator \(b(s)\); state feedback moves poles, not zeros.

\(\bar N\) multiplies an external signal, so it appears only in the numerator: it moves no pole. A wrong \(\bar N\) gives a wrong steady state, never instability.

Worked example 2.1 The reference gain two ways

For the running example with \(\mathbf{K} = [3\;\;-0.5]\), find the steady-state output with \(u = -\mathbf{K}\mathbf{x} + r\), then \(\bar N\).

1
\(\mathbf{A} - \mathbf{B}\mathbf{K} = \begin{bmatrix} -4 & \frac{3}{2} \\ -8 & -3 \end{bmatrix}\), \(\det = 24\), \((\mathbf{A} - \mathbf{B}\mathbf{K})^{-1} = \dfrac{1}{24}\begin{bmatrix} -3 & -1.5 \\ 8 & -4 \end{bmatrix}\).
2
\(\mathbf{C}(\mathbf{A} - \mathbf{B}\mathbf{K})^{-1}\mathbf{B} = \tfrac{1}{24}[-3\;\;-1.5]\begin{bmatrix} 1 \\ 2 \end{bmatrix} = -\tfrac{6}{24} = -\tfrac14\). So with \(u = -\mathbf{K}\mathbf{x} + r\), \(y_{ss} = 0.25r\): a 75 % error.
3
\(\bar N = -1/(-1/4) = 4\).
4
Ratio check: \(\alpha_c(0) = 24\), \(b(0) = 6\) (from \(G = (s+6)/(s^2+5s+6)\)), so \(\bar N = 24/6 = 4\) ✓ with no matrix inversion.
\(\bar N = 4\). The closed loop is \(Y/R = \dfrac{4(s+6)}{s^2 + 7s + 24}\), with DC gain 1 (Figure 2.1).

Figure 2.1: With \(\bar N\) the output reaches 1 with 7.5 % overshoot; the plant zero at −6, which state feedback cannot move, adds a little overshoot beyond the 4.1 % expected from \(\zeta = 0.714\) alone.

The textbook route

FPE 7.5.2 asks first what steady state and steady input a command demands, \(\mathbf{x}_{ss} = \mathbf{N}_xr\), \(u_{ss} = N_ur\), and writes the control as a correction about that operating point:

Reference input via N_x and N_u (FPE 7.97 to 7.99)\[ \begin{gathered} \begin{bmatrix} \mathbf{A} & \mathbf{B} \\ \mathbf{C} & D \end{bmatrix}\begin{bmatrix} \mathbf{N}_x \\ N_u \end{bmatrix} = \begin{bmatrix} \mathbf{0} \\ 1 \end{bmatrix}, \\ u = N_ur - \mathbf{K}(\mathbf{x} - \mathbf{N}_xr) = -\mathbf{K}\mathbf{x} + \bar Nr, \qquad \bar N = N_u + \mathbf{K}\mathbf{N}_x \end{gathered} \]
\(\mathbf{N}_x\)
Steady state per unit command.
\(N_u\)
Steady input per unit command.

For the running example \(\mathbf{N}_x = \begin{bmatrix} 1 \\ 0 \end{bmatrix}\) and \(N_u = 1\), so \(\bar N = 1 + [3\;\;-0.5]\begin{bmatrix} 1 \\ 0 \end{bmatrix} = 4\) ✓. The two routes are identical; the book's is general (several inputs and outputs) and \(\mathbf{N}_x,\,N_u\) do not depend on \(\mathbf{K}\). Both fail only when \(b(0) = 0\): a plant with a zero at the origin can hold no steady output.

Watch out

\(\bar N\) is computed from the model. It gives zero error only if the model is exact: it is a calibration, not a feedback property. Week 10 replaces it with integral control for exactly this reason.

03Why an estimator

Full-state feedback needs every element of \(\mathbf{x}\). In most systems that is false: a sensor for every state costs too much, and some states (internal temperatures in a reactor, for instance) cannot be measured at all. We do know the model \((\mathbf{A}, \mathbf{B}, \mathbf{C})\), the input \(u(t)\) (we command it) and the measured output \(y\). Can we reconstruct \(\mathbf{x}\)?

The first idea is an open-loop estimator: run a copy of the model driven by the same input, \(\dot{\hat{\mathbf{x}}} = \mathbf{A}\hat{\mathbf{x}} + \mathbf{B}u\). Subtracting it from the plant gives the estimate error \(\tilde{\mathbf{x}} = \mathbf{x} - \hat{\mathbf{x}}\):

Open-loop estimator error (FPE 7.128)\[ \dot{\tilde{\mathbf{x}}} = \mathbf{A}\tilde{\mathbf{x}} \]
\(\tilde{\mathbf{x}}\)
Estimate error, true state minus estimate.
\(\mathbf{A}\)
The plant's own dynamics: the open-loop estimator has no way to change the error decay rate.

The error decays only as fast as the plant's own modes, and grows without bound if the plant is unstable. It would work only if \(\hat{\mathbf{x}}(0) = \mathbf{x}(0)\), but it is precisely our ignorance of \(\mathbf{x}(0)\) that makes an estimator necessary. Model errors in \(\mathbf{A}\) or \(\mathbf{B}\) also make the estimate drift. The remedy, as always, is feedback: compare \(\hat y = \mathbf{C}\hat{\mathbf{x}}\) with the measured \(y\).

04The closed-loop estimator

Full-order estimator (FPE 7.130)\[ \dot{\hat{\mathbf{x}}} = \mathbf{A}\hat{\mathbf{x}} + \mathbf{B}u + \mathbf{L}(y - \mathbf{C}\hat{\mathbf{x}}), \qquad \mathbf{L} = [\,L_1 \;\; L_2 \;\; \cdots \;\; L_n\,]^T \]
\(\hat{\mathbf{x}}\)
State estimate.
\(\mathbf{L}\)
Estimator gain, a column of n gains.
\(y - \mathbf{C}\hat{\mathbf{x}}\)
Output error, the measured output minus the predicted output.

Subtracting from the plant equation, with \(y = \mathbf{C}\mathbf{x}\):

Estimator error dynamics (FPE 7.132, 7.133)\[ \dot{\tilde{\mathbf{x}}} = (\mathbf{A} - \mathbf{L}\mathbf{C})\tilde{\mathbf{x}}, \qquad \det[s\mathbf{I} - (\mathbf{A} - \mathbf{L}\mathbf{C})] = \alpha_e(s) = (s - \beta_1)\cdots(s - \beta_n) \]
\(\mathbf{A} - \mathbf{L}\mathbf{C}\)
Estimator error matrix: it governs how fast the error decays.
\(\alpha_e(s)\)
Desired estimator characteristic polynomial.
\(\beta_i\)
Chosen estimator error poles.

If \(\mathbf{L}\) makes \(\mathbf{A} - \mathbf{L}\mathbf{C}\) stable and fast, the error goes to zero independent of \(u\) and of \(\hat{\mathbf{x}}(0)\): we no longer need the initial state. The estimator is a set of equations in a computer, not hardware, so a large \(\mathbf{L}\) costs nothing in actuator terms.

Key idea

Duality. Control: \(\det[s\mathbf{I} - (\mathbf{A} - \mathbf{B}\mathbf{K})]\). Estimator: \(\det[s\mathbf{I} - (\mathbf{A} - \mathbf{L}\mathbf{C})]\). The same problem with \(\mathbf{A} \to \mathbf{A}^T\), \(\mathbf{B} \to \mathbf{C}^T\), \(\mathbf{K} \to \mathbf{L}^T\) (FPE Table 7.1), so no new theory is needed. Precondition: the plant must be observable, \(\det\mathcal{O} \ne 0\).

05Finding L

The same three routes as for \(\mathbf{K}\):

  • Compare coefficients of \(\det[s\mathbf{I} - (\mathbf{A} - \mathbf{L}\mathbf{C})]\) with \(\alpha_e(s)\). Practical for \(n \le 3\); the default.
  • Observer canonical form: there \(\mathbf{A}_o - \mathbf{L}_o\mathbf{C}_o\) keeps the companion shape with first column \(-(a_i + L_i)\), so \(L_{o,i} = \beta_i - a_i\) (coefficients of \(\alpha_e\) minus those of the open loop), then \(\mathbf{L} = \mathbf{T}\mathbf{L}_o\). Only possible if the system is observable.
  • Ackermann's estimator formula, the dual of the control formula:
Ackermann's estimator formula (FPE 7.146)\[ \mathbf{L} = \alpha_e(\mathbf{A})\,\mathcal{O}^{-1}\begin{bmatrix} 0 \\ \vdots \\ 0 \\ 1 \end{bmatrix}, \qquad \alpha_e(\mathbf{A}) = \mathbf{A}^n + \beta_1\mathbf{A}^{n-1} + \cdots + \beta_n\mathbf{I} \]
\(\mathcal{O}\)
Observability matrix \([\mathbf{C};\,\mathbf{C}\mathbf{A};\,\cdots]\).
\(\beta_i\)
Coefficients of \(\alpha_e(s)\) (here used as polynomial coefficients).
\([0\cdots1]^T\)
Selector column, now on the far right.
Worked example 5.1 Estimator gain three ways

Place the running example's estimator poles at −12 and −15 (about 3.5 times the control \(\omega_n\)).

1
Observability: \(\mathbf{C}\mathbf{A} = [-1\;\;1]\), \(\mathcal{O} = \begin{bmatrix} 1 & 0 \\ -1 & 1 \end{bmatrix}\), \(\det\mathcal{O} = 1\) ✓. \(\alpha_e(s) = (s+12)(s+15) = s^2 + 27s + 180\).
2
Compare coefficients. \(\mathbf{L}\mathbf{C} = \begin{bmatrix} L_1 & 0 \\ L_2 & 0 \end{bmatrix}\), so \(\det\begin{bmatrix} s+1+L_1 & -1 \\ 2+L_2 & s+4 \end{bmatrix} = s^2 + (5 + L_1)s + (6 + 4L_1 + L_2)\). Then \(5 + L_1 = 27 \Rightarrow L_1 = 22\); \(6 + 88 + L_2 = 180 \Rightarrow L_2 = 86\).
3
Ackermann. \(\alpha_e(\mathbf{A}) = \mathbf{A}^2 + 27\mathbf{A} + 180\mathbf{I} = \begin{bmatrix} 152 & 22 \\ -44 & 86 \end{bmatrix}\); \(\mathcal{O}^{-1} = \begin{bmatrix} 1 & 0 \\ 1 & 1 \end{bmatrix}\), so \(\mathcal{O}^{-1}[0\;\;1]^T = [0\;\;1]^T\) and \(\mathbf{L}\) is the second column of \(\alpha_e(\mathbf{A})\): \([22\;\;86]^T\) ✓.
4
Observer canonical form. \(\mathbf{A}_o = \begin{bmatrix} -5 & 1 \\ -6 & 0 \end{bmatrix}\), \(\mathbf{C}_o = [1\;\;0]\); \(\mathbf{L}_o = [27-5\;\;180-6]^T = [22\;\;174]^T\). With \(\mathbf{T} = \mathcal{O}_x^{-1}\mathcal{O}_z = \begin{bmatrix} 1 & 0 \\ -4 & 1 \end{bmatrix}\), \(\mathbf{L} = \mathbf{T}\mathbf{L}_o = [22\;\;86]^T\) ✓.
5
Trace check. \(\mathrm{tr}(\mathbf{A} - \mathbf{L}\mathbf{C}) = \mathrm{tr}\,\mathbf{A} - \mathbf{C}\mathbf{L} = -5 - 22 = -27 = -\beta_1\) ✓.
\(\mathbf{L} = [\,22 \;\; 86\,]^T\). \(L_2\) is much larger than \(L_1\): the unmeasured state has to be inferred from how the measured one changes. In MATLAB, L = acker(A',C',pe)' or place(A',C',pe)'.

06Choosing the estimator poles

Estimator poles are chosen like controller poles, with one rule of thumb on top:

Rule of thumb

Place the estimator poles 2 to 6 times faster than the controller poles. The estimate error then dies out quickly and the controller poles dominate, which is what the control-law design assumed. If sensor noise is significant, choose them slower, even slower than twice the controller poles: this lowers the bandwidth and smooths the noise, at the cost of a disturbance response dominated by the estimator.

Estimator error with noise\[ \dot{\tilde{\mathbf{x}}} = (\mathbf{A} - \mathbf{L}\mathbf{C})\tilde{\mathbf{x}} + \mathbf{B}_1w - \mathbf{L}v \]
\(w\)
Process noise or disturbance, entering through \(\mathbf{B}_1\); not multiplied by \(\mathbf{L}\).
\(v\)
Sensor noise on \(y\), multiplied by \(\mathbf{L}\).

The trade-off differs from the controller's. A faster controller needs a larger \(\mathbf{K}\), so a bigger actuator. A faster estimator needs a larger \(\mathbf{L}\), which costs nothing directly; what it costs is bandwidth, so more sensor noise passes into \(\hat{\mathbf{x}}\) and on to the actuator. Small \(\mathbf{L}\) rejects noise but tracks disturbances poorly; large \(\mathbf{L}\) does the reverse.

Figure 6.1: Top: faster poles pull the estimate onto the true state sooner, but with a larger initial peak in x̂₂ (2.3 for poles −12, −15 and 9.5 for −30, −37.5, off the top of the plot). Bottom: with ±0.02 of uniform noise on y, the fast design (amber, L = [62.5 869]ᵀ) passes the noise straight into x̂₂, while the moderate design (teal, L = [22 86]ᵀ) stays much smoother. That is the real limit on estimator speed.

Not examined

Reduced-order estimators (FPE 7.7.2) and optimal estimator pole selection (7.7.3, symmetric root locus) are not for examination.

07Practice problems

Problem 1. Tutorial 7 problem 1 and 2: \(\mathbf{A} = \begin{bmatrix} 0 & 1 \\ -8 & -6 \end{bmatrix}\), \(\mathbf{B} = [0\;\;1]^T\), \(\mathbf{C} = [1\;\;0]\). Find \(\mathbf{K}\) for poles \(-6 \pm 6j\), the steady-state output with \(u = -\mathbf{K}\mathbf{x} + r\), and \(\bar N\).

\(\alpha_c = s^2 + 12s + 72\); companion form gives \(\mathbf{K} = [72 - 8\;\;12 - 6] = [64\;\;6]\). With \(u = -\mathbf{K}\mathbf{x} + r\): \(y_{ss} = 1/72 = 0.0139\), a 98.6 % error. \(\bar N = \alpha_c(0)/b(0) = 72/1 = 72\).

Problem 2. For the same plant, place both estimator poles at −20.

\(\det[s\mathbf{I} - (\mathbf{A} - \mathbf{L}\mathbf{C})] = s^2 + (6 + L_1)s + (8 + 6L_1 + L_2) = s^2 + 40s + 400\): \(L_1 = 34\), \(L_2 = 188\). Trace −40 ✓.

Problem 3. Why does \(\bar N\) not move any closed-loop pole?

It multiplies the external signal \(r\), so it enters only the input matrix of the closed loop \((\mathbf{A} - \mathbf{B}\mathbf{K},\,\mathbf{B}\bar N)\), never the system matrix.

Problem 4. With estimator poles at −5 (three times) for the servo drive of Tutorial 7, \(l_3 = 0\). What does that mean?

The estimator then makes no correction to the actuator-state estimate from the output error: \(\hat x_3\) runs open loop, decaying at the actuator's own pole of −5, which already equals the requested pole.

08Formula sheet

Reference

\(u = -\mathbf{K}\mathbf{x} + \bar Nr\)

\(\bar N = -1/[\mathbf{C}(\mathbf{A}-\mathbf{B}\mathbf{K})^{-1}\mathbf{B}] = \alpha_c(0)/b(0)\)

\(\bar N = N_u + \mathbf{K}\mathbf{N}_x\)

Estimator

\(\dot{\hat{\mathbf{x}}} = \mathbf{A}\hat{\mathbf{x}} + \mathbf{B}u + \mathbf{L}(y - \mathbf{C}\hat{\mathbf{x}})\)

\(\dot{\tilde{\mathbf{x}}} = (\mathbf{A}-\mathbf{L}\mathbf{C})\tilde{\mathbf{x}}\)

\(\det[s\mathbf{I} - \mathbf{A} + \mathbf{L}\mathbf{C}] = \alpha_e(s)\)

Finding L

\(\mathbf{L} = \alpha_e(\mathbf{A})\mathcal{O}^{-1}[0\cdots1]^T\)

Observer form: \(L_{o,i} = \beta_i - a_i\), \(\mathbf{L} = \mathbf{T}\mathbf{L}_o\)

\(\mathrm{tr}(\mathbf{A}-\mathbf{L}\mathbf{C}) = \mathrm{tr}\mathbf{A} - \mathbf{C}\mathbf{L}\)

Pole choice

Estimator 2 to 6 times faster than control; slower if sensor noise matters
